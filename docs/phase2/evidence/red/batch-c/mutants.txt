# Phase 2 batch C: mutants of the scratch oracle

Method: a runner applies ONE text edit to a pristine copy of the oracle source (repository.py, triggers.py, errors.py, engine.py), runs the whole tests directory (SQLite side, Python 3.13, stop at the first failure) or, for the mutants that only Postgres can see, the matching tests with -m postgres against a throwaway Postgres 18.6 (-k selection), restores the pristine files and reads the failures. Four worker copies of the oracle ran in parallel.

95 mutants: 91 caught, 4 survivors (all four are equivalent or unpinned, explained below).
