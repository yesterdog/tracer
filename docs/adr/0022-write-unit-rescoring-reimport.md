## Context
A `RunBundle` is the unit of a run (N22): `check_run_bundle` judges every cross-record rule over it, and a rescoring is a new RunBundle for the same run (B5), so records of fact are shared across bundles. Importers mint a new UUIDv7 for every external object (`from_external`) and must look up an existing record before minting, or a re-imported call is stored twice (P-02). Deletion can remove a member that a stored bundle lists (ADR 0020). A transcript's language declaration can be found wrong after import (finding N18), and records of fact are never edited.

Facts in the code: `check_run_bundle` requires `run.config_snapshot_id` to equal the embedded snapshot's ID (`[snapshot]`) and every `UsageRecord.run_id` to equal the run (`[membership]`); `ExternalRef.system`, `kind` and `value` are `VerbatimText` (any code point except lone surrogates); `Run.external_refs` is a list that the model does not deduplicate; `loader.load_bundle` checks the 256 MiB limit before parsing and takes `expected_purpose` for exports only.

## Decision
Machine-read by `test_adr0022_policy_rules_are_tested`: every numbered rule cites at least one existing test name.

1. **The write unit is the whole validated RunBundle (Q5).** `store_run_bundle(bundle)` takes a `RunBundle` and validates it again from its own JSON text, `loader.load_bundle(RunBundle, bundle.model_dump_json())` (size limit, strict loader, every model rule and `check_run_bundle`), before any statement is sent, so an instance built without validation or changed after it cannot be stored. There is no API that writes a single run-owned record. Tests: `test_invalid_run_bundle_never_stored`, `test_run_bundle_round_trip_byte_identical_json`.
2. **Checks before the write.** Before any statement, the repository also requires: the bundle's project is stored (it never creates one); the snapshot's test-profile reference carries a plain digest (`snapshot.check_internal_snapshot`, ADR 0019 Ambiguity 10); every integer of every record can be stored, that is its magnitude is at most `2**53 - 1` (ADR 0019 Decision 6 and Ambiguity 5, revision 35), else `StoreValueOutOfRange(table, column)`. Each failure is a typed error that names the record and the rule, never a value (`ProjectNotStored`, `InternalSnapshotRefused`, `StoreValueOutOfRange`), and no `INSERT`, `UPDATE` or `DELETE` is sent before every check has passed (revision 36). Tests: `test_invalid_run_bundle_never_stored`, `test_store_errors_hide_input`, `test_store_run_bundle_refuses_a_bundle_whose_project_is_not_stored`, `test_store_run_bundle_refuses_absent_or_keyed_profile_digest`, `test_store_run_bundle_refuses_an_integer_it_cannot_store_before_any_write`.
3. **One transaction.** All rows of one bundle are written in one transaction; a failure at any point, including after the turns, leaves the store unchanged. Every repository function opens exactly one transaction with `engine.begin()` on the engine it is given, committed when it returns and rolled back when any exception leaves it; no function commits partway (revision 36, batch C A1). Tests: `test_run_bundle_store_is_atomic`, `test_repository_functions_require_an_engine`.
4. **Versioned content is inserted or verified (Q8), and a deletion is never undone by a second store (revision 39).** A versioned record or snapshot whose key is present is compared by `doc_sha256`: equal is a no-op (idempotent); different is `ConflictingVersionError` for a versioned entity and `ConflictingRecordError` for a snapshot (the evalschema error classes). A key that is absent is handled by the repair rule:
   - **A fresh run is a new import.** When the bundle's run row is not stored, `store_run_bundle` inserts the snapshot, the definitions it embeds, the bundle's pricing catalogs and test profiles whose keys are absent, as before.
   - **A stored run never brings back a deleted member.** When the bundle's run row is stored, a member of the seven deletable kinds (test profile, `pricing_catalog`, and the five definitions `persona`, `rubric`, `evaluator`, `metric_definition`, `metric_binding`) that the stored run lists (in a stored `run_bundle_member` row of the run, or in the stored snapshot's `snapshot_member` and `snapshot_profile_ref` rows) and that the database no longer holds is NOT inserted again: it was removed by `delete_test_profile` or `delete_definition` (ADR 0020), and inserting it would undo a data-subject deletion. It stays absent, `load_run_bundle` keeps reporting it (Decision 8, `IncompleteRunBundle`) and `verify_database` keeps its `bundle_member_absent` note. Being listed is what tells a deleted record from a new one, because the audit holds no ID (ADR 0020 Decision 6).
   - **Repair is explicit.** `store_run_bundle(engine, bundle, *, repair_members=False)`: only `repair_members=True` inserts those absent members again. It writes no `deletion_audit` row (audit rows are content-free and cannot name what was restored); it is a deliberate act of restoring deleted data, documented as such in `packages/evaldb/STORAGE_POLICY.md`. Anything that is not exactly a `bool` is a `TypeError` raised before any statement.
   - **Documented limit.** `store_snapshot` and `store_definition` called directly still insert the record the caller names when its key is absent, a deleted one included (batch G ambiguity B1): the call names the record, and a snapshot stored by itself is not tied to a stored run. The rule above is about `store_run_bundle`.

   `latest_version(kind, id)` and the lookup of a snapshot by its content digest read the projections. Tests: `test_store_definition_idempotent_same_content`, `test_store_definition_conflicting_content_rejected`, `test_store_snapshot_extracts_embedded_definitions`, `test_store_snapshot_conflicting_embedded_definition_rejected`, `test_latest_version_lookup`, `test_snapshot_lookup_by_content_digest`, `test_storing_the_same_bundle_again_does_not_bring_back_a_deleted_member`, `test_a_deleted_test_profile_leaves_no_personal_data_after_a_second_store`, `test_a_run_that_is_not_stored_is_imported_whole_as_before`, `test_repair_members_inserts_the_deleted_member_again`, `test_repair_members_is_a_keyword_only_bool_defaulting_to_false`.
5. **Records of fact are deduplicated by ID (Q6).** A record whose ID is already stored is compared by `doc_sha256`: equal, the stored row is shared and not inserted again; different, `ConflictingRecordError` naming the kind and the ID. A stored record owned by another run (a different `run_id`; for `usage_record` its native `run_id`) is refused with `RecordOwnershipConflict(kind, record_id)` whether or not its content is equal: a record of fact belongs to one run. Ownership is checked before content (revision 36, batch C A3), so a second run that shares any record ID gets the ownership conflict, and the content of another run's records is never compared. The bundle envelope is a record of fact too: storing a RunBundle whose ID is stored with the same envelope and the same member rows is a no-op; with any difference it is `ConflictingRecordError`. A rescoring is a new RunBundle ID for the same run that lists the shared records and its own results and verdict; it stores only the rows whose IDs are not yet stored (its own envelope and member rows, results and verdict, and any new record such as the new transcript of Decision 12), and because its run is stored, the repair rule of Decision 4 applies to it: a member deleted since the first store is not brought back (revision 39). Tests: `test_rescoring_bundle_shares_records_without_duplication`, `test_rescoring_bundle_conflicting_record_rejected`, `test_run_owned_tables_have_run_id_cascade`, `test_store_same_run_bundle_twice_is_a_no_op`, `test_record_owned_by_another_run_rejected`, `test_same_bundle_id_with_other_members_is_a_conflict`, `test_a_rescoring_of_a_stored_run_does_not_bring_back_the_deleted_member`, `test_storing_a_bundle_twice_without_a_deletion_is_still_a_no_op`.
6. **Every tier is stored the same way.** Storage does not depend on the observed tier: the T-DEG bundles of every tier fill the same tables, and missing evidence stays absent (NULL), never 0 or false. Tests: `test_tdeg_bundles_round_trip_identical_table_set`, `test_not_applicable_results_projected_null_never_zero_or_false`, `test_not_available_cost_projected_without_amount_or_basis`.
7. **Batched writes.** Rows are inserted per table with one multi-row statement (`executemany`), so the number of statements of `store_run_bundle` does not grow with the number of records. Tests: `test_store_run_bundle_statement_count_independent_of_record_count`, `test_huge_call_bundle_round_trip`.
8. **Loading a bundle, complete or not (Q16).** `load_run_bundle(bundle_id, *, allow_incomplete=False)` rebuilds the bundle from its envelope and its member rows in member order (every list keeps its order, `withheld` included) and returns a result with `complete` and `missing`:
   - every member present: `complete=True`, `missing=()`, and `bundle` is the `RunBundle`, validated by its model, whose `model_dump_json()` equals the bytes of the bundle that was stored;
   - a member deleted (ADR 0020): with `allow_incomplete=False` a typed incomplete-bundle error listing the missing `(kind, id)` pairs (and the version for a versioned member), never their content; with `allow_incomplete=True`, `complete=False`, `missing` as above, `bundle=None`, and the records that remain, each validated by its own model, grouped by member list in member order. A partial set is never returned as a `RunBundle`, so one RunBundle ID never stands for two contents.
   - the load reads the member rows and the records in one read transaction, at REPEATABLE READ on Postgres, so the report describes one moment (revision 36, batch C A16; no test pins the isolation level); an ID that names no stored bundle, or a bundle whose run was deleted, is `RecordNotStored`.
   Tests: `test_run_bundle_round_trip_order_preserved`, `test_run_bundle_round_trip_byte_identical_json`, `test_run_bundle_withheld_round_trip`, `test_run_bundle_load_reports_incomplete_after_member_deletion`.
9. **Exports are stored and loaded as opaque documents (Q7).** `store_export(export, *, expected_purpose)` and `load_export(export_id, *, expected_purpose)` take `expected_purpose` keyword-only and required, with no default (SCHEMA_POLICY section 11). `None` is a `TypeError` at both entry points, unlike `loader.load_bundle`, which reads `None` as any purpose (revision 36, batch C A12). `store_export` accepts an `ExportBundle` or JSON text; text is size-checked before parsing (256 MiB), and both forms go through `loader.load_bundle(ExportBundle, ..., expected_purpose=expected_purpose)`; a different purpose is refused. `doc` is the `model_dump_json()` of the validated export, so sealed ciphertext is byte-identical at rest; the link rows of ADR 0019 Table 2 are written, and no export record enters the internal tables. `load_export` checks `byte_length` against the limit before parsing. Tests: `test_store_export_requires_expected_purpose`, `test_load_export_requires_expected_purpose`, `test_store_export_purpose_mismatch_rejected`, `test_export_round_trip_byte_identical`, `test_export_sealed_payload_ciphertext_unchanged_at_rest`, `test_export_size_limit_enforced_before_parse`, `test_export_records_not_decomposed_into_internal_tables`.
10. **Re-import keys (P-02, Q17).** `external_ref_index` holds one row per distinct external reference of a stored record: each entry of `Run.external_refs` (kind `run`), `StageSpan.span_ref` (`span`), `Transcript.provider_call_ref` (`transcript`, when present) and `UsageRecord.provider_call_ref` (`usage_record`, when present). The key is `key_sha256`, the SHA-256 of the JCS bytes of the JSON array `[system, kind, value]` (`digest.jcs_bytes`, `digest.sha256_hex`), so the lookup is exact: letter case, white space, NFC and NFD forms and U+0000 are all distinct, and a value of 1 MB costs one 32-byte key. Identical references repeated in one record give one row. The key is unique for the kind `run` only (revision 35, batch B A1). For `span`, `transcript` and `usage_record` it is not unique and is looked up per run: one provider call may yield several transcripts or usage records (not assumed otherwise), and the frozen golden `RunBundle/valid/maximal.json` holds two spans of one run with the same `span_ref`, so a unique span key would refuse a valid bundle. The SCOPE test `test_external_ref_unique_per_entity_kind` is read accordingly: unique for the run kind; the other kinds are lookups. Finding **P2-F3** (0.0.2): either a rule that the `span_ref` values of one run are distinct, or an explicit statement in the schema that they need not be. Importers call `find_by_external_ref("run", ref)` with an `ExternalRef` to find an existing run, and the run-scoped lookup for the other kinds, before minting an ID. Tests: `test_reimport_finds_existing_run_by_external_ref`, `test_external_ref_unique_per_entity_kind`, `test_external_ref_key_is_hash_of_jcs_tuple`, `test_external_ref_lookup_is_exact`, `test_child_provider_call_refs_not_unique`.
11. **Re-import conflicts.** When a run arrives whose external-ref key (the unique kind `run`) already names a stored run, and either the ID or the `doc_sha256` differs, the write is refused before any statement with `ReimportConflict`, a subclass of `ConflictingRecordError`, naming the entity kind and the stored ID, never the reference. It is checked before the plain ID comparison of rule 5, because it is the more specific diagnosis. Test: `test_reimport_conflicting_content_raises_reimport_conflict`.
12. **A changed language declaration is a new record (N18, Q22).** A `Transcript` is never edited. Correcting `declared_language` after import means a new Transcript (new ID) with its turns as new Turn records naming it, the results recomputed over them, in a new RunBundle of the same run. The old transcript, its turns and the results that cite them stay, so every stored result keeps its meaning. A `supersedes` link would be an additive 0.0.2 change. Tests: `test_update_rejected_on_every_table`, `test_rescoring_bundle_shares_records_without_duplication`.
13. **Storage limits (Q23).** The limit is the loader's 256 MiB per document, checked before parsing on every read and, for bundles and exports, on write. No per-field limit is set until the measurements of P2-23 support a number. Tests: `test_export_size_limit_enforced_before_parse`, `test_huge_call_bundle_round_trip`.

## Repository API and typed errors (revision 36, batch C)
Recorded from qa's batch C contract (`docs/phase2/api-surface-batch-c.md` sections 2 and 7; ambiguities A1, A2 and A4 auto-approved by the lead; SCOPE Decisions D5). The contract is the exact reference for signatures and behaviour; this section records the shape.

- **Home.** `tracer_evaldb.repository` holds the 15 functions, the four result types and `translate_integrity_error`; `tracer_evaldb` re-exports the functions, the result types and the errors.
- **Engine first, one transaction.** Every function takes the `sqlalchemy.engine.Engine` of `create_store_engine` as its first positional argument and opens exactly one `engine.begin()` transaction (Decision 3). A `Connection`, a URL string, a `URL` object or `None` is a `TypeError` raised before any statement. There is no module-level engine, no session object and no cache, and no transaction that spans two calls. Identifier arguments are typed IDs of the right kind or a version 7 `uuid.UUID`. Tests: `test_repository_functions_require_an_engine`, `test_repository_functions_and_signatures`, `test_id_arguments_are_typed_ids_or_uuids`.
- **Writers** (`store_project`, `store_definition`, `store_snapshot`, `store_dataset_item`, `store_run_bundle`, `store_export`) serialise their argument with `model_dump_json()` and load that text again through the strict loader before any `INSERT`, so an instance built or changed without validation cannot be stored. Each returns `StoreResult(kind, entity_id, version, created, inserted)`. Test: `test_store_functions_revalidate_instances_built_without_validation`.
- **Readers** (`load_project`, `load_definition`, `load_snapshot`, `load_dataset_item`, `load_run_bundle`, `load_export`) decode through the batch B codecs; `load_run_bundle` returns `LoadedRunBundle(bundle_id, complete, missing, bundle, records)` with `MissingMember(kind, record_id, record_version)` entries (Decision 8). Lookups: `latest_version`, `find_snapshot_by_digest` and `find_by_external_ref`, which returns `ExternalRefMatch(entity_kind, entity_id, run_id)` tuples (Decision 10). Tests: `test_result_types_are_frozen_dataclasses`, `test_loading_something_that_is_not_stored_is_a_typed_error`.
- **Typed errors** (the eight of batch C, `tracer_evaldb.errors`):

| Error | Direct bases | Raised by | Attributes |
|---|---|---|---|
| `ReimportConflict` | `tracer_evalschema.errors.ConflictingRecordError` (not a `StoreError`) | `store_run_bundle` (Decision 11) | `entity_kind`, `stored_id` |
| `RecordOwnershipConflict` | `StoreError` | `store_run_bundle` (Decision 5) | `kind`, `record_id` |
| `ProjectNotStored` | `StoreError` | `store_run_bundle` (Decision 2) | `project_id` |
| `InternalSnapshotRefused` | `StoreError`, `ValueError` | `store_snapshot`, `store_run_bundle` (Decision 2) | `snapshot_id` |
| `RecordNotStored` | `StoreError` | every `load_*` | `kind`, `record_id`, `version` |
| `IncompleteRunBundle` | `StoreError` | `load_run_bundle` (Decision 8) | `bundle_id`, `missing` |
| `ExportReferenceNotStored` | `StoreError` | `store_export` (Decision 9) | `kind`, `record_id` |
| `StoreConstraintViolation` | `StoreError` | any write (ADR 0019 Decision 18) | `kind`, `table`, `constraint` |

  The repository lets these evalschema errors through unwrapped: `ConflictingVersionError` and `ConflictingRecordError` (Decisions 4 and 5), `BundleSizeError`, `DigestMismatch`, `pydantic.ValidationError`, the `[purpose]` `ValueError` and `TypeError`; the batch B errors `StoreIntegrityError` and `StoreValueOutOfRange` keep their meaning. Every message holds the kind and the ID (wire form) and never a field value, a document fragment or an external reference. Tests: `test_error_types_and_their_parents`, `test_reimport_conflict_is_a_conflicting_record_error_checked_first`, `test_translate_integrity_error_names_the_kind_and_no_value`.

## Ambiguities resolved
- **Ambiguity 1. Trusting a `RunBundle` instance.** pydantic allows building a model without validation. **Recommendation:** rule 1 re-validates from the instance's own JSON. Rejected: trusting the instance (a `model_construct` call would bypass `check_run_bundle`).
- **Ambiguity 2. The same bundle stored twice.** **Recommendation:** a no-op when identical (rule 5), the natural form of an idempotent re-import. Proposed test name for the lead to add to the P2-12b row: `test_store_same_run_bundle_twice_is_a_no_op`.
- **Ambiguity 3. A record shared by two runs.** The models do not forbid two runs' bundles holding one record ID. **Recommendation:** refuse with a typed ownership conflict (rule 5); re-parenting a record would move it between runs and break the cascade of the first run. Proposed test name: `test_record_owned_by_another_run_rejected`.
- **Ambiguity 4. `ReimportConflict` and `ConflictingRecordError`.** `test_reimport_conflicting_content_raises_reimport_conflict` expects `ReimportConflict` for a re-import with different content. **Recommendation:** `ReimportConflict` subclasses `ConflictingRecordError` and is checked first (rule 11), so a caller that catches the general class still catches it.
- **Ambiguity 5. What an incomplete load returns.** A RunBundle that lost a member fails its own rules (`[unresolved]`) or, worse, could pass as a different content. **Recommendation:** rule 8 (typed error by default; with `allow_incomplete=True` the remaining records, never a `RunBundle`).
- **Ambiguity 6. N18 and the turns.** Turns name their transcript, so a new transcript needs new turns. **Recommendation:** rule 12 (copies with new IDs); the duplicated text is personal data like the original and is deleted with the run.
- **Ambiguity 7. Error and function names.** `ReimportConflict` and `IncompleteRunBundle` come from SCOPE; the ownership conflict, the missing-project error and `find_by_external_ref` are the recommendation, and the Phase 2 API contract written by qa pins the final spelling. **Revision 36:** pinned by `docs/phase2/api-surface-batch-c.md` and recorded in the section "Repository API and typed errors" above.

## Rejected alternatives
- **Per-record writes of run-owned records (Q5).** They bypass `check_run_bundle`. Streaming ingest and staging tables are a Phase 5 design input.
- **Rescoring by replacing results in place (Q6).** It edits records of fact; a rescoring is a new bundle.
- **A silent partial bundle (Q16).** Two contents would stand under one RunBundle ID.
- **A plain failure for an incomplete bundle (Q16).** The remaining records would become unreachable.
- **A unique external-ref key for every kind (Q17).** One provider call may yield several transcripts or usage records; uniqueness would be an assumption.
- **A unique key for spans as well (revision 34 text; batch B A1).** The frozen golden RunBundle holds two spans of one run with one `span_ref`; the store would refuse a valid bundle.
- **Matching external references after normalization.** It would merge identifiers that another system keeps distinct (case, white space, normalization forms).
- **A versioned language declaration (Q22).** It edits a record of fact.
- **Per-field length limits now (Q23).** No measurement supports a number yet.

## Consequences
- A rescoring keeps the run's snapshot (`[snapshot]` requires `run.config_snapshot_id` to equal the embedded snapshot), so scoring with other definitions is a new run.
- `verify_bundle_digests` (B11) is not part of Phase 2 (Q27): the store holds no keyed own digests, and exports are opaque; it comes with key management.
- Importers must look up before minting; the store refuses, never merges, a second run for one external reference. Spans, transcripts and usage records with a repeated reference are all stored, and a lookup returns every one of them in the run.
