## Context
A schema designed only from documentation fits documentation. Phase 1 must show that real outputs of the systems we target (Pipecat OTel spans, Langfuse-attributed OTLP, Sarvam STT REST, Pipecat conversation logs and turn events, AudioBufferProcessor WAV, Pipecat Evals scenario YAML, a VoicEra transcript export) fit the schema without losing information and without inventing values. One of these samples is a real call from the user's own deployment and contains a real person's speech, so it must stay private.

## Decision
1. **Fixtures F1-F8**, each committed with a `provenance.json` of `{source, retrieval date, software version/commit, method: captured|synthetic_from_docs|synthetic_hand_written_twin|private_real, license, PII status}` (revision 31: `synthetic_hand_written_twin` added for the public F8 twin, which is written by hand from the documented structure of a private real file and is neither captured nor derived from published documentation; Decision 5):
   - F1 Pipecat OTel spans (T1)
   - F2 Langfuse-attributed OTLP (T1; `synthetic_from_docs` unless a real instance is available)
   - F3 Sarvam STT REST (T0)
   - F4 Pipecat `conversation.json` (T2)
   - F5 Pipecat Evals scenario YAML
   - F6 AudioBufferProcessor WAV
   - F7 turn events (T2)
   - F8 VoicEra transcript export

   Captures come from the pinned harness (`tools/capture/`, `pipecat-ai==1.13.0`), which is not a runtime dependency.
2. **The no-fabrication rule.** A mapping may fill a target field only from a source field or a documented derivation that uses source fields only. Anything else stays `None`/absent, or uses the explicit unknown member of a closed enum (`wall_time.meaning=unknown`, `Turn.source=agent_log` where the producer is the agent but the stage is unstated), plus an ingest warning. Guessed values are forbidden: 0, false, made-up timestamps, made-up confidences, assumed timezones, an assumed transcript stage, an assumed timestamp meaning. **Field-provenance tables (P-51):** each mapping declares a table (target path -> source path, derivation name, or `absent`), and `test_no_fabricated_values_all_mappings` checks every non-null target value against it, so fabricated non-trivial values (an assumed stage, a computed timestamp) are caught, not only suspicious ones (0, false). A derivation that relies on a provider's published API contract (for example the currency of a cost field that carries none, ADR 0014 Decision 12b) cites the contract (URL and `retrieved_at`) in that table; an uncited contract is not a derivation. A speaker the source does not identify maps to role `unknown`, never to a guessed `caller` or `agent`. **User declarations (revision 10, N14):** `Transcript.declared_language` is the only target field that a mapping may fill from outside the source, and only from a declaration that the user gave to the importer (ADR 0004 Decision 6g). Its row in the provenance table is `user_declared`, not a source path. `test_no_fabricated_values_all_mappings` accepts a non-null `declared_language` only when the test run supplied a declaration, and never in a mapping of a source that carries a transcript-level label.
3. **The blocking-gap definition** (verbatim from SCOPE.md gate item 13):

   > A blocking gap is a source field whose information is needed by an MVP-1 metric, the verdict or the cost model and that cannot be represented without loss or would need a guessed value (0, false, a made-up timestamp or confidence).

3a. **Repeated usage quantities (revision 17, N64 decided, auto-approved, option A; ADR 0014 Decision 9).** `UsageRecord.quantities` holds one quantity per unit and the type never sums. A mapping that meets two or more quantities of one unit merges them into one (their exact sum) only when the source payload, or the source's published API contract cited in the field-provenance table with URL and `retrieved_at` (as for currencies, P-53), states that they are parts of one billable event. Quantities of separate billable events (separate calls the source identifies) become separate usage records, one per call. Otherwise the mapping records a mapping gap: an IngestWarning whose `path` locates the repeated field, and a gap-register row (Decision 4) for the field. It never sums, and never keeps one count and drops the other, because increment and minimum apply per usage record and unit and a guessed merge can change the bill. **Revision 18 (N76 decided, auto-approved, option A):** when the quantities cannot be merged, the mapping builds **no `UsageRecord` for that call** (not even with its other units), records an IngestWarning with `code` `usage_quantities_not_merged`, `path` the repeated field in the mapping's path form and no `raw`, and a gap-register row classified **blocking** (Decision 3: cost information is lost). A record without the repeated unit would be priced by `compute_cost` as an available partial cost of the call, which ADR 0014 Decision 13 forbids; because no cost record then says "usage lost", the gap must block the gate until the source or a cited contract settles the billing. Test: `test_f1_repeated_unit_quantities_merged_only_for_one_billable_event` (P1-29).
4. **The gap register** (P1-35) lists every unmapped or lossy source field with its fixture, a classification (blocking / non-blocking), a reason and an owner. The gate requires 0 blocking gaps. `KNOWN_SCHEMA_GAPS` may contain only non-blocking mapping gaps with owners (gate item 2). A blocking gap is resolved by a schema change, never by a guess.
5. **The private fixture policy.** The real VoicEra file lives only under `packages/evalschema/tests/fixtures/private/voicera/`. That path is gitignored, and a guard script plus a CI job fail if anything under `private/` is tracked or staged. Its tests carry the `private_fixtures` marker and are deselected in CI (not skipped). It is never committed or pushed, and its text is never quoted in committable files (code, docs, ADRs, test names, assertion messages, gap register). A hand-written **synthetic twin** with identical structure and no real text is public and runs in CI. `test_f8_twin_matches_real_structure` (private marker) checks that the twin and the real file have the same structure.
6. **The F8 structure** (description only): line 1 `call_id=<uuid>`; line 2 `---`; then one line per logged message, `[ISO-8601 UTC timestamp with milliseconds and +00:00] assistant|user: text`. There is one timestamp per line with ambiguous meaning, and no audio, confidence, language tag, tool calls or end-of-call reason. `call_id` is a bare UUID kept as an `ExternalRef`. One assistant line may concatenate several utterances. Turns may mix scripts. The file name carries local time (IST) while the content is UTC; the file name is not used for timing. The user states this is VoicEra's standard export (not verified). The importer itself is Phase 6; Phase 1 proves the format can be expressed.
   **F8 mapping (accepted in revision 3):** `assistant` -> role `agent`, `user` -> role `caller`; both with `Turn.source=agent_log` (the export is the agent's log and does not state the stage); the per-line timestamp -> `Turn.wall_time{at, meaning: unknown}`; `timing_source=none`; `start_ms`/`end_ms` absent; one Turn per line; `language` absent; `interrupted=None`; the file's call ID -> `ExternalRef`; `Transcript.declared_language` absent unless the user declares a language at import (revision 10, N14; worked example in ADR 0004 Decision 6h). The two candidate blocking gaps of revision 2 (timestamp meaning, unknown stage) are therefore resolved without loss and without a guess. The concatenation limitation stays in the gap register as non-blocking.
7. **F3 language labels (accepted in revision 3).** A provider label such as `bn_IN` is kept verbatim in `Transcript.detected_language_raw`; the importer derives `detected_language=bn-IN` and records a `language_label_normalized` warning (ADR 0005). This resolves the revision 2 candidate blocking gap for language-switch metrics. Whether Sarvam actually returns underscores is to be confirmed from the real capture (P1-31); the test covers the underscore case either way.
8. **Doc-derived fixtures** (`synthetic_from_docs`) are re-captured from real systems before the Phase 5/6 gates. Docs read from Pipecat `main` are re-verified on the 1.13.0 tag.
9. **Indic fixtures** carry `verified: rule|source|needs_native_review`. A `needs_native_review` fixture is never used as a WER/CER reference.
10. **Secrets during capture:** provider keys (for example Sarvam for F3) come from environment variables at capture time only, and never appear in fixtures or provenance (ADR 0007).

## Rejected alternatives
- **Docs-only fixtures.** Documentation diverges from behaviour (unverified items include cached-token accounting, timestamp timezones and `turn_number` base). Real captures catch this before adapters are built.
- **Fill missing values with defaults so fixtures validate.** That hides the gaps the exercise exists to find, and it puts fabricated data into the reference fixtures that every later test trusts.
- **Commit the real VoicEra file with redaction.** Redaction of free Indic speech cannot be verified reliably by us, and the user approved local use only.
- **Skip private tests in CI (`pytest.skip`).** It conflicts with "zero skips" (gate item 2), and skipped tests look like passing coverage. Deselection by marker is explicit.
- **A looser blocking-gap definition** ("anything unmapped"). Every vendor attribute would block the gate. The definition targets exactly what affects metrics, the verdict and cost.
- **Mapping F8 user lines to `agent_stt`.** Likely but not stated by the source; it is a guessed stage.

## Consequences
- The gap register is a living document. Later adapters (Phases 5/6) add rows.
- With `wall_time`, `agent_log` and `detected_language_raw` in place, F3, F4 and F8 have no known candidate blocking gaps left; the real captures may still reveal new ones.

## Decided items (formerly [Proposed]; all decided by the user in revision 5)
- **P-51. Field-provenance tables. Decided by the user (revision 5): accepted as recommended.** Decision: each mapping declares a table (target path -> source path, derivation name, or `absent`), and `test_no_fabricated_values_all_mappings` checks every non-null target value against it. Reason: without a declared table the test can only look for suspicious values (0, false), which misses fabricated non-trivial values such as an assumed stage or a computed timestamp. Had it been decided otherwise: the test uses a value-pattern heuristic and documents what it cannot catch.
