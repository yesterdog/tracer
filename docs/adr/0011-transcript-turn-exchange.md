## Context
A run may have several transcripts of one conversation: our own BYOK STT, the agent's STT, the agent's LLM output, the text the agent sent to TTS, the agent's LLM context, the agent's own exported log, the script, and a human reference. They differ, and the differences are measurements: STT noise in Indic languages, TTS deviations, interruptions. Presenting noisy STT as ground truth is the main way voice evaluation lies. Sources also differ in timing: aligned audio, telemetry, observer frames, wall-clock log lines only (F8), or nothing (F4). Pipecat's "turn" is a user turn plus a bot response, which is what we call an Exchange.

## Decision
1. **`Transcript`** (entity `tsc`): `{source, provider?, model?, provider_call_ref?, detected_language: ObservedLanguageTag?, detected_language_raw: VerbatimText?, language_confidence?, declared_language: LanguageDeclaration? (revision 10), timeline_origin: TimelineOrigin?, privacy: PrivacyMarker}`. One transcript per producer. `language_confidence` is present only if the producer reported it. `detected_language_raw` keeps the provider's label verbatim (ADR 0005). `timeline_origin` is required iff any of its turns or segments has offsets (ADR 0002). `privacy` follows ADR 0016. **Turns are separate records (revision 11, N21 decided by the owner, option A):** a Transcript does not embed its turns; each Turn names its transcript (`Turn.transcript_id`), and the rules that span a transcript and its turns (`seq` unique within the transcript, `timeline_origin` iff any turn or segment has offsets) are checked by the pure function `check_transcript(transcript, turns, exchanges=None)` over the records of one RunBundle. `provider_call_ref` is an `ExternalRef` (revision 11, N28: a provider's request identifier is a foreign identifier, ADR 0012 Decision 6). **`Transcript.source` names the producer (P-27):** `our_stt | agent_export | agent_telemetry | observer | script | human_reference`, while `Turn.source` names the pipeline stage per turn, because one producer's transcript can mix stages (F4: user lines are agent STT, assistant lines are LLM context). F8 is `agent_export`.
1a. **`Transcript.declared_language` (revision 10, N14 decided by the owner).** A user-declared language for an imported transcript that carries no transcript-level label. The value object is `LanguageDeclaration{language: SupportedLanguage (no script subtag), source: user_declared, declared_by: MachineKey (no `@`), declared_at: UtcDatetime}`. It is allowed only when `source` is `agent_export`, `agent_telemetry`, `observer` or `human_reference` and `detected_language` and `detected_language_raw` are both absent. It is never an observation: it fills no observed field, and it is never copied to another transcript. How metrics use it, and how results record that use, is in ADR 0004 Decision 6g. `declared_by` names an actor, and like the rest of the transcript it is covered by `privacy`. Whether shared exports drop it is decided at P1-14.
2. **`Segment`** (value object): `{granularity: word|phrase|utterance, start_ms?, end_ms?, text, confidence?}` holds provider sub-structure (for example Sarvam phrase timestamps). `confidence` is only ever a reported value, in [0,1]. **Placement (P-28):** segments live in `Turn.segments[]` (optional); when both the segment and its turn carry times, the segment's range lies inside the turn's range.
3. **`Turn`** (entity `turn`): `{transcript_id (revision 11, N21), seq, role, start_ms?, end_ms?, wall_time: WallTime?, timing_source, source, text, segments[]?, language?, language_raw?, interrupted, exchange_index?, contains_bidi_controls}`:
   - `seq` is required (order is always known) and unique within its transcript. Timing is optional.
   - `role` comes from the closed Role set `caller | agent | unknown` (ADR 0016). `unknown` is used when the source does not identify the speaker (for example an undiarized STT transcript).
   - `timing_source ∈ {audio_alignment, telemetry, observer, none}`. It is `none` if and only if `start_ms` and `end_ms` are both absent.
   - **`wall_time: WallTime{at: UtcDatetime, meaning: start|end|logged|unknown}`** (accepted in revision 3; replaces `started_at`). It is an annotation, not timing: it never affects `timing_source` and never produces offsets.
   - `source ∈ {our_stt, agent_stt, agent_llm_output, agent_tts_input, agent_context, agent_log, script, human_reference}` records which pipeline stage produced the text. It is never collapsed. **`agent_log`** (accepted in revision 3) means: reported in the agent's own export or log, pipeline stage not stated. It is used when the source does not say whether the text came from the agent's STT, LLM, TTS input or context.
   - `text` is `VerbatimText` (ADR 0017). `contains_bidi_controls` is computed from `text` and verified on load.
   - `interrupted: bool | None`: `None` means unknown and is distinct from `False`.
   - `language` is an `ObservedLanguageTag` or `None`. `language_raw: VerbatimText?` keeps a per-turn provider label verbatim (P-13, ADR 0005).
   - **No Turn-level confidence (P-29):** confidence lives only on Segment (utterance granularity where providers report it), so no number that no provider reported is ever presented as a turn measurement.
4. **`Exchange`** (entity `exc`): `{index, started_at?, duration_ms?, was_interrupted?, source}`: a user turn plus the bot response, the unit Pipecat calls a turn. Turns link to it with `exchange_index`, which must name an existing exchange of the same run (revision 11, N22: an Exchange names no run, so "the same run" means the Exchanges of the same RunBundle, checked by `check_transcript(..., exchanges)`). Pipecat `turn_number` maps to `Exchange.index`, never to `Turn.seq`. `Exchange.started_at` is used only when the source states the exchange's start. **`Exchange.source` (P-06):** `audio_alignment | telemetry | observer | inferred_from_turns`; an exchange we reconstruct from turns is always `inferred_from_turns`.
5. **The no-fabrication rule for transcripts.** Missing timing gives `timing_source=none`, never synthesized offsets. Missing confidence stays `None`. A timestamp whose meaning the source does not state is `wall_time.meaning=unknown`. Text whose pipeline stage the source does not state is `agent_log`, never a guessed stage. One source line that concatenates several utterances (F8) is stored as one Turn with its text verbatim. It is not split by a heuristic.
6. Performance: a 50,000-turn (about 4 h) transcript validates in under 2 s (A-05). **Measurement (P-30):** the test runs on a fixed CI runner class and compares against a calibration loop measured in the same job (limit = 2 s scaled by the calibration ratio, floor 2 s on the reference runner), so it does not fail intermittently.

## Rejected alternatives
- **One transcript per run with a merged "best" text.** Merging is a judgement that hides disagreements between sources, and WER(agent_tts_input vs our_stt) is itself a metric (Phase 3 ablation).
- **Collapse agent sources into `agent`.** An LLM output, the text sent to TTS (which may differ after interruption or post-processing) and the LLM context are different evidence. Merging them makes the interruption analysis impossible. `agent_log` exists only for sources that do not say which of these they are.
- **Map an agent export to the most likely stage (for example `agent_stt` for user lines).** It is a guessed value under ADR 0018, and it would let an agent's STT output be compared as if we knew its provenance.
- **Required timing on Turn.** Transcript-only sources (F4, F8) would need fabricated timestamps. A transcript without timing is a first-class mode.
- **`started_at` for every per-turn timestamp.** It asserts a start time; for sources that log one unspecified timestamp per line this is a guess.
- **Deriving `start_ms` from `wall_time` and the first line's time.** It invents an origin and treats log time as speech time.
- **`interrupted: bool` defaulting to False.** "We don't know" would become "it was not interrupted", which biases interruption metrics.
- **Using Pipecat's turn as our Turn.** It mixes two speakers in one unit, so per-speaker metrics (talk ratio, WER per speaker) break.
- **Splitting concatenated lines by punctuation.** Heuristic splits create utterance boundaries that the source never asserted.

## Consequences
- Several transcripts per run are normal. Metrics must state which source they consume (via `requires`: `transcript` = our STT; `agent_transcript` = agent-side sources including `agent_log`).
- The F8 assistant lines are concatenations, so turn-level metrics on F8 measure "logged agent message", not "utterance". That limitation is recorded in the F8 gap register as non-blocking.
- Metrics that need a specific agent stage (for example TTS deviation, which needs `agent_tts_input`) are not_applicable on `agent_log` transcripts through `requires`, not scored on a guessed stage.

## Decided items (formerly [Proposed]; all decided by the user in revision 5)
- **P-27. `Transcript.source` vs `Turn.source`. Decided by the user (revision 5): accepted as recommended.** Decision: `Transcript.source` names the producer (closed set: `our_stt`, `agent_export`, `agent_telemetry`, `observer`, `script`, `human_reference`), and `Turn.source` names the pipeline stage per turn. Reason: one producer can report several stages in one transcript, so a single stage on the Transcript cannot be true for every turn. **Correction (revision 21, mapping contract M8, auto-approved; `docs/phase1/api-surface-mappings.md` section 4 and M8):** the example given here until revision 20 was wrong. The real F4 capture (Pipecat's conversation observer) shows that user and assistant lines are both writes to the agent's LLM context, so both are `agent_context`: typed RTVI text becomes a user turn that never passed STT, and calling the user lines `agent_stt` would be the guessed stage rejected above. The decision still holds, because the F1 telemetry transcript does mix stages (caller turns `agent_stt` from the STT spans, agent turns `agent_tts_input` from the TTS spans). Had it been decided otherwise (both carry the same stage set, all turns equal to the transcript's): F4 must be split into two transcripts per stage, and `test_transcript_source_names_producer` becomes `test_turn_source_equals_transcript_source`.
- **P-28. Turn and Segment. Decided by the user (revision 5): accepted as recommended.** Decision: `Turn.segments[]` (optional); when both carry times, segment times lie inside the turn's range. Reason: SCOPE defines Segment but not where it lives; providers report phrase/word structure inside an utterance, and placing segments on the turn keeps that structure with its text. Had it been decided otherwise (segments on Transcript with a `turn_seq` link): the containment test becomes a link-resolution test. Test (binding): `test_segment_times_within_turn`.
- **P-29. No Turn-level confidence. Decided by the user (revision 5): accepted as recommended.** Decision: confidence lives only on Segment (utterance granularity where providers report it); Turn has no confidence field. Reason: providers report confidence per segment or word; a Turn-level field would invite averaging those into a number no provider reported, which is a derived value presented as a measurement. The plan's `Turn.confidence` is satisfied by `Segment{granularity: utterance, confidence}`. Had it been decided otherwise: `Turn.confidence?` is added with the rule "only when the source reports it per turn", and `test_turn_confidence_only_when_reported` is added.
- **P-30. Making the 50k-turn time limit reliable. Decided by the user (revision 5): accepted as recommended.** Decision: the test runs on a fixed CI runner class and compares against a calibration loop measured in the same job (limit = 2 s scaled by the calibration ratio, floor 2 s on the reference runner). Reason: a wall-clock limit on shared CI runners fails intermittently, and an intermittent gate test gets ignored or retried until green, which removes its value. Had it been decided otherwise (plain 2 s limit): the test stays as written and may fail on slow runners; reruns must then be recorded in the gate evidence.

## Decided items (revision 11)
- **N21. How a Turn is tied to its Transcript. Decided by the owner (revision 11): option A.** `Turn.transcript_id` plus `check_transcript`; the Transcript does not embed its turns (Decisions 1 and 3). Rejected: embedding `turns` in the Transcript, which would put up to 50,000 Turn entities inside one record and make evidence references point into it.
- **N22. "The same run". Decided by the owner (revision 11): option A.** Records of fact other than `UsageRecord` carry no `run_id`; the RunBundle is the unit of a run (Decision 4; ADR 0009 Decision 5).
