## Context
Phase 4A calls agents over WebSocket and WebRTC on loopback (ADR 0026). Some agents under test are reached only by a phone number. A call over the public telephone network (PSTN) reaches a real line: if the number is wrong, a person answers a synthetic voice. Sarvam's terms v2.0 bear on it directly: 10.2(5) forbids "automated dialling systems or artificial ... voice messages to place calls without appropriate human authorisation and consent"; 10.2(8) requires labelling synthetic audio that could be mistaken for human speech; 10.3(6) asks agentic workflows for "human oversight, testing, rate-limiting and authorisation". The SIP stacks with Python bindings that the project could embed are copyleft: PJSIP is GPL-2 unless a commercial licence is bought, and `pyVoIP` is GPL-3, either of which fails `test_no_lgpl_or_gpl_in_lock`.

## Decision
Machine-read by `test_adr0029_rules_are_tested`, in the format of ADR 0023: every numbered rule of this section and every invariant cites at least one test name in backticks. A cited name that no test defines yet must be one that the task table of `docs/phase4/SCOPE.md` (section A) names. While this ADR is Proposed its rules bind no code; the batch P tasks implement them after O5.

1. **Provider REST dial-out plus a media-stream WebSocket (Q20; recommended).** Tracer asks the telephony provider the owner already uses to place the call through the provider's REST API (httpx in `tracer-evalproviders`, ADR 0024 rules 2 and 3: an injected transport, a fixed host, no redirect, TLS verified, no proxy environment), and the provider streams the call's audio to `tracer-evalsim` over its media-stream WebSocket, in the matching dialect (`twilio-media-stream/1` of ADR 0026 rule 6 when the provider is Twilio-compatible; otherwise a new named dialect from that provider's public documentation). SIP signalling stays inside the provider; Tracer contains no SIP stack. Rejected: PJSIP Python bindings (GPL-2 unless a commercial licence; fails the no-GPL check); `pyVoIP` (GPL-3); a SIP stack written by the project (a large audit surface for one feature). Alternative if the owner has only a SIP trunk (decided at P4-40): an external `baresip` process (BSD-3-Clause, outside the Python lock), bridged by audio files or pipes, at about 12 more hours. Trade-off: one provider per adapter, and the provider sees the call's audio. Tests: `test_adr0029_rules_are_tested`, `test_no_lgpl_or_gpl_in_lock`.
2. **The number allowlist (Q14, Q17; P4-31).** A number is called only if it is an entry of the allowlist file of ADR 0026 rule 16, written in E.164 (`+` and 8 to 15 digits, compared exactly as written, no other normalisation); the entries are the owner's own numbers only (O5). The check runs at step 2 of ADR 0026 rule 14, before any credential is read and before any provider request. The number to dial comes from the `--target` agent file only, never from text the agent or the brain produced (ADR 0028 rule 8). A number not on the list is refused (exit 4). Rejected: country-prefix or range entries (one entry would allow many lines); a confirmation prompt instead of a list (it can be clicked through). Trade-off: each number is added by hand. Tests: `test_dial_refuses_number_not_on_allowlist_before_any_request`, `test_target_not_on_allowlist_refused_before_any_key_or_socket`, `test_injection_from_agent_never_changes_dial_target_or_tools`.
3. **The authorisation record (terms 10.2(5) and 10.3(6)).** Before the first PSTN call to a number, the owner records in the decision log: the number's owner (by role, never a person's name), that the number is answered by the agent under test and not by a person, who authorised automated calls to it and when, and the reference text used for `--authorisation-reference` on such calls. A PSTN call without `--authorisation-reference` is refused at step 3 (ADR 0026 rule 21: only the SHA-256 is stored). The run book checks that the hash matches a logged record. Rejected: an authorisation stored in the run as text (a name or a number in a machine record); an authorisation given once for all numbers. Trade-off: each new number needs a logged authorisation before it is called. Tests: `test_refusals_happen_before_any_key_read_or_connect`, `test_order_of_operations_pinned_by_call_trace`.
4. **Rate limits (Q18; terms 10.3(6)).** One call per invocation, concurrency 1, and the minimum interval of ADR 0026 rule 18, all as for WebSocket calls; any further limit (calls per day, hours of the day when calls may be placed) is an owner value under O5 and has no default in code. Rejected: a suite mode for PSTN (BL-276). Trade-off: PSTN tests are slow by design. Tests: `test_one_call_per_invocation_and_min_interval`.
5. **Telephony credentials are BYOK (ADR 0007; ADR 0024 amendment A4).** The provider's credentials are read at run time from environment variables whose names the adapter fixes at P4-40 (or from `--env-file`, read for those names only), held in redacting wrappers, never in any output: exception, log at any level, call log, store, report, recovery file or TTS cache name. The caller id the provider requires is the owner's number and is sent only in the dial request. Rejected: credentials in the agent file or the allowlist (both are files a user may share). Trade-off: one more set of variables per provider. Tests: `test_dial_credentials_never_in_any_output`, `test_key_canaries_never_in_any_output_channel`.
6. **Hang-up on every end reason.** Every one of the eleven end reasons of ADR 0026 rule 9 ends with a provider hang-up request for the call, and the dial request also sets the provider's own maximum call duration to the call's maximum duration, so a crashed simulator does not leave a line open; a hang-up request that fails is retried within ADR 0024 rule 9 and then recorded. Rejected: relying on the media WebSocket closing (some providers keep the call up). Trade-off: one more request per call. Tests: `test_dial_hangup_on_every_end_reason`.
7. **The media endpoint is not exposed by default.** If the provider must connect to Tracer for the media stream, Tracer listens only for the duration of one call, on a path holding a one-time token of at least 128 random bits that is checked before the WebSocket upgrade is accepted, and every other connection is refused; exposure to the internet is only through a tunnel the owner approved under O5, opened for the call and closed after it. The token is never logged, stored or printed. Rejected: a permanently open endpoint; a token in a query string (it is logged by more intermediaries). Trade-off: each call needs the tunnel step. Tests: `test_media_endpoint_requires_one_time_token`.
8. **Numbers in records and outputs.** The target number appears only in the `AgentTarget` endpoint (`sip:` form, ADR 0012) in the local store and in the dial request; it is never printed by the CLI, never in the call log, the report, a log line or any committed file (the report shows the endpoint with the number replaced by a fixed placeholder). The caller id is never stored. Rejected: printing the last digits "for convenience" (a partial number still identifies a line). Trade-off: the report cannot tell two numbers apart; the run's agent target id can. Tests: `test_simulate_never_prints_target_number_or_key`, `test_sim_call_log_has_no_text_no_number_no_key`.
9. **Synthetic audio over the telephone (terms 10.2(8)).** The report labels the caller channel "synthetic caller audio" (as for every simulated run). Whether a PSTN call must also say so audibly at its start is part of the owner's regulation statement under O5 (BL-297); if it must, the disclosure line is a fixed text per language, reviewed by indic-linguistics, recorded as the first `script` turn, and its effect on the agent is stated in the measurement report. Rejected: deciding it without the owner's statement. Trade-off: until O5, an audible disclosure is neither required nor forbidden by this ADR. Tests: `test_sim_report_labels_synthetic_audio`.
10. **Audit and the first call (P4-42, P4-43).** The telephony audit delta (the robocall clause, the exposure of the media endpoint, numbers in records) is GO before the first PSTN call; the first call goes to the owner's allowlisted number only and is logged before and after with counts only. Indian rules for automated calls are not verified by the project; the owner's statement under O5 is recorded in the decision log before the first call. Rejected: a PSTN test in CI (it would dial). Trade-off: telephony is proven by one owner-gated call. Tests: `test_p4_telephony_audit_items_cite_tests`.

## Consequences
- No telephony code exists before O5 is answered; Phase 4A does not depend on this ADR.
- Every PSTN call needs an allowlist entry, a logged authorisation, caps, the audit, and the owner's regulation statement.
- When O5 is answered, P4-40 rewrites the "at P4-40" items with the provider's names and sets the status to Accepted, with an index revision and a Changes entry.
- (2026-10-27, owner decision; BACKLOG BL-311.) Telephony is moved out of Phase 4 to a later stage that starts with a design and research study, because several CPaaS providers, individual SIP servers and trunks, and telco-specific behaviours have to be thought through first; this ADR is therefore a provisional sketch, not a decision, and its recommended design (provider REST dial-out plus a media-stream WebSocket) will be revisited, probably rewritten, by that study's ADR.
