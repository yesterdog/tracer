## Context
The Phase 3 base case is one language, mr in Devanagari, and two recorded calls (owner, 2026-10-25). For each call there is a mono recording and the agent's own VoicEra-format export of the same call. The export is the agent's output, already reviewed by a person, but it is not claimed to be correct anywhere; the owner's product principle is review reduction: Tracer points at the spans of the export a person should read, so the person reads less. No list of known mistakes is an input or an evaluation set (owner correction, 2026-10-25; BL-178).

So Tracer transcribes the recording with a second engine (Sarvam STT, ADR 0024), aligns the two texts word by word, and flags the export spans where they disagree. Nothing here is a reference transcript: a disagreement says that two machine outputs differ, not which one is wrong. Schema 0.0.1 stays byte-unchanged (SCOPE Decisions D5), so every rule below uses the 0.0.1 records as they are; the gaps go to the 0.0.2 backlog (BL-180 to BL-182).

Facts in the 0.0.1 code that shape this ADR: the units are exactly `ms`, `count`, `ratio`, `percent`, `wer` and `cer`, and `wer` and `cer` are error rates that may exceed 1 (ADR 0010 Decision 1a); `transcript` is our STT and `agent_transcript` an agent-side source (ADR 0011); `DECLARABLE_SOURCES` excludes `our_stt` (ADR 0004 Decision 6g); `EvidenceRef` holds no character span, confidence or signal (ADR 0012); `ConfigSnapshot` needs an `Evaluator`, a `Persona` and a `Rubric` with a required item that has a pass rule; and the applicability steps of a metric whose `requires` names `agent_transcript` read only the turns with role `agent` (`bundle._turns_read`, ADR 0004 Decision 6d), whatever its other input kinds.

1. **Agreement, never accuracy (owner product principle; BL-165).** The scores say how much the agent's export and our STT transcript of the same call agree, and where they disagree. They never claim that either text is right, and no number is called accuracy, a word or character error rate, a recall or a precision. Tracer-authored text of the CLI output and of the HTML report contains none of these words or phrases, matched case-insensitively as whole words: `accuracy`, `WER`, `CER`, `error rate`, `correct`, `recall`, `precision`. The deny-list applies to the text Tracer writes (labels, headings, help, messages), not to the transcript text a user supplied, which is shown escaped (ADR 0017). The concept page `docs/concepts/recorded-scoring.md` contains exactly one sentence that names them, verbatim: "Tracer reports how far two transcripts agree; it does not measure accuracy, and none of its numbers is a WER, a CER, an error rate, a recall or a precision." and no deny-listed word outside that sentence. The agreement value is labelled "agreement distance (MER)" in the CLI, the report and the concept page; the expansion of the abbreviation and the title of the paper that defines it both contain deny-listed words, so they are written only in this ADR, and the concept page cites the paper by its authors and year. Rejected: calling the value WER against the export (the export is not a reference, BL-165); a free-text disclaimer without a check (it drifts). Trade-off: the word list can miss a paraphrase; the check is a floor, the review gate (P3-G) the rest. Tests: `test_cli_output_never_claims_accuracy`, `test_report_never_claims_accuracy`, `test_concept_page_states_no_accuracy_claim`.
2. **What is compared, and the roles (F6, Q10).** Every turn of the agent export (`Transcript.source=agent_export`), of both roles, is compared with every turn of our STT transcript (`our_stt`), as one whole-call, speaker-merged sequence each (mono audio, BL-166; no shared time base, BL-167). The export's `assistant` lines map to `agent` and its `user` lines to `caller` (ADR 0016 I13); the `caller` turns of the export are the agent's own speech recognition of the caller, so they are agent outputs under the amended ADR 0016 Decision 1, and what is judged is the agent's text, never the caller. The STT turns have role `unknown` (no diarization, F10). Rejected: agent lines only (misses the agent's recognition of the caller, probably its commonest transcript mistakes). Trade-off: the result mixes two kinds of agent output; the report labels each flag with the role of its export turn. Tests: `test_metrics_evaluate_agent_outputs_only`, `test_voicera_reader_maps_assistant_agent_user_caller`, `test_stt_transcript_maps_one_turn_per_nonempty_chunk`.
3. **Three shipped definition templates (F5, Q5, Q9; P3-18).** All three have `kind=deterministic`, `value_type=numeric`, `requires=["transcript", "agent_transcript"]`, `languages=["mr"]`, `script_sensitive=false` (the export's language comes from a declaration, which a script-sensitive metric never uses, ADR 0004 Decision 6g), `aggregation=per_conversation`, **no pass rule**, `implementation_ref` `builtin:<key>` and the two parameters of rule 4:
   - `stt_export_agreement_mer`: unit `ratio`, the MER of rule 7;
   - `stt_export_flag_count`: unit `count`, the number of flags (rule 10);
   - `stt_export_flagged_token_share`: unit `ratio`, the flagged share of export tokens (rule 11).
   The scorer registry (BL-144) maps each `implementation_ref` to its scorer; `ScorerInfo.version` is the distribution version of `tracer-evalcore`. A definition whose `implementation_ref` the registry does not know, or whose version differs, stops the run before any send. Rejected: a pass rule in the shipped templates (a pass line is the owner's review budget, rule 17, never a shipped value); one combined definition with a `json` value (three numbers each with its own unit are aggregable and checked by the schema). Trade-off: three results repeat the same alignment record (rule 12). Tests: `test_shipped_definitions_have_no_pass_rule`, `test_agreement_unit_is_ratio_never_wer_or_cer`, `test_definitions_requires_transcript_and_agent_transcript`, `test_unknown_scorer_refuses_before_run`.
4. **Binding parameters with no defaults (Q8; BL-172).** Each of the three definitions declares `flag_min_confidence` (`value_type=number`) and `normaliser` (`value_type=string`), and neither has a `default`. The binding supplies both. `flag_min_confidence` must be a finite number in [0, 1] and not a boolean; it is read exactly as the decimal of its shortest round-trip spelling (Python `Decimal(repr(value))`), so `0.5` is the decimal `0.5`. `normaliser` must name a normaliser `tracer-evalcore` ships; in Phase 3 that is only `mr-Deva/1` (ADR 0025). The three bindings of a run carry equal values (one alignment and one threshold per run). A missing, null, out-of-range or unequal value, or an unknown normaliser, stops the run before any STT request is sent. The MER value does not depend on the threshold; the parameter is there so that one record (rule 12) describes the run. Rejected: a default threshold (the owner sets it, BL-172); a threshold in the CLI only (it would be missing from the snapshot, so the run could not be reproduced). Trade-off: a run cannot start until someone has written the value into the run's inputs; for the base case the owner pre-registered 0.5 (P3-29, SCOPE Decisions D10), and Tracer never supplies a value itself. The review budget follows the same principle through the rubric file (rule 17). Tests: `test_flag_threshold_has_no_default`, `test_missing_binding_param_refuses_before_any_send`, `test_normaliser_id_is_versioned_and_recorded`.
5. **Tokens.** Both texts are tokenised over the original `Turn.text`, and each token carries its half-open code-point offsets `[start, end)` into that text and its comparison key, computed per token by the normaliser (ADR 0025 owns the boundary and key rules, among them that white space and punctuation separate tokens and are not tokens, and that a token's key is never empty). Offsets are Python string indices (code points), never UTF-16 units or bytes. The export sequence is the tokens of its turns in `seq` order; the STT sequence is the tokens of its turns in `seq` order, which is chunk order. Rejected: tokenising the normalised text (its offsets do not map back to what the reviewer reads). Trade-off: a key may differ in length from its original slice (case folding, NFC, dropped joiners), so the confidence of rule 9 is measured on keys while the highlight uses the original offsets; any change of a key, a boundary or an offset is a new normaliser id (ADR 0025). Tests: `test_tokens_carry_code_point_offsets_into_original_text`, `test_token_edges_never_split_a_grapheme_cluster`, `test_latin_tokens_inside_marathi_kept_as_tokens`, `test_numbers_tokenised_whole`.
6. **Word alignment with unique counts.** The two token sequences are aligned by comparing keys for equality, with a dynamic program whose cost is the pair (edits, deletions plus insertions), compared lexicographically and added component by component: a match costs (0, 0), a substitution (1, 0), a deletion (1, 1) and an insertion (1, 1). A **deletion** is an export token with no STT token, an **insertion** an STT token with no export token. Minimising edits first and then deletions plus insertions makes the counts H (hits), S, D and I unique for a pair of texts: for equal lengths, two substitutions and one deletion with one insertion both cost two edits, and a plain edit distance would let the tie-break choose between them, changing the MER. Among the alignments of minimal cost the backtrace from the end prefers, at each step, a match, then a substitution, then a deletion, then an insertion, so the op list (which decides the spans of rule 8) is deterministic. Inputs above the aligner's size cap give a typed error, never a partial alignment; the cap is a named constant of `tracer-evalcore`, fixed by P3-15 from its measurement and stated in its CHANGELOG, and changing it changes the scorer version. Rejected: a plain Levenshtein distance with a tie-break only (counts and MER depend on the tie-break); an alignment on characters (BL-183). Trade-off: the pair cost is a little more code than a single integer. Tests: `test_alignment_identical_texts_all_matches`, `test_alignment_single_substitution_insertion_deletion`, `test_alignment_tie_break_is_deterministic`, `test_alignment_size_cap_typed_error`, `test_alignment_mixed_script_latin_tokens`, `test_alignment_numbers_digits_vs_native_digits`, `test_alignment_measurement_2000_tokens`.
7. **MER and its unit (F5, Q5).** The agreement distance is the Match Error Rate of Morris, Maier and Green (2004), MER = (S + D + I) / (H + S + D + I), over the counts of rule 6. With rule 6 it is symmetric (swapping the two texts swaps D and I and changes nothing else) and always lies in [0, 1], 0 when the texts agree token for token. The value is the JSON number nearest to the exact fraction (Python's correctly rounded integer division); the exact counts are in the record of rule 12. The unit is `ratio`, whose domain is exactly [0, 1]. The units `wer` and `cer` are never used: ADR 0010 defines them as error rates that may exceed 1, measured against a reference transcript, and neither text here is a reference (BL-165, BL-161). Rejected: edit distance divided by the longer length (equally valid, less established); edit distance divided by the export length (unbounded, needs `wer`, and implies the export is a reference). Trade-off: MER is less familiar to readers than WER; the concept page explains it. Tests: `test_mer_in_unit_interval_and_exact_counts`, `test_alignment_is_symmetric_in_mer`, `test_agreement_unit_is_ratio_never_wer_or_cer`.
8. **Disagreement spans (P3-16).** A span is a maximal run of consecutive non-match ops of the op list, split where its export tokens belong to different export turns, so a span never crosses a turn boundary. Inside a split run, a substitution goes with its export token, and an insertion goes with the span of the nearest export token before it in the run, or, if the run has none before it, with the span of the first export token after it. A run of insertions only becomes a zero-width span at its gap: at the end offset of the export token before the gap, in that token's turn, or, when the gap is before every export token, at the start offset of the first export token. Each span records its export turn by `seq`, its half-open code-point offsets `[start, end)` into that turn's text (from the first span token's start to the last one's end, so the substring between them is shown exactly as written), its half-open range of STT token indices, and its op counts. Its approximate audio range comes from the STT Segments that hold its STT tokens (phrase granularity, F10): from the start of the first such Segment to the end of the last; it is absent when the span has no STT token or those turns have no Segment timing. Spans are only ever placed on the export text; the STT text is the comparison side. Rejected: spans on the STT text (the reviewer reads the export); merging adjacent spans of different turns (one highlight would cover two speakers). Trade-off: a disagreement at a turn boundary yields two spans and so two flags. Tests: `test_spans_are_maximal_non_match_runs`, `test_spans_never_cross_turn_boundaries`, `test_insertion_flag_is_zero_width_at_gap`, `test_span_maps_back_to_exact_export_substring`, `test_span_audio_range_from_stt_segments_or_absent`, `test_spans_only_on_export_never_on_stt`.
9. **Confidence: an uncalibrated disagreement strength, not a probability (Q7).** For each span, the export key is the keys of its export tokens joined by one U+0020 SPACE, and the STT key likewise. `edit_distance` is the Levenshtein distance between the two keys over code points (unit costs), and `key_length` the larger of their lengths in code points (at least 1, since a span has at least one token and keys are never empty). The confidence is `edit_distance / key_length`, in [0, 1]; for a pure insertion or a pure deletion one key is empty, so it is exactly 1. The record keeps both integers and the confidence as a canonical decimal string rounded half to even to 4 fractional digits, which is for display only. The value is not calibrated, is not a probability and is never described as one; calibration needs labelled data (BL-184, BL-178). Rejected: a constant 1.0 (the threshold would select nothing); a "probability" label (an unearned claim). Trade-off: a one-letter spelling variant in a long word gets a low confidence and a short substituted word a high one, which is the intent; number words against digits get a high one (BL-192). Tests: `test_confidence_in_unit_interval_and_deterministic`, `test_confidence_is_one_for_pure_insertion_or_deletion`.
10. **Flags, the threshold and the signal (Q7, Q8).** A span is a flag iff its confidence is at or above `flag_min_confidence`, compared exactly: `edit_distance >= flag_min_confidence * key_length` in exact decimal arithmetic, never on the rounded display value. Every span is recorded (rule 12), flagged or not, so the report can show the distribution of confidences; it shows a histogram and never a recommended threshold. Flags are raised behind a `Signal` interface; the only Phase 3 signal is named `stt_disagreement`, and a second signal plugs in behind the same interface with its own name (BL-173 to BL-175). A span is `near_chunk_boundary` iff its STT tokens include the first or the last token of an STT turn (a chunk, ADR 0024), or, for a span without STT tokens, its gap lies between two STT turns; the rule uses token positions only, so it needs no time margin. Rejected: keeping only flagged spans (the owner could not see what a threshold would change); a time margin around cuts (a number nobody measured). Trade-off: every span is stored, so a noisy call stores many records. Tests: `test_flag_kept_iff_confidence_at_or_above_threshold`, `test_signal_interface_accepts_second_signal_stub`, `test_near_chunk_boundary_marked`.
11. **The three values and the workload unit (Q9).** `stt_export_flag_count` is the number of flags. `stt_export_flagged_token_share` is the number of export tokens inside flags divided by the number of export tokens, the JSON number nearest to the exact fraction; a zero-width flag covers no export token. The CLI and the report print every value with its counts: MER with H, S, D and I, the flag count, the share as numerator and denominator, and the number of export turns that hold a flag. Rejected: characters as the workload unit (long words weigh more); turns (too coarse for "read only the spans"). Trade-off: an insertion flag adds to the count but not to the share. Tests: `test_cli_prints_counts_with_denominators`, `test_e2e_synthetic_mr_exact_outputs`.
12. **The `tracer.flags/1` record (F4, Q6).** Each of the three scored results carries in `MetricResult.metadata["tracer.flags"]` the same document of the format in the section "The `tracer.flags/1` format": the format name, the signal, the normaliser id, the STT provider and the model as requested, the threshold, the alignment counts, the token counts and one record per span. It holds only integers, booleans, canonical decimal strings and short machine keys: no text of either transcript, no ID string and no path, so `metadata_flags` stays empty; turns are named by their `seq`. `tracer-evalcore` validates the document against the format and its cross-field rules before it builds a result, and refuses a result whose `metadata_flags` would not be empty. The format is owned by `tracer-evalcore`; any change of a field, a rule or a meaning is a new format name (`tracer.flags/2`). Not-applicable and error results carry no such document. Rejected: one result per flag (one definition gives one result per run); `per_turn_share` (no character spans); a sidecar file (neither stored nor reproducible); the document on the count result only (the MER and share results would not carry their own counts). Trade-off: untyped in 0.0.1 and stored three times per run; a typed record is a 0.0.2 row (BL-181). Tests: `test_flags_metadata_validates_against_tracer_flags_1`, `test_flags_metadata_has_no_text_and_no_metadata_flags`, `test_adr0023_flags_format_matches_json_schema`.
13. **The result records (P3-19).** A scored result carries `ScorerInfo` (rule 3), `transcript_ids=[<export>, <stt>]` (required, since the bundle holds two transcripts, ADR 0004 Decision 9), `language_source=declared` with `declared_language_transcript_ids=[<export>]` (rule 14), and evidence references: one `EvidenceRef{kind: turn}` per distinct export turn that holds a flag, in `seq` order, then one `EvidenceRef{kind: artifact_range}` per distinct audio range of a flag (rule 8), in span order. All three scored results of a run carry the same references. Every result passes `results.check_result_against_definition`, and every reference resolves in the bundle. Rejected: references only on the count result (the report links each value to its evidence). Trade-off: none beyond the repetition of rule 12. Tests: `test_results_pass_check_result_against_definition`, `test_transcript_ids_required_with_two_transcripts`, `test_language_source_declared_from_export`, `test_evidence_refs_resolve_in_bundle`.
14. **Language (F2, Q4).** The STT request sends `language_code=unknown` (ADR 0024), so each STT turn carries the tag the engine observed for its chunk (`Turn.language`), and a forced code, which the engine only echoes, is never sent. The export carries no language label, so its language is the user's declaration (`Transcript.declared_language`, source `user_declared`, from the required `--declared-language` input, ADR 0004 Decision 6g), and the results record `language_source=declared` (the report says "language declared by user", BL-147). In 0.0.1 the applicability of a metric that requires `agent_transcript` reads only the `agent` turns (`bundle._turns_read`), so the STT turns (role `unknown`) never enter the language steps and `check_run_bundle` would reject a not-applicable result that cites them. The STT language gate is therefore the scorer's, applied before any alignment, over the non-empty chunks: any STT turn without an observed language gives `status=error` with `error.code=stt_language_not_observed`; otherwise any STT turn whose primary language is not mr gives `status=error` with `error.code=stt_unsupported_language`. Both carry the language provenance the re-run computes (`declared` and the export's ID), never a value, never 0 and never a pass or fail, and the message counts the turns by outcome and names no tag and no text; the CLI and the report say "not scored: unsupported language detected", never an agent failure and never a zero. An export without a declaration gives `not_applicable` `language_not_observed` with `language_source=None` (ADR 0004 Decision 6f), which the re-run agrees with. `Transcript.detected_language` of the STT transcript is set only when every non-empty chunk reported the same tag. Rejected: forcing `mr-IN` (echoed, not observed, so always `language_not_observed`, F2); a not-applicable result the bundle check rejects; dropping the non-mr chunk (fake deletion flags). Trade-off: a non-mr chunk is an `error`, not the `unsupported_language` reason, until 0.0.2 lets a metric read the turns of each input kind (Ambiguity 1). Tests: `test_stt_turn_language_is_observed_from_unknown_request`, `test_tdeg_non_mr_chunk_is_not_scored`, `test_tdeg_export_without_declaration_language_not_observed`, `test_detected_language_set_only_when_all_chunks_agree`, `test_report_shows_language_declared_by_user`.
15. **Not-applicable and error rules (T-DEG; Q14, Q16).** Every case produces the same three result keys and the same record kinds; only status, value and reasons differ, and a missing input is never 0, false or a failure (ADR 0004):
   - audio and export (with declaration), every non-empty chunk mr: three `scored` results;
   - no audio: no STT transcript, so `transcript` is not in `available_inputs` and the three results are `not_applicable` `missing_input` with `missing_kinds=["transcript"]`;
   - no export: `not_applicable` `missing_input` with `["agent_transcript"]`; neither: `["transcript", "agent_transcript"]` (the order of `requires`); an export with no `assistant` line holds no agent turn, so `agent_transcript` is not available either (ADR 0004 T-A4);
   - an STT failure on any chunk: no STT transcript at all (all or nothing, ADR 0024), so `missing_input` `["transcript"]`, a Run `IngestWarning` and a non-zero exit (ADR 0004 Decision 10);
   - an export with no token, or an STT transcript with no token (every chunk empty or punctuation only): `status=error` with `error.code=no_tokens`, the message naming the side (`export` or `stt`); never a MER of 0 or 1, because with one side empty every token would disagree and the likelier cause is a silent input, not the agent;
   - the STT language outcomes of rule 14; an input over the size cap (rule 6): `error` with its own code.
   The scorer checks the STT language first, then the tokens, then the size cap. Rejected: `error` for a failed STT (the input never existed, Q14); a partial STT transcript (its missing chunks would read as deletions, Q14). Trade-off: a failed chunk discards the paid transcription of the chunks that succeeded (their usage is still recorded, ADR 0024). Tests: `test_tdeg_audio_and_export_scored`, `test_tdeg_no_audio_missing_input_transcript`, `test_tdeg_no_export_missing_input_agent_transcript`, `test_tdeg_schema_identical_across_cases`, `test_tdeg_export_without_agent_turn_missing_input_agent_transcript`, `test_empty_export_is_error_no_tokens_not_zero`, `test_empty_stt_is_error_no_tokens_not_zero`, `test_alignment_empty_side_cases`, `test_stt_failure_is_missing_input_with_warning_and_nonzero_exit`.
16. **The recorded run (F7, Q20).** The Run has `mode=recorded`, `caller_origin` from the required `--caller-origin` input (no default, ADR 0016 Decision 2), `observed_tier=T0` (an `agent_export` transcript and timing `none` or `audio_alignment` are T0 evidence, F7), `available_inputs` exactly `audio`, `transcript`, `agent_transcript` when all three exist (fewer in the T-DEG cases), and no `started_at` (the recording does not state it, and it is never the ingest time). The Artifact and both Transcripts carry a privacy marker from the explicit `--consent` and `--retention` inputs; the unknown-role STT turns make the run human-subject whatever the caller origin (ADR 0016 Decision 5). No `RunVerdict` is produced in Phase 3 (BL-186). Every produced bundle passes `check_run_bundle`. The Run holds no `external_refs`: the VoicEra call id stays on the export transcript's `provider_call_ref` (revision 42, finding F14), because a call id on the Run is the re-import key of ADR 0022 Decision 11, so a second run of the same call (the repeat and shifted-chunk measurements of P3-31) would be refused as a `ReimportConflict` in the same store. The snapshot's `AgentTarget` needs an endpoint, which a recorded call does not have; it is `wss://recorded-call.invalid/`, a name in the reserved `.invalid` domain (RFC 6761) that can never resolve, and nothing else is declared about the agent (revision 42, finding F15). Rejected: inferring the start from the export's wall-clock lines (they time the lines, not the recording, BL-167); a verdict over a review budget nobody has used yet (Q20); the call id on the Run (two runs of one call could not share a store); a real-looking endpoint (it would claim a connection that never existed). Trade-off: finding earlier runs of a call means reading the export transcripts, not a Run index. Tests: `test_pipeline_bundle_passes_check_run_bundle`, `test_pipeline_observed_tier_is_t0`, `test_pipeline_started_at_absent_never_ingest_time`, `test_cli_requires_every_privacy_and_language_input`, `test_artifact_privacy_marker_requires_explicit_consent_input`.
17. **Evaluator, Persona and Rubric for a recorded run (F3, Q13).** `Run.config_snapshot_id` is required, so a recorded run carries a snapshot with these workarounds, each stated as such:
   - the `Evaluator` text says what the run is, plainly: `instructions` states that a recorded call is scored by agreement between the agent export and an STT transcript and that no call was simulated; `expected_outcome` states that no outcome is evaluated; `language` is the declared language; `max_duration_ms` is 14,400,000, the schema maximum, stated as such in the text and not a measured length;
   - the `Persona` holds only the declared call language; it has no text field, so the `Evaluator` text carries the statement that no simulated caller exists (batch D ambiguity 5);
   - the `Rubric` has exactly two required items, in this order (revision 42, finding F13: `ConfigSnapshot` requires an enabled `llm_judge` boolean `equals_true` check that uses `{{expected_outcome}}` as a required rubric item, so the share cannot be the only required item):
     - FIRST, an inert check named `recorded_call_no_outcome_check`: its judge model is recorded as none (`not_run`), it is never run, it produces no result and no verdict reads it. It exists only because 0.0.1 demands such a check; it is a schema workaround, not a judgement, and the CLI and the report never show it as a check of the agent;
     - SECOND, a definition version of `stt_export_flagged_token_share` with the pass rule `range{max: <review budget>}`; the other two definitions are optional items. Definition versions are fresh version-1 definitions built from the shipped templates and the rubric file (batch D ambiguity 2).
   - The review budget, like `flag_min_confidence`, is an explicit field of the RUBRIC FILE the user passes to the CLI. It has no default in code, the shipped definitions carry no pass rule (rule 3), and Tracer never proposes, derives or supplies a value; a rubric file that lacks the budget (`rubric_budget_missing`), or lacks a required item with a pass rule, is refused before any send. An optional top-level `note` in the file is for people and is never stored.
   - **The base-case placeholder (revision 41, SCOPE Decisions D10; BL-214).** The project's own rubric file for the base case, shipped as a clearly labelled example, sets `max` = 1.0 as an explicit placeholder meaning "no limit; the rule cannot fail" (a share is never above 1). It is a value written in a user-visible file, not a code default. The CLI and the report print it as "review budget: 1.0 (no limit)" and never present the pass or fail of that rule as a judgement of the agent. The owner may set a real number at any time by editing the rubric file.
   No `RunVerdict` reads the rubric in Phase 3 (rule 16); the result of the share still records `passed` against the budget. The honest consequence: the snapshot of every recorded run holds one required check that never runs and texts that exist only to satisfy 0.0.1; a reader of the snapshot alone could take them for an evaluation, so the report states what they are. Rejected: running a judge on the expected outcome (a judgement nobody asked for, with spend and a model); a disabled check (0.0.1 requires it enabled); a budget default in code (a number nobody chose would read as a target); an unlabelled number in the example file (it would read as a recommendation); a schema change to make the judge check, Persona and the required item optional (D5; BL-182, BL-215). Trade-off: the snapshot carries workaround records until 0.0.2. Tests: `test_rubric_file_without_required_pass_rule_refused`, `test_missing_binding_param_refuses_before_any_send`, `test_shipped_definitions_have_no_pass_rule`.
18. **Reproducibility (revision 42, finding F16 and batch D ambiguity 4).** Every record gets a fresh UUIDv7 when it is built, so byte identity holds for the stored round trip: a bundle written to the store and loaded again is byte-identical. A rerun with the same audio, export, rubric file and STT responses gives the same records modulo their IDs (and the timestamps derived from them), never the same bytes, and each run builds a new snapshot with a new digest. The run records the normaliser id, the scorer version, the STT provider, the requested model and the request ids (ADR 0024). A comparison across runs therefore reads the parameters in the `tracer.flags/1` document (threshold, normaliser id, STT provider and model) and the scorer version, never the snapshot digests; a report that compares runs whose values differ says so (BL-147, BL-217). Rejected: deterministic IDs from the inputs (two runs of one call would collide in the store, and UUIDv7 is the schema's rule, ADR 0001); comparing snapshot digests (they differ for every run). Trade-off: "the same run" is a statement about parameters, not bytes. Tests: `test_pipeline_is_deterministic_given_same_stt`, `test_run_round_trips_through_store_byte_identical`, `test_normaliser_rule_change_requires_new_id`.
19. **Two clips are a demonstration (BL-170).** The owner fixes `flag_min_confidence` and the review budget, and they are written in the decision log, before any real result is seen (P3-29); on 2026-10-25 the owner pre-registered `flag_min_confidence` = 0.5, and the base-case budget is the labelled placeholder of rule 17 (SCOPE Decisions D10). Results of the two calls are reported per call with their counts and denominators, never as an aggregate claim, and no threshold is tuned on them. The run-to-run and chunk-boundary measurements (P3-31) report Jaccard indices of the flagged token sets with their counts. Rejected: choosing the threshold from the real results (the numbers would describe the choice, not the method). Trade-off: the first threshold may flag too much or too little; a change after R1 is a new pre-registration, logged with its reason. Tests: `test_flag_threshold_has_no_default`, `test_measurement_report_has_counts_and_denominators`.

Cross-field rules that JSON Schema cannot state, checked by the `tracer-evalcore` validator (each a refusal, never a repair):
- `flag_min_confidence` and `normaliser` equal the binding values of rule 4; `stt.model` is the model sent (ADR 0024).
- `alignment.hits + substitutions + deletions == tokens.export` and `alignment.hits + substitutions + insertions == tokens.stt`.
- Each span: `start <= end`; `export_tokens == substitutions + deletions`; `stt_token_end - stt_token_start == substitutions + insertions`; `start == end` iff `export_tokens == 0` (a zero-width insertion span); `confidence` is `edit_distance / key_length` rounded half to even to 4 fractional digits in canonical form; `flagged` is `edit_distance >= flag_min_confidence * key_length` exactly; the two audio fields are both present or both absent, with `audio_start_ms <= audio_end_ms`.
- The span op counts add up to the alignment counts: the sums of `substitutions`, `deletions` and `insertions` over all spans equal the alignment's.
- Spans are sorted by (`turn_seq`, `start`, `end`, `stt_token_start`); non-zero-width spans of one turn do not overlap; STT token ranges do not overlap and lie within `[0, tokens.stt]`.
- `tokens.flagged_export` is the sum of `export_tokens` over the flagged spans.
- When the result is built against its bundle: each `turn_seq` names a turn of the export transcript, and `[start, end)` lies within that turn's text, on token edges.

## Ambiguities resolved
- **Ambiguity 1. A non-mr STT chunk cannot be `unsupported_language` in a valid 0.0.1 bundle (new finding, F12).** SCOPE F2 and D1 say any non-mr chunk makes the whole result `unsupported_language`. In 0.0.1 a metric whose `requires` names `agent_transcript` has its language steps run over the `agent` turns only (`bundle._turns_read`), so the STT turns (role `unknown`) are never read, the re-run of `check_run_bundle` computes `scored` with `declared`, and a stored `not_applicable` result is rejected (`[applicability]`, field `status`). **Recommendation:** rule 14 (the scorer's gate, `error` with `stt_unsupported_language` or `stt_language_not_observed`, language provenance as the re-run computes it); accepted by the lead (SCOPE Decisions D7), which renamed the T-DEG test of P3-27 to `test_tdeg_non_mr_chunk_is_not_scored` (a named spec change of the row before any test existed). The 0.0.2 backlog row BL-193 records the fix: a metric with several transcript input kinds reads, for each kind, the turns that kind names (ADR 0004 Decision 6d read per input kind), so the STT turns enter the language steps. Rejected: `requires=["transcript"]` alone (a missing export would then not be `missing_input`); setting a role on the STT turns (fabrication); dropping or failing the chunk (fake deletions, or a run that hides the language).
- **Ambiguity 2. Which results carry `tracer.flags`.** Q6 says the count result; P3-19 says the scored results. **Recommendation:** all three, identical (rule 12), so each value is reproducible from its own result.
- **Ambiguity 3. Booleans in the record.** The SCOPE lists integers, decimal strings and machine keys. **Recommendation:** also JSON booleans (`flagged`, `near_chunk_boundary`); they hold no text and are never flagged by the metadata rule (ADR 0007 Decision 5a).
- **Ambiguity 4. Spans below the threshold.** **Recommendation:** recorded with `flagged=false` (rule 10), so the histogram and a pre-registered threshold can be audited; the count and share read flagged spans only.
- **Ambiguity 5. An empty STT side.** The SCOPE names `no_tokens` for an empty export. **Recommendation:** the same code for an STT side with no token (rule 15); the test `test_empty_stt_is_error_no_tokens_not_zero` was added to the P3-19 row (SCOPE Decisions D7).
- **Ambiguity 6. The deny-list on the concept page.** `test_concept_page_states_no_accuracy_claim` needs the page to state that no accuracy is claimed, which names deny-listed words. **Recommendation:** the one verbatim sentence of rule 1 is the only allowed occurrence; the CLI and the report have none, so MER is labelled "agreement distance (MER)".
- **Ambiguity 7. The parameters on the MER definition.** P3-18 lists both parameters for the templates. **Recommendation:** all three take both, with equal values (rule 4); the MER does not read the threshold.
- **Ambiguity 8. An export with only caller lines.** T-A4 makes `agent_transcript` unavailable without an agent turn. **Recommendation:** `missing_input` `["agent_transcript"]` (rule 15), stated so that it is not read as a missing file; the test `test_tdeg_export_without_agent_turn_missing_input_agent_transcript` was added to the P3-27 row (SCOPE Decisions D7).
- **Ambiguity 9. The no-verdict rule has no test of its own.** **Recommendation:** `test_pipeline_bundle_passes_check_run_bundle` also asserts that the bundle holds no `RunVerdict` (rule 16).

## Consequences
- The Phase 3 base case reports agreement and review workload per call and nothing else; any later claim about the agent's quality against a reference needs a reference transcript (`human_reference`) and its own decision.
- A run cannot start until its inputs name `flag_min_confidence` (in the bindings) and the review budget (in the rubric file); Tracer never supplies either. For the base case they are 0.5 (pre-registered by the owner) and the labelled placeholder 1.0 (no limit), revision 41.
- A non-mr chunk is an `error` result in Phase 3 (rule 14), so a report counts it with the errors, not with the not-applicable reasons, until the 0.0.2 fix of Ambiguity 1.
- The `tracer.flags/1` document is untyped in the schema; readers outside `tracer-evalcore` must validate it with the shipped schema and the cross-field rules.
- Every change of tokenisation, normalisation, alignment, confidence or the flag rule changes the scorer version, and a normaliser change also needs a new normaliser id (ADR 0025).
- (Revision 42.) Four 0.0.1 constraints shape every recorded run: an inert required judge check (F13, rule 17), no Run external references so the same call can be scored twice in one store (F14, rule 16), the reserved endpoint `wss://recorded-call.invalid/` (F15, rule 16), and fresh IDs per run, so runs are compared by their `tracer.flags/1` parameters (F16, rule 18). F13, F15 and the Persona have 0.0.2 backlog rows (BL-215, BL-216, BL-182), and the comparison rule of F16 is BL-217; F14 needs no schema change.
