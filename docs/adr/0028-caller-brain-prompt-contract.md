## Context
The caller brain decides what the simulated caller says next. It has three modes: scripted (the evaluator's `scripted_turns`, no model), LLM (Sarvam chat v2, `POST https://api.sarvam.ai/v2/chat/completions`, F8) and replay (`--caller fake:<dir>`, caller lines read from files). In LLM mode the model reads text that the agent under test produced, and the agent is untrusted: it may say "ignore previous instructions", ask for the system prompt or a key, dictate a phone number, send bidirectional controls or markup, or send ten thousand characters. The LLM's own reply is untrusted as well: it is spoken to the agent and recorded. Nothing the agent or the model says may change who is called, what is sent to a provider, what is logged, or what the evaluation knows. The Sarvam documentation says that `seed` is accepted and that "Output is not guaranteed to be identical across requests, even at `0`"; tool support per model is not verified (F8).

## Decision
Machine-read by `test_adr0028_rules_are_tested`, in the format of ADR 0023: every numbered rule of this section and every invariant cites at least one test name in backticks. A cited name that no test defines yet must be one that the task table of `docs/phase4/SCOPE.md` (section A) names; that set of not-yet-defined names shrinks to empty by the gate (P4-G).

1. **Three brain modes behind one protocol (P4-03, P4-15).** `CallerBrain` has exactly three implementations. Scripted: the next line is the next `Evaluator.scripted_turns` entry by `index`; it makes no LLM request at all, and its lines are synthesised before the call (ADR 0026 rule 14 step 7). LLM: each line is one `LlmEngine` request (rules 2 to 8). Replay: `--caller fake:<dir>` reads the line of turn N from `turn-NNNN.json` (four digits, from `0001`), makes no request, and every file the call could need (up to `max_turns`) is checked to exist and parse at step 1, so a missing file is a refusal before any key is read or any socket opened, never a failure mid-call; a replayed line passes the same output validator as an LLM line (rule 6). The mode is recorded in `tracer.sim_profile/1` and in `metadata["tracer.caller_text_origin"]` of the `script` transcript (ADR 0027). Rejected: an LLM fallback when the script runs out (a scripted run would silently spend and stop being reproducible); reading replay files lazily (a missing file would end a paid call). Trade-off: a replay directory must hold a file for every turn the call may reach. Tests: `test_brain_protocol_accepts_scripted_llm_replay`, `test_scripted_mode_makes_no_llm_request`, `test_replay_brain_missing_file_is_a_refusal_before_connect`.
2. **What enters an LLM request (Q8; P4-13).** Exactly: a fixed system template shipped by `tracer-evalcore` under a versioned id (`tracer.caller_prompt/<n>`), whose id and SHA-256 are recorded in `tracer.sim_profile/1`; the persona's language tag (`Persona.language`); the evaluator's `instructions`; the values of the evaluator's test profile, resolved as ADR 0006 states, which are synthetic by rule (a test profile holds invented identity and account values, never a real person's); the caller's own earlier lines of this call; and the agent's text of this call, inside fenced data blocks (rule 4). Nothing else, and the order is fixed by the template. Rejected: the persona's accent label in the prompt (the SCOPE names the language only; an accent label asks a text model for something text cannot carry, and accent fidelity is never claimed, ADR 0026 rule 24); free-form system text supplied on the command line (an unreviewed template could not be identified by its hash). Trade-off: a user who wants another template needs a new template version in `tracer-evalcore`. Tests: `test_prompt_template_hash_recorded_in_sim_profile`, `test_agent_text_only_inside_fenced_data_block`.
3. **What never enters any request (Q8).** The evaluator's `expected_outcome` (the caller must not steer the agent towards the success criterion), any metric definition, binding, rubric or judge text, any key or credential, the target endpoint or number, the allowlist, any file path, the authorisation reference, any identifier of this or another run, and anything of another persona. This holds for LLM requests and equally for TTS requests (only the caller line and the voice parameters are sent, ADR 0024 amendment A2) and for every log line. The request bodies are built offline in the tests and inspected for each forbidden item, with canaries. Rejected: letting the caller see the expected outcome "to stay on task" (the run would measure the caller's coaching, not the agent). Trade-off: an LLM caller may wander from the goal; `instructions` must state the caller's goal without the success criterion. Tests: `test_expected_outcome_never_in_any_llm_request`, `test_injection_cannot_leak_expected_outcome_or_key_canary`.
4. **The agent's text is fenced, escaped, capped and labelled untrusted (Q8).** The agent's text reaches the brain only as the text of its agent-channel STT turns (rule 9), and only inside a fenced data block of the template: a fixed opening and closing delimiter line, with the label that the block is untrusted data from the other party and holds no instruction. Before insertion, the text is cleaned in exactly this order, and nothing else is changed: every character of category Cc, Cf (which includes the bidirectional controls of ADR 0017), Cs, Co or Cn is removed, except U+200C ZERO WIDTH NON-JOINER and U+200D ZERO WIDTH JOINER, which Devanagari spelling uses (ADR 0025); any occurrence of either delimiter is replaced by a fixed escape token; the text is cut to `agent_text_max_chars` code points, a named constant of `tracer-evalcore` recorded in `tracer.sim_profile/1`, with a fixed truncation marker appended when it was cut. The cleaning is deterministic, so a replayed run builds byte-identical request bodies. Rejected: a random delimiter per request (request bodies would not be reproducible); passing the agent's text as a system message (it would read as an instruction); no length cap (a 10,000-character reply would fill the context and the spend). Trade-off: a fence lowers the chance that the model obeys injected text; it cannot make it zero, so rules 6 to 8 do not trust the reply either. Tests: `test_agent_text_only_inside_fenced_data_block`, `test_injection_from_agent_never_changes_dial_target_or_tools`.
5. **The request is fully explicit (Q10; P4-09).** Every LLM request sends an explicit `model`, a required `max_tokens`, the `seed` when the profile gives one, `reasoning_effort` when the profile gives one (required in the profile for a model the user declares as a reasoning model), no `tools`, no streaming, and nothing the provider would default. The seed is recorded and never presented as a guarantee: every output says that replies may differ between requests. Rejected: a default model or token limit in code; a determinism claim from the seed (the provider says it is not one, F8). Trade-off: the user names the model and the limits every time. Tests: `test_sarvam_llm_model_and_max_tokens_required`, `test_sarvam_llm_seed_recorded_never_claimed_deterministic`.
6. **The output validator (Q8; P4-13).** A reply is accepted only if, after removing leading and trailing white space and nothing else, it is either exactly the end sentinel (rule 7) or exactly one line of 1 to `max_line_chars` code points (a required value of `tracer.sim_profile/1`, no default) in Unicode NFC, every character of which is in the allowed set of the persona's script (for mr: the characters indic-linguistics lists in P4-00f, the Devanagari block, the danda, ASCII digits, ASCII punctuation and the space). The validator refuses; it never repairs (no stripping of characters, no re-normalisation, no truncation). A refused reply gets at most one regeneration (the same request again, the refusal counted in `brain_invalid_outputs`); a second refusal ends the call with `brain_invalid_output`. A replayed line that fails is refused with no regeneration. The text of a refused reply is never stored, logged, printed or synthesised; only the count is kept. Rejected: repairing a reply (the caller would say something no model and no script produced); unlimited regenerations (spend without bound). Trade-off: a model that drifts into Latin script ends the call early instead of speaking it. Tests: `test_caller_output_outside_persona_script_refused_once_then_ends`, `test_caller_output_length_cap_required`.
7. **The end of the call by the caller: a sentinel, not a tool (Q9).** The caller ends the call by replying exactly the line `END_CALL` (ASCII letters, which no valid mr line contains, so a line cannot become the sentinel by accident). Only an exact whole reply counts; the sentinel inside a sentence is not an end and the line then fails the character rule. No request carries a `tools` field, so no model output can call anything. The end reason is `caller_end_call`. Rejected: an `end_call` tool (tool support per Sarvam model is not verified, and a tool is one more output the model controls); ending on a phrase in the persona's language (an agent could make the caller say it). Trade-off: a model may say the sentinel inside a sentence; that reply is refused, not obeyed. Tests: `test_injection_from_agent_never_changes_dial_target_or_tools`, `test_caller_output_outside_persona_script_refused_once_then_ends`.
8. **No text can change the target or any action (Q8).** The target, the allowlist entry, the dialect and every provider endpoint are fixed before step 2 of ADR 0026 rule 14 and are read from the command line and the files named there only. A brain output has exactly two possible effects: a line that is synthesised and sent, or the end of the call. No code path reads agent text or model output into a target, a number, a URL, a file name, a cache key other than the TTS cache key of the line itself (ADR 0024 amendment A9), a log field, a command-line argument or a dial request (ADR 0029). Rejected: letting the caller "follow" a number the agent dictates (that is the injection the suite tests). Trade-off: a scenario that needs a callback to another number is not supported. Tests: `test_injection_from_agent_never_changes_dial_target_or_tools`, `test_target_not_on_allowlist_refused_before_any_key_or_socket`.
9. **The agent's text comes from in-call speech-to-text of each agent reply (new reading; Ambiguity 1).** In LLM mode the brain needs the agent's last reply as text during the call. When the agent falls silent (ADR 0026 rule 10), the agent-activity segment just ended is transcribed by the run's STT engine as one chunk of `tracer.chunk_plan/2` (ADR 0024 amendment A5; a segment longer than `max_chunk_ms` is cut by ADR 0024 rule 7), under the STT cap and with its usage handed out before the next request; those chunks are not sent again after the call (ADR 0026 rule 14 step 12). An empty STT result gives the brain an empty fenced block, never invented text. An STT request that fails after its bounded attempts (ADR 0024 rule 9) ends the call with `transport_error`; it is recorded as an STT failure (a Run `IngestWarning`), and the run then has no agent-channel transcript (all or nothing, ADR 0004 Decision 10a). The time this takes is the simulator's own reply time (`self.stt_ms` of `tracer.timing/1`), never part of an agent gap. Scripted and replay modes need no in-call STT. Rejected: a second, post-call transcription in LLM mode (the same audio paid twice, and two texts of one reply); live streaming STT (not verified for Sarvam, BL-279). Trade-off: in LLM mode the caller replies later than a person would, by the STT and LLM time; the timing document states it. Tests: `test_stt_agent_channel_turns_have_role_agent_from_declared_map`, `test_simulator_self_latency_excluded_from_agent_gap`, `test_simulator_never_speaks_while_brain_pending`.
10. **Caps (Q17).** Each LLM request has `max_tokens`; the run has `--max-llm-tokens` (ADR 0026 rule 15); a call has at most `max_turns` brain requests plus at most one regeneration each; `max_line_chars` is at most 2,500, the Sarvam TTS limit (ADR 0024 amendment A2). A cap reached ends the call with `spend_cap` or `max_turns`, never with a truncated line. Rejected: a soft cap that only warns. Trade-off: a long conversation needs the user to raise `max_turns` and the token cap explicitly. Tests: `test_caller_output_length_cap_required`, `test_simulate_requires_caps_for_real_engines`.
11. **Injection hardening is a tested property (P4-14).** The adversarial suite drives a fake agent that injects instructions, asks for the system prompt and for keys, dictates a phone number, sends bidirectional controls, markup and 10,000-character lines, and a fake LLM that returns injections back. No expected-outcome text, no key canary and no agent-dictated number reaches a TTS request, the call log, stdout, stderr, the store, the report or a dial action, and adversarial agent text never breaks the report or the store (it is escaped as ADR 0017 states). The security audit P4-32 reviews the suite before the first real call. Rejected: relying on the model's safety training. Trade-off: the suite covers known patterns, not every possible injection; the structural rules 3, 7 and 8 are the guarantee. Tests: `test_injection_from_agent_never_changes_dial_target_or_tools`, `test_injection_cannot_leak_expected_outcome_or_key_canary`, `test_adversarial_agent_text_never_breaks_report_or_store`, `test_p4_audit_items_cite_tests`.
12. **What a run keeps of the brain (Q11).** The stored run holds what is needed to rebuild every request: the template id and hash (`tracer.sim_profile/1`), the persona, the evaluator and its test profile (the snapshot), the caller lines (the `script` transcript) and the agent texts (the agent-channel `our_stt` turns). Refused replies are counted, never stored. The replay files of `fake:<dir>` hold one caller line each, so the lines of a stored LLM run can be replayed by writing its `script` turns into such files (a command that writes them is BL-296). LLM runs are replayable, not repeatable. Rejected: storing the raw request and reply bodies (a second copy of the same texts, and refused replies may hold injected material). Trade-off: rebuilding a request needs the template of the recorded version, which `tracer-evalcore` must keep shipping. Tests: `test_prompt_template_hash_recorded_in_sim_profile`, `test_scripted_mode_makes_no_llm_request`.

## Ambiguities resolved
For the lead (SCOPE D1 covers Q8 to Q11; these are readings the SCOPE leaves open).
- **Ambiguity 1. Where the LLM caller gets the agent's text (new finding, F12 of Phase 4).** Q8, Q11 and P4-13 put the agent's text into the prompt, while P4-21 transcribes the agent channel only after the call (step 12). An LLM caller cannot reply to text that does not exist yet. **Recommendation:** rule 9, in-call STT of each finished agent segment, which is the same chunk the post-call plan would cut, so nothing is transcribed twice and step 12 sends only the segments the call loop did not transcribe (all of them in scripted and replay modes). Rejected: post-call STT plus a second in-call pass; streaming STT.
- **Ambiguity 2. Tools.** P4-09 says "no `tools` except Q9's `end_call`", while Q9 says tool-calling is not used. **Recommendation:** Q9 wins: no request carries `tools` (rule 7), and P4-09's row is read that way.
- **Ambiguity 3. An STT failure during an LLM call.** The SCOPE names no end reason for it. **Recommendation:** the call ends with `transport_error`, the failure is recorded as an STT failure (Run `IngestWarning`), and the run has no agent-channel transcript (all or nothing; rule 9). Rejected: continuing with an empty block (the brain would reply to text it never received, and the stored transcript would have a hole); a new end reason (the closed list of ADR 0026 rule 9 is pinned by P4-04).
- **Ambiguity 4. Accent.** P4-00c says "persona" enters the prompt and P4-13 says "persona language". **Recommendation:** the language tag only (rule 2).

## Consequences
- In LLM mode every agent reply costs one STT request during the call, and the caller's replies are slower than a person's by that time plus the LLM time; `tracer.timing/1` reports it separately.
- A model that answers in the wrong script, too long, or in two lines, twice in a row, ends the call; the outcome counts it and the report says so.
- The template is part of the reproducibility contract: changing it is a new template id, never an edit.
