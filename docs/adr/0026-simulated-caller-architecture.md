## Context
Phases 1 to 3 score calls that already happened. Phase 4 places one call: a persona-driven caller (scripted, or an LLM caller) talks to one AI agent under test over a named wire dialect, records both sides, and hands the recording to the Phase 3 scoring path. Only the agent is evaluated; the caller here is a simulator (`Run.caller_origin=simulated`, ADR 0016 Decision 2). The facts below are the SCOPE findings, read by the staff-reviewer on 2026-10-27 from the Pipecat documentation and GitHub `main` (not a tag), PyPI and the Sarvam documentation and terms:
- Pipecat Evals (`pipecat eval run`) is a test-only harness: the bot must run Pipecat's `EvalTransport` behind the development runner's `/ws` route and the harness speaks RTVI `eval-*` messages, so it cannot place a black-box (T0) call to a deployed agent (F1).
- "A Pipecat WebSocket endpoint" is not one protocol: the development runner serves `/ws` (a telephony media WebSocket whose provider is detected from the first messages) and `/ws-client` (a plain WebSocket), plus `POST /start`, `/client/`, `/status` and Daily routes (F2). Which dialect a Dograh or VoicEra deployment exposes is not verified (the adapters phase). Corrected 2026-10-27 from the source at tag `v1.14.0` (BL-301; section "Dialect specifications"): `parse_telephony_websocket` detects Twilio, Telnyx, Plivo and Exotel (Vonage has its own runner file and no Genesys detection was seen, so the earlier list of six serializers is not confirmed); `/ws-client` does not enforce `ProtobufFrameSerializer` (the bot chooses its serializer and sample rate); `/client/` is the prebuilt web UI, and WebRTC signalling is `POST` and `PATCH /api/offer`.
- `pipecat-ai` 1.14.0 (uploaded 2026-10-24) requires `num2words` (PyPI licence "LGPL"), `soundfile` (wheels bundle libsndfile, LGPL-2.1, not verified for the locked wheel), `onnxruntime`, `numba` and others; its `sarvam` extra pins `sarvamai==0.1.28`, which is already rejected (no licence declared). As a runtime dependency it would break `test_no_lgpl_or_gpl_in_lock` (F3).
- The Sarvam terms v2.0 bear on the simulator: 10.5(a) (using output to test an AI system needs written permission), 10.2(5) (no automated dialling without human authorisation and consent), 10.2(8) (label synthetic audio that could be mistaken for human speech) and 10.3(6) (agentic workflows need human oversight, testing, rate limiting and authorisation) (F4; facts read from the terms, not legal advice).
- `aiortc` 1.15.0 is BSD-3-Clause but requires `av` (PyAV, whose wheels bundle FFmpeg; the licence of the bundled build is not verified), and the SmallWebRTC signalling route and body are not on the documentation page (F9). Since read in the source at tag `v1.14.0` (2026-10-27, BL-291, BL-301): `POST /api/offer` for the offer and answer and `PATCH /api/offer` for trickled ICE candidates (section "Dialect specifications").
- A value measured at the simulator is honest only if both clock edges are the simulator's own, and it includes the network and both sides' buffering (F10).

1. **A thin protocol client; no Pipecat in any tracer wheel (Q2; F1, F3).** Tracer speaks each wire dialect itself, written by hand from public documentation: no Pipecat source is copied, no code is generated from a Pipecat file, and no Pipecat module is imported by any tracer package. For `pipecat-protobuf/1` the public source is `frames.proto` at the cited tag (BSD-2-Clause, `Copyright (c) 2024-2026, Daily`): its message names, field numbers and types are interface facts recorded in this ADR, and Tracer implements a minimal hand-written encoder and decoder for them (amended 2026-10-27, BL-298); the BSD-2-Clause attribution is kept with those facts in this ADR and in `NOTICE` when the dialect ships. `pipecat-ai` is never a runtime dependency of a tracer wheel and is listed in `[[rejected]]` of `docs/security/license-policy.toml` for runtime with its reason (P4-02). Pipecat Evals is not built on and its RTVI `eval-*` messages are not a dialect. Rejected: Pipecat as a runtime dependency (LGPL `num2words`, `onnxruntime`, `numba`, the rejected `sarvamai` extra, weekly releases); `protoc`-generated code from `frames.proto` (a vendored licence notice and churn at every version; BL-298); building on Pipecat Evals (it needs the bot to run `EvalTransport`, so the call is not black-box, F1); the RTVI `eval-*` protocol (a harness protocol, not a production transport). Trade-off: Tracer maintains the dialect code and must re-verify it at every pinned Pipecat version (BL-282); the loopback interop tests are the drift alarm. Tests: `test_no_lgpl_or_gpl_in_lock`, `test_samplebot_not_a_workspace_member_and_not_in_uv_lock`, `test_samplebot_closure_reviewed_and_tool_only`, `test_dialect_spec_cites_docs_with_retrieval_date`.
2. **The package split (Q3, Q4).** Pure logic stays in `tracer-evalcore`: the `TtsEngine`, `LlmEngine` and `CallerBrain` protocols and their error taxonomy, the call state machine (rule 9), the turn-taking policy (rule 10), the recorder timeline and G.711 decode (ADR 0027), timing extraction, the prompt builder and output validator (ADR 0028), the timing definitions and the simulated bundle builder. It stays synchronous, takes its clock and its randomness injected, and imports no network module and no asyncio network API. Provider HTTP stays in `tracer-evalproviders` (httpx, ADR 0024). Async network transports live in the new `tracer-evalsim` (`tracer_evalsim`): the asyncio call runner, the wire dialects, the paced sender and the WebRTC client; it is the only importer of `websockets` and `aiortc`. `tracer-cli` adds the `tracer simulate` command. Rejected: the transports inside `tracer-evalproviders` (it mixes async sockets into the audited HTTP package); inside `tracer-evalcore` (breaks the no-network rule, ADR 0024 rule 1); threads instead of asyncio (no structured cancellation for the hang-up paths). Trade-off: a fourth runtime package to release, audit and pin. Tests: `test_evalsim_runtime_imports_whitelist`, `test_evalcore_imports_no_network_module`, `test_evalcore_imports_no_asyncio_network`, `test_evalsim_wheel_contains_no_tests`, `test_evalschema_unchanged_since_phase4_baseline`, `test_tracer_simulate_help_runs`.
3. **Bounded dependency ranges (SCOPE Decisions D3).** `websockets` (BSD-3-Clause) and `aiortc` (only in the optional `[webrtc]` extra) are declared with bounded ranges (amended 2026-10-27, lead decision E-b: `protobuf` is not a dependency; the `pipecat-protobuf/1` wire format is encoded and decoded by hand, rule 1, so no tracer package imports `google.protobuf`), each tested at its lower bound in a `lowest-direct` leg; their closures are reviewed from the licence files actually bundled in the locked wheels (P4-02), and any copyleft runtime item is a named, owner-rule exception (owner question O6 for the FFmpeg inside `av`). `pipecat-ai` is pinned exactly (`==1.14.0`) in `tools/samplebot/` only (rule 20). Rejected: exact pins in the libraries (users could not resolve them next to other packages); unbounded ranges (a major release could change cancellation or framing silently); keeping `protobuf` for the protobuf dialect (an extra supply-chain dependency and the temptation of generated code, E-b). Trade-off: the lower bounds must be re-tested when raised; the hand-written codec covers only the five frame messages of the cited `frames.proto` and must be re-checked at every pinned Pipecat version (BL-282). Tests: `test_phase4_requires_dist_bounded_ranges`, `test_license_policy_lists_phase4_closures`, `test_license_exceptions_exact`.
4. **Engine protocols and their errors (P4-03).** `TtsEngine` takes text, a voice (`provider`, `model`, `speaker`, `pace`), a sample rate and a codec, and returns PCM or G.711 bytes and one usage record; `LlmEngine` takes messages and returns one reply text and one usage record; `CallerBrain` has three implementations, scripted, LLM and replay (ADR 0028). Each has the shape of the Phase 3 `SttEngine` boundary (`tracer_evalcore.stt`): provider-neutral errors (`Tts*`, `Llm*`) that hold facts only (status, a short machine code, a request id, an index), raised outside any `except` block with no `__cause__` and no `__context__` (finding F-B2 of Phase 3), and `UsageStreaming*` variants that hand out each request's usage record before the next request is built (the R1 lesson, ADR 0024 rule 16 (d)). Rejected: one engine protocol for all three roles (their inputs differ); errors that carry the provider message (it can echo input). Trade-off: three protocol families to keep in step. Tests: `test_tts_llm_errors_hold_facts_only_and_no_chain`, `test_engines_stream_usage_before_next_request`, `test_brain_protocol_accepts_scripted_llm_replay`.
5. **Named, versioned wire dialects (Q5; F2).** A dialect is a named, versioned wire protocol, `<name>/<n>`: `pipecat-protobuf/1` (the Pipecat development runner's `/ws-client`), `twilio-media-stream/1` (a telephony media stream compatible with Twilio Media Streams, to the runner's `/ws`) and `smallwebrtc/1` (rule 7). The dialect id is recorded in `tracer.sim_profile/1`, `tracer.sim_outcome/1` and `tracer.timing/1` (ADR 0027), and every timing value is labelled with it. Each dialect has a specification in the section "Dialect specifications" that cites the public document it was written from, with its URL and retrieval date, and marks every item it could not verify as "not verified"; a dialect is implemented only from a specification whose message set is verified. Any change of a message, field or meaning is a new version (`/2`). The protobuf dialect is kept (lead decision 2026-10-27, BL-298): its frame format is documented from the public `frames.proto` at the cited tag and implemented by hand (rule 1), so the earlier fallback condition ("cannot be documented without copying Pipecat's `.proto` file") does not apply. The Q5 fallback (the protobuf dialect moves to the BACKLOG and `twilio-media-stream/1` is the only WebSocket dialect) is taken only if P4-16 cannot verify the message set at the pinned tag line by line. Rejected: declaring the dialect undocumentable (the file is public and readable). An inbound message the dialect does not know is ignored and counted (`inbound_messages_ignored` in `tracer.sim_outcome/1`), never interpreted. Rejected: one "Pipecat WebSocket" dialect (F2: there are two protocols behind two routes); the RTVI `eval-*` protocol (rule 1); every telephony serializer at once (Telnyx, Plivo, Exotel, Vonage, Genesys: scope, BL-274). Trade-off: a deployment that speaks only another serializer cannot be called until its dialect exists. Tests: `test_dialect_spec_cites_docs_with_retrieval_date`, `test_protobuf_dialect_roundtrip_in_memory`, `test_protobuf_dialect_unknown_message_ignored_and_counted`.
6. **The Twilio-compatible media stream (P4-17).** In `twilio-media-stream/1` Tracer plays the telephony side: it opens the WebSocket to the agent's `/ws`, sends the stream's opening messages (`connected`, then `start`), then caller audio as G.711 mu-law at 8,000 Hz, mono, in 20 ms frames (Tracer's own pacing choice, not a Twilio rule: Twilio's pages do not state a frame size, BL-301), and at the end `stop`. The call ends when Tracer closes the socket (amended 2026-10-27, BL-299): `stop` is sent for Twilio-compatible servers but never relied on, because the Pipecat serializer ignores an inbound `stop` and only the end of the WebSocket ends a Pipecat call. Tracer receives the agent's `media` and `clear` messages; `mark` messages are optional: accepted and counted when they arrive, never required and never waited for (the Pipecat serializer never sends one). The exact message sequence is the one the verified specification states (section "Dialect specifications"). The sample bot of `tools/samplebot` (rule 20) runs this dialect with `auto_hang_up` off and with no Twilio credentials, so it never sends a request to Twilio. Because a Pipecat bot with `auto_hang_up` on and real Twilio credentials posts `Status=completed` to Twilio's REST API for the `callSid` it was given, every allowlist entry used with a `twilio-media-stream/1` target carries the required boolean `bot_holds_telephony_credentials` (rule 16): an entry without it is refused, and a target whose entry says `true` is refused in Phase 4 unless the owner records a decision to allow it (decision log and an amendment of this rule), at step 2, before any key or socket. The stream and call identifiers Tracer sends are synthetic and marked as such: they carry the fixed prefix `tracer-sim-` and a run-local counter, never a value shaped like a real provider identifier, and they are never stored as external references (ADR 0022 Decision 11). An agent `clear` message is recorded as barge-in evidence (the agent asked the telephony side to drop its queued audio), with its arrival instant. Rejected: realistic-looking identifiers (they could be mistaken for a real call in a provider's logs or Tracer's records, and a bot with real credentials would post about them); ignoring `clear` (it is the agent's own statement that it stopped); relying on `stop` or on `mark` to end or pace the call (Pipecat ignores the one and never sends the other); dropping the dialect because of the credential risk (it loses the telephony-shaped test; the allowlist field refuses the risky target instead). Trade-off: a synthetic `tracer-sim-` callSid can still reach a bot whose operator wrote `false` wrongly (the operator's statement in the allowlist is the control); at the pinned tag the identifier shape is not validated (section "Dialect specifications"); a later version that validates it is recorded as a named spec change at P4-17. Tests: `test_twilio_dialect_message_sequence_exact`, `test_twilio_dialect_ids_are_synthetic_and_marked`, `test_twilio_dialect_agent_clear_message_is_barge_in_evidence`.
7. **WebRTC to SmallWebRTC, loopback-proven only (F9; P4-18).** The WebRTC client lives in the `[webrtc]` extra of `tracer-evalsim` (aiortc); without the extra, `--target` with a WebRTC endpoint is refused with a message that names the extra. The signalling route and request body are implemented only after P4-18 reads them in the Pipecat 1.14.0 source at the tag and records them, with the file path and the tag, in this ADR's dialect specification; if they are not stable or not readable, WebRTC moves to the BACKLOG with that evidence. No ICE server is configured by default (host candidates only); a non-loopback WebRTC target needs an explicit `--ice-server`, which is logged in the call log (no credentials in the log). In Phase 4 WebRTC is proven on loopback only. Channel 0 of the recording is the PCM handed to the encoder (WebRTC encodes it with a lossy codec on the wire). Rejected: a public STUN server by default (it discloses the host's addresses to a third party, BL-280); a signalling body guessed from the documentation page (F9: it is not there). Trade-off: no remote WebRTC call in Phase 4. Tests: `test_webrtc_no_stun_by_default`, `test_webrtc_signalling_body_matches_pinned_pipecat`, `test_webrtc_extra_absent_gives_clear_refusal`, `test_integration_webrtc_against_pipecat_loopback`.
8. **Real-time pacing and an independent watchdog (P4-20).** The sender sends caller audio in 20 ms frames at real time against the injected monotonic clock: frame k leaves no earlier than the call's send origin plus k times 20 ms, and the sender never sends ahead to catch up after a stall (it never bursts). It applies backpressure (it waits for the transport's write to complete before scheduling the next frame). A wall-clock watchdog, independent of the state machine and of the sender, hangs up when the call's maximum duration (rule 15) plus a fixed grace of one second has elapsed, whatever state the machine is in. Rejected: sending a whole line at once (an agent that buffers would hear it early, and the gap measurement would start at the wrong edge); a watchdog driven by the state machine (a stalled machine would never fire it). Trade-off: a slow host can make frames late; lateness is visible in the frame log, never hidden by a burst. Tests: `test_sender_paces_real_time_with_injected_clock`, `test_watchdog_hangs_up_even_if_state_machine_stalls`.
9. **The call state machine (P4-04).** A pure, table-driven machine in `tracer-evalcore` with exactly the states `preflight`, `connecting`, `connected`, `caller_speaking`, `awaiting_agent`, `agent_speaking`, `ending` and `ended`, and exactly the end reasons `script_complete`, `caller_end_call`, `agent_hangup`, `max_duration`, `max_turns`, `max_silence`, `kill_switch`, `setup_failed`, `transport_error`, `brain_invalid_output` and `spend_cap`. Every call ends in `ended` with exactly one end reason, recorded in `tracer.sim_outcome/1` (ADR 0027). Four properties hold for every transition table the implementation pins: no state is entered after `ended` and no event after `ended` changes anything; the kill switch reaches `ended` from every state; a failure to establish the call (refused connection, timeout, handshake error) is the end reason `setup_failed`, never an exception out of the runner; and the call's maximum duration is the smaller of `Evaluator.max_duration_ms` and `--max-call-seconds` times 1,000. The exact events, guards and transitions are pinned by the batch A contract and its table test. Rejected: an implicit machine spread over callbacks (the hang-up paths could not be enumerated); exceptions for setup failure (a failed call is an outcome to record, not a crash). Trade-off: every new event needs a table row and a test. Tests: `test_state_machine_transition_table_exact`, `test_max_duration_is_min_of_evaluator_and_cap`, `test_kill_switch_reaches_ended_from_every_state`, `test_no_event_after_ended`, `test_setup_failure_is_an_end_reason_not_an_exception`.
10. **Turn-taking: wait for silence, an optional scripted barge-in (Q6; P4-05).** Agent activity is a received frame holding any non-zero sample: no energy threshold and no voice-activity model runs in Tracer. The agent is silent once no active frame has arrived for `wait_for_agent_silence_ms`. `max_silence_ms` is the wait budget (amended 2026-10-27, lead decision on the batch A reading 1; the earlier text, "once no active frame has arrived for `max_silence_ms`", could never end a comfort-noise call): the call ends with `max_silence` once the simulator has waited `max_silence_ms` since its wait for the agent began without being able to take its turn, whether the agent stayed silent or kept sending active frames. So an agent reply that starts later than `max_silence_ms` after the wait began, or a pause-free reply that is still running at that point, ends the call with `max_silence` (an owner consequence for the O4 values). Both are required values of `tracer.sim_profile/1` with no default in code (the shipped example profile is labelled as an example, and its values are owner values, O4); `caller_speaks_first` is required too. A scripted turn may carry `barge_in_after_ms`: the caller starts that line that many milliseconds after the onset of agent activity instead of waiting for silence. The simulator never sends caller audio while the brain is still producing the next line. An agent that streams comfort noise never looks silent, so such a call ends on `max_silence` (or `max_duration`) with its timing values without a second edge (ADR 0027), named in the outcome, never a hang. Rejected: a Silero VAD inside Tracer (it runs a model; owner rule); an energy threshold (a number nobody measured). Trade-off: comfort-noise agents cannot be driven turn by turn in Phase 4. Tests: `test_agent_activity_is_any_nonzero_sample_no_threshold`, `test_wait_for_silence_parameter_has_no_default`, `test_barge_in_fires_at_offset_from_agent_onset`, `test_comfort_noise_agent_never_goes_silent_is_max_silence_not_a_hang`, `test_simulator_never_speaks_while_brain_pending`.
11. **Persona to voice: an explicit table (Q7).** The sim profile file maps each persona (by its id) to a voice `{provider, model, speaker, pace, sample_rate_hz, codec, language_code}`; the run uses the entry of its snapshot's persona, and a persona without an entry is refused before any key is read. There is no automatic mapping, no default voice, and an accent is never inferred from a voice name; indic-linguistics checks only that the language codes match (P4-00f records the Sarvam voices for `mr-IN` as observed facts, never as accent claims). Cloned or custom voices are refused in Phase 4; if they are ever allowed, their payloads carry the marker reason `real_person_likeness` (ADR 0016 Decision 5; BL-277). Rejected: choosing a voice from the persona's accent label (an accent claim nobody verified); a default speaker (a voice nobody chose). Trade-off: every persona needs a hand-written voice entry. Tests: `test_sarvam_tts_sends_explicit_model_speaker_language_rate`, `test_tts_cache_key_covers_every_parameter`, `test_adr0027_documents_match_json_schemas`.
12. **Models are explicit; a seed is never a claim (Q10).** The caller model (`--caller-model`, recorded in `tracer.sim_profile/1`), the TTS `model` and `speaker` and the STT model have no default in code: each is required for a real engine and recorded as requested. The LLM `seed` is sent and recorded, and every output says that replies may differ between requests (the provider documents that output is not guaranteed identical even at seed 0, F8). Rejected: provider defaults (a run could not be attributed or priced); claiming repeatability from a seed. Trade-off: the user must name every model. Tests: `test_sarvam_llm_model_and_max_tokens_required`, `test_sarvam_llm_seed_recorded_never_claimed_deterministic`, `test_sarvam_tts_sends_explicit_model_speaker_language_rate`.
13. **Reproducibility (Q11).** Scripted mode plus the content-addressed TTS cache (ADR 0024 amendment A9) gives byte-identical caller audio on a re-run, with zero TTS requests and zero LLM requests. An LLM-mode run stores everything needed to replay it: the caller lines (the `script` transcript, ADR 0027) and the agent text the brain was given (the agent-channel `our_stt` turns), and the prompt template id and hash (ADR 0028); `--caller fake:<dir>` replays caller lines without a request. Nothing is claimed about the agent side: the same caller audio may meet a different agent reply. Rejected: claiming that an LLM run can be repeated (only replayed). Trade-off: an LLM run is replayable, not repeatable. Tests: `test_tts_cache_hit_sends_nothing_and_records_no_usage`, `test_scripted_mode_makes_no_llm_request`, `test_recorder_is_deterministic_from_frame_log`, `test_e2e_sim_synthetic_mr_exact_outputs`.
14. **The order of operations (Q15; P4-21).** `tracer simulate` runs exactly these steps in this order, pinned by a call-trace test: (1) parse and validate every input (the agent file, the evaluator, the persona, the profile, the sim profile, every cap, the authorisation reference); (2) the target allowlist (rule 16), the minimum interval and the kill-switch file (rules 17 and 18); (3) the authorisation and terms gates (rule 21); (4) the required spend caps are present for every real engine (rule 15); (5) the output probe, which creates nothing; (6) the engine factories read the keys and open the call log; (7) every scripted turn is synthesised in advance, with each answered request's usage handed out before the next request (recovery as ADR 0024 rule 16 (d)); (8) the store is opened; (9) connect (or dial, ADR 0029); (10) the call loop; (11) hang up; (12) the speech-to-text of the agent channel that the call loop did not already transcribe (ADR 0024 amendment A5); (13) scoring; (14) the store write; (15) the report. A refusal at steps 1 to 6 sends nothing, opens no socket and is exit 4 (64 for a usage error); a missing key at step 6 leaves no directory behind. A `BaseException` anywhere after step 6 keeps the usage of every answered request in `usage-recovery-<UTC>.json` (ADR 0024 rule 16 (d)) and is raised again. Rejected: opening the store before the engine factories (a missing key would leave a directory, ADR 0024 Ambiguity 8); synthesising each line during the call in scripted mode (TTS latency would become dead air and the call would depend on a provider mid-call); connecting before the store is open (a store failure after a paid call would lose the run). Trade-off: pre-synthesis spends TTS before the call is known to connect; the cache makes a retry free. Tests: `test_order_of_operations_pinned_by_call_trace`, `test_refusals_happen_before_any_key_read_or_connect`, `test_usage_survives_ctrl_c_mid_call`, `test_replay_brain_missing_file_is_a_refusal_before_connect`.
15. **Required caps; no default (Q17; P4-23).** `--max-call-seconds`, `--max-tts-chars`, `--max-llm-tokens` and `--max-stt-seconds` are required whenever the engine they bound is real (`sarvam`), with no default; with `fake:` engines they may be absent. Before each request the adapter checks the cap against what was already used: TTS characters and STT seconds are known exactly before the send, so a request that would cross its cap is not sent; the LLM cap counts the tokens the provider reports, and a request is sent only while the reported total plus that request's `max_tokens` stays within the cap, so the prompt tokens of one request may cross it (stated in the outcome, BL-295). A cap reached during the call ends it with `spend_cap` and records which cap; a cap reached during pre-synthesis is a refusal before connect. The call's length is bounded by the smaller of `Evaluator.max_duration_ms` and the call cap (rule 9). `--dry-run` reads the inputs and prints the plan (scripted lines, characters to synthesise, cache hits, planned requests per engine, each cap line) and reads no key, creates nothing and opens no socket. Rejected: default caps (a number that decides spend, nobody chose); a token estimate before the send (no tokenizer for the provider's models; an invented number). Trade-off: the user must state four caps for a real run; the LLM cap can be crossed by one request's prompt. Tests: `test_simulate_requires_caps_for_real_engines`, `test_max_duration_is_min_of_evaluator_and_cap`, `test_simulate_dry_run_prints_plan_and_sends_nothing`.
16. **The target allowlist (P4-31).** `--allowlist <file>` is required for every non-dry run. The file is git-ignored, must be a regular file with no group or other permission bit (mode 0600 or stricter) and is not followed through a symbolic link; one entry per line, `#` starts a comment, blank lines are ignored. An entry is a `ws://`, `wss://`, `http://` or `https://` URL (the last two for WebRTC signalling) or an E.164 number (ADR 0029), optionally followed by fields written `name=value` and separated by spaces (amended 2026-10-27, BL-299, BL-300): `bot_holds_telephony_credentials=true|false` (required for an entry used with a `twilio-media-stream/1` target, rule 6); `auth_token_env=<NAME>` (the name of an environment variable, `[A-Z_][A-Z0-9_]{0,63}`); `origin=<scheme://host[:port]>`. An unknown field, a repeated field or a malformed value refuses the file. Authentication: when `auth_token_env` is set, the token is read from that variable at step 6 with the other keys and sent only as an `Authorization: Bearer` header of the WebSocket handshake or the signalling request; it is never put in the path or a query, never logged, stored, printed or reported, and a missing or empty variable refuses the run before any socket. Only the variable name is recorded. The `Origin` header sent is the entry's `origin` field; without that field no `Origin` header is sent. The variable name (or none) and the origin (or none) are recorded as labels in `tracer.sim_profile/1` (ADR 0027). Tracer never writes a token into a path; a runner that expects a path token (`/ws/{token}`, `/ws-client/{token}`) or a `?token=` query is called only through the header form. Target and entry are compared exactly after one normalisation: the scheme and the host in lower case, the default port written out (80 or 443), the path kept byte for byte (no percent-decoding, an empty path written `/`); a URL with user information, a query or a fragment, or a host outside ASCII, is refused as an entry and as a target (BL-294). A target that is not on the list is refused (exit 4) at step 2, before any key is read and before any socket is opened; a loopback target needs an entry too. The simulator is the project's first dialer, so the controls of BACKLOG BL-142 apply, with the allowlist as the operator's explicit statement: plain `ws://` and `http://` are allowed only for a loopback target (`localhost`, `127.0.0.1` or `::1` written in the entry), every other target needs `wss://` or `https://` with TLS verified; a redirect in the WebSocket handshake or the WebRTC signalling is never followed (it ends the call with `setup_failed`); a host name is resolved once per call and every address of the answer is checked before the connection: a private, loopback, link-local or unspecified address is reachable only through an entry that names that literal address or `localhost`, so a public name that resolves to a private address (DNS rebinding) is refused, and `localhost` must resolve to loopback addresses only. The target is never derived from any text the brain or the agent produced (ADR 0028). The CLI never prints the target number or a key. Rejected: no allowlist for loopback (a typo would reach another host); BL-142's blanket deny of private and loopback destinations (the loopback sample agents of P4-27 and an agent on the operator's own network could not be called; the literal entry is the narrower exception); prefix or wildcard matching (an attacker-controlled path or subdomain could match); a query string in the target (it often carries a token, which would then sit in the allowlist and the snapshot); for the runner's optional token: the `?token=` query (it leaks into logs and the allowlist file) and a token in the path (it sits in the allowlist file and the snapshot) (BL-300). Trade-off: every target, loopback included, must be written into the file once, and an agent on a private network needs TLS; a runner whose token is accepted only in the path or the query cannot be called. Tests: `test_target_not_on_allowlist_refused_before_any_key_or_socket`, `test_allowlist_mode_and_link_rules`, `test_simulate_never_prints_target_number_or_key`, `test_guard_rejects_staged_sim_outputs_and_allowlist`.
17. **Kill switch, signals and the watchdog (Q17).** A kill-switch file in `--out` (its name a constant of `tracer-evalsim`) is checked before connect (present: refused, exit 4) and before every frame sent during the call (present: hang up within one frame, end reason `kill_switch`). The first SIGINT or SIGTERM hangs up gracefully (end reason `kill_switch`) and the run is stored with what was recorded; a second signal aborts at once, and the usage is still kept (rule 14). The watchdog of rule 8 is the last line. A partial recording and the usage of a killed call are kept, never discarded. Rejected: a kill switch checked once per turn (a long line would keep talking); discarding a killed call (it happened and may have cost money). Trade-off: a file check per frame (50 per second). Tests: `test_kill_switch_file_hangs_up_within_one_frame`, `test_kill_switch_reaches_ended_from_every_state`, `test_tdeg_sim_kill_switch_keeps_partial_recording_and_usage`, `test_watchdog_hangs_up_even_if_state_machine_stalls`.
18. **Rate limits (Q18).** One call per invocation and concurrency 1; no suite or batch mode in Phase 4 (BL-276). A minimum interval between calls is enforced with a lock file in `--out` that records the monotonic and UTC instants of the last connect; a call earlier than `limits.min_call_interval_ms` of the sim profile after the last one is refused at step 2 (exit 4). The interval is an owner value (O4) with no default in code. Rejected: no interval (a loop in a shell script becomes an automated dialler, terms 10.3(6)); a global lock outside `--out` (Tracer writes nothing outside the user's output directory). Trade-off: two invocations with different `--out` directories are not rate-limited against each other; the run book says to use one output directory per agent under test. Tests: `test_one_call_per_invocation_and_min_interval`.
19. **Exit codes (Q16).** The Phase 3 codes keep their meaning: 0 the call was established, the run stored and every result scored or not applicable; 1 an unexpected failure (usage kept, rule 14); 2 a result was not scored (`status=error`); 3 the speech-to-text of the agent channel failed (no `our_stt` transcript, ADR 0004 Decision 10a); 4 an input or a target refused before any request; 64 a usage error. New: 5, the call was not established (`setup_failed`): the run is still stored, every result is `not_applicable` with its missing inputs, and the report says so. When several apply, the highest-precedence code wins in the order 1, 5, 3, 2, 0. Rejected: reusing exit 3 for a failed call (it means STT failed); not storing a failed call (the attempt and its spend happened). Trade-off: a seventh exit code to document. Tests: `test_simulate_exit_codes`, `test_tdeg_sim_setup_failed_all_not_applicable_exit_5`, `test_setup_failure_is_an_end_reason_not_an_exception`.
20. **`tools/samplebot`, an isolated tool project (P4-26).** The Pipecat sample agents used for loopback interop and for the owner-gated runs live in `tools/samplebot/`, a uv project with its own lock that is not a workspace member, is not in the root `uv.lock` and is never imported by a tracer package (the precedent is `tools/capture`). `scripted_bot` is a Pipecat 1.14.0 pipeline with no model: a timer-based end-of-caller detector and pre-recorded replies with known delays, for `/ws-client`, `/ws` (Twilio) and SmallWebRTC; `llm_bot` follows owner answer O3 and is owner-gated to run. Its closure (`num2words`, `soundfile`, `onnxruntime`, `numba`, `sentencex`, `loudness`) is reviewed as tool-only (P4-02). Rejected: sample agents inside a tracer package (their closure would enter a wheel); a sample agent that runs a model for the interop tests (non-deterministic replies, model downloads in CI). Trade-off: a second lock to keep current. Tests: `test_samplebot_not_a_workspace_member_and_not_in_uv_lock`, `test_samplebot_scripted_bot_uses_no_model`, `test_samplebot_closure_reviewed_and_tool_only`.
21. **Terms of service and authorisation (F4).** No code decides the Sarvam terms: before the first real call with Sarvam TTS or LLM the owner answers O1 (10.5(a)) and the answer is logged, and the run book checks it. What code does: every non-dry run requires `--authorisation-reference TEXT` (1 to 200 characters, no edge white space, no character of category Cc, Cf, Cs, Co, Cn, Zl or Zp), the human authorisation that 10.3(6) asks for; its SHA-256 (lower-case hex) is stored in `tracer.sim_outcome/1` and its text is never stored, printed, logged or reported (the text stays with the operator's record, which the hash identifies). The report labels the caller channel "synthetic caller audio" (10.2(8)). Robocalling (10.2(5)) applies to PSTN dial-out and is ADR 0029's. Rejected: a code check of the terms (the code cannot know what Sarvam permitted); storing the authorisation text (free text in a machine record, possibly a name or a number). Trade-off: a reader of a run sees that an authorisation was given and can match it to a record, not read it. Tests: `test_sim_report_labels_synthetic_audio`, `test_refusals_happen_before_any_key_read_or_connect`, `test_order_of_operations_pinned_by_call_trace`.
22. **A hostile agent cannot exhaust the simulator.** Every inbound message has a size cap and every call a cap on inbound frames per second; both are named constants of `tracer-evalsim`, fixed by P4-16 and P4-17 from the dialect's frame size and stated in its CHANGELOG (technical bounds, not measured values). A message over its cap ends the call with `transport_error`; unknown messages are ignored and counted (rule 5); agent text never reaches a file name, a log line or a dial action (ADR 0028), and is shown escaped in the report (ADR 0017). Rejected: unbounded buffers (a frame flood fills memory); trusting the agent's frame sizes. Trade-off: an agent that sends unusually large frames is cut off and must be called through a dialect version that allows them. Tests: `test_protobuf_dialect_unknown_message_ignored_and_counted`, `test_adversarial_agent_text_never_breaks_report_or_store`, `test_p4_audit_items_cite_tests`.
23. **Tests open no socket; integration is loopback only (P4-19, P4-27, P4-30).** Unit tests use injected fakes and in-memory transport pairs and never open a socket (the no-network guard of ADR 0024 rule 17 is extended to `tracer-evalsim`). Tests marked `integration` connect to `127.0.0.1`, `::1` or `localhost` only, run in a separate CI job against `tools/samplebot`, and never use a key. Deterministic fake agents (pure Python, `tests/support`) exist for each dialect with injected reply delays, silence, comfort noise, hang-up, garbage frames and bursts. A real call is an owner-gated step, never a test. Amended 2026-10-27 (batch D, named spec change S-D1, auto-approved): tests in `packages/evalsim/tests` that carry the `loopback` marker run in the default suite (not deselected) under an adversarial loopback-only guard: a connection only to `localhost` or a literal loopback address (the real resolver is never called for any other name), a bind only to a loopback address, no UDP and no Unix socket; a violation is an `AssertionError`. Every unmarked test keeps the full no-network guard, loopback included. A test confines the marker to the evalsim test modules declared for it. Rejected: recorded network cassettes (a missing one would reach the network); deselecting the `loopback` tests by default like the `postgres` tests (the dialect tests would then run only in a separate leg); reusing the `integration` marker (that category runs against `tools/samplebot` in its own job); in-memory transports only (the websockets client and server code paths, redirects, proxies and compression, would go untested); mocking websockets (the observed library behaviour is what the tests pin). Trade-off: real-agent drift is seen only in owner-gated runs; a `loopback`-marked test can reach any listener on the loopback interface, and the guard patches the socket paths it names, not every possible one (BL-289, BL-290). Tests: `test_unit_tests_open_no_socket`, `test_integration_tests_loopback_only`, `test_fake_agents_are_deterministic`, `test_integration_protobuf_dialect_against_pipecat`, `test_integration_twilio_dialect_against_pipecat`.
24. **What Phase 4 measures and never claims (Q21, Q22).** Phase 4 reports: whether the call was established; the first agent audio, the per-turn gaps and their median with N, the overlap, the barge-in stop time, the answered caller turns (ADR 0027), each "observed at the simulator over <dialect>"; the simulator's own reply time, separately; and agreement with the agent export when one is supplied (ADR 0023). It never claims accuracy, an error rate, recall or precision, agent quality or task success, the agent's internal latency, persona realism or accent fidelity, determinism of the caller or of the agent, a comparison between agents or dialects, or an aggregate across runs beyond the descriptive counts of the measurement report; the claim words are checked as ADR 0023 amendment A1 states. Calibration numbers of P4-27 go to the measurement report, never into a claim. Rejected: the plan's "WER against scripted turns" (the owner rule wins, BL-284). Trade-off: the outputs are deliberately plain. Tests: `test_simulate_output_never_claims_accuracy_or_quality`, `test_sim_report_never_claims_accuracy_or_quality`, `test_sim_concept_page_states_no_claims`, `test_integration_calibration_gap_within_quantum`.

### `pipecat-protobuf/1`
- Sources, all read at tag `v1.14.0` of `pipecat-ai/pipecat` and retrieved 2026-10-27 (BL-291): `https://raw.githubusercontent.com/pipecat-ai/pipecat/v1.14.0/src/pipecat/frames/frames.proto` (note: the path is `src/pipecat/frames/frames.proto`; `src/pipecat/frames/protobufs/` holds the generated module, and the `protobufs/frames.proto` path returns HTTP 404), `https://raw.githubusercontent.com/pipecat-ai/pipecat/v1.14.0/src/pipecat/serializers/protobuf.py`, `https://raw.githubusercontent.com/pipecat-ai/pipecat/v1.14.0/src/pipecat/runner/run.py`, `https://raw.githubusercontent.com/pipecat-ai/pipecat/v1.14.0/src/pipecat/transports/websocket/fastapi.py`. Each file carries the header `Copyright (c) 2024-2026, Daily` and `SPDX-License-Identifier: BSD 2-Clause License`. The fetch tool summarised the larger files with a small model; only `frames.proto` was returned as the full text, so the other items below are from summaries of the quoted code and the line-level wording is not re-checked.
- Route: `/ws-client` (and `/ws-client/{token}`), a WebSocket route of the development runner (`run.py`). On connect it checks, when `--ws-auth token` is set, a single-use token taken from the path, the `Authorization: Bearer` header or the `?token=` query parameter, and checks the `Origin` header against `--allowed-origins`; a failure closes the socket with code 4003. It then accepts the connection and calls the bot's `bot(runner_args)` with `transport_type="websocket"`. The runner sets no serializer, sample rate, VAD or RTVI option: the bot code does. So `ProtobufFrameSerializer` on `/ws-client` is the convention of the Pipecat samples, not something the runner enforces; which serializer a deployed agent uses behind that route is not verified (the adapters phase). `POST /start` with `transport: websocket` returns `wsUrl` (`.../ws-client`), `sessionId`, an optional `token`.
- Wire framing: the serializer returns `bytes` from `serialize()` and `FastAPIWebsocketClient.send` calls `send_bytes` for bytes, so one binary WebSocket message is exactly one serialised `pipecat.Frame`. The receiving side reads whichever of binary or text arrives and passes it to `deserialize(str | bytes)`; no length prefix, no extra envelope.
- Frame message set (proto3, `package pipecat;`, verbatim names, types and field numbers from `frames.proto`): `TextFrame { uint64 id = 1; string name = 2; string text = 3; }`; `AudioRawFrame { uint64 id = 1; string name = 2; bytes audio = 3; uint32 sample_rate = 4; uint32 num_channels = 5; optional uint64 pts = 6; }`; `TranscriptionFrame { uint64 id = 1; string name = 2; string text = 3; string user_id = 4; string timestamp = 5; }`; `MessageFrame { string data = 1; }`; `InterruptionFrame { uint64 id = 1; string name = 2; }`; and the top-level `Frame { oneof frame { TextFrame text = 1; AudioRawFrame audio = 2; TranscriptionFrame transcription = 3; MessageFrame message = 4; InterruptionFrame interruption = 5; } }`. The file has five payload messages, one more than the candidate shape (`InterruptionFrame`).
- Serializer behaviour at the tag: serialisable frames are text, output audio, transcription, message and interruption; deserialisable are text, input audio, transcription, message and interruption (audio is one-directional in each sense: the bot serialises output audio and deserialises input audio, which is what a client sends). `MessageFrame.data` holds a JSON string (the bot wraps its transport messages with `json.dumps` and parses incoming ones with `json.loads`, so the RTVI messages travel in this frame). A `Frame` whose oneof is unset or not deserialisable is logged and dropped (returns `None`), which is the behaviour rule 5 mirrors with its ignored-and-counted rule. `id`, `name` and `pts` travel as fields and are restored when non-empty.
- Q5 fallback input: the `.proto` is public source under BSD-2-Clause, and the field names and numbers above are interface facts recorded by this ADR without copying the file; whether that satisfies the clean-room wording of rule 1 and the Q5 fallback condition is decided at P4-16 (see BL-298). Decided earlier, 2026-10-27 (lead, BL-298): it does; the format is hand-written from the proto (rules 1 and 5).
- Audio: the proto carries `sample_rate` and `num_channels` per frame and does not state a sample format; that the `audio` bytes are 16-bit little-endian PCM is not verified here (the frame classes and the transport's output path were not read). Tracer's rule: PCM, mono, at the sim profile's rate; an agent frame at another rate or channel count is refused (the recorder never resamples, ADR 0027). ### `twilio-media-stream/1`
- Sources, retrieved 2026-10-27 (BL-291): Twilio, `https://www.twilio.com/docs/voice/media-streams/websocket-messages` and the overview `https://www.twilio.com/docs/voice/media-streams` (both read through the fetch tool's summarising model, so field tables are verified at the level of that summary, not character by character); Pipecat at tag `v1.14.0`: `https://raw.githubusercontent.com/pipecat-ai/pipecat/v1.14.0/src/pipecat/serializers/twilio.py`, `https://raw.githubusercontent.com/pipecat-ai/pipecat/v1.14.0/src/pipecat/runner/utils.py`, `https://raw.githubusercontent.com/pipecat-ai/pipecat/v1.14.0/src/pipecat/runner/run.py`.
- Messages from Twilio to the server (what Tracer sends as the telephony side), all JSON text messages. `connected` (sent once, first): `event` ("connected"), `protocol` (string, example "Call"), `version` (string, semantic version, example "1.0.0"); no `streamSid` and no `sequenceNumber`. `start` (sent once, right after `connected`): `event` ("start"), `sequenceNumber` (string, starts at "1"), `streamSid` (string), and `start` {`accountSid`, `streamSid`, `callSid` (strings), `tracks` (array of strings, `inbound` and/or `outbound`), `mediaFormat` {`encoding` "audio/x-mulaw", `sampleRate` 8000 (number), `channels` 1 (number)}, `customParameters` (object of string pairs)}. `media`: `event`, `sequenceNumber` (string), `streamSid`, and `media` {`track` ("inbound" or "outbound"), `chunk` (string, starts at "1"), `timestamp` (string, milliseconds from stream start), `payload` (string, base64 of raw mu-law 8,000 Hz audio, no file header)}. `stop`: `event`, `sequenceNumber`, `streamSid`, `stop` {`accountSid`, `callSid`}. `mark` (bidirectional streams only; Twilio echoes a mark the server sent, when the media before it has played, or at once if nothing is queued, and after a `clear` for each outstanding mark): `event`, `streamSid`, `sequenceNumber`, `mark` {`name`}. `dtmf` (bidirectional only): `event`, `streamSid`, `sequenceNumber`, `dtmf` {`track` "inbound", `digit`}. The page shows `sequenceNumber`, `chunk` and `timestamp` as quoted strings in its examples and does not define their type in prose.
- Messages from the server to Twilio (what the agent sends; accepted only on bidirectional `<Connect><Stream>` streams): `media` {`event`, `streamSid`, `media` {`payload` (base64, `audio/x-mulaw`, 8,000 Hz, no header)}} with no `sequenceNumber`, `track`, `chunk` or `timestamp`; `mark` {`event`, `streamSid`, `mark` {`name`}}; `clear` {`event`, `streamSid`}, which empties Twilio's buffered audio. Outbound audio is buffered and played in order and "can be of any size".
- Track values: `inbound` and `outbound` are the only values; on a bidirectional stream only the `inbound` track is received ("you can only receive the inbound track"); the overview says a call can have one bidirectional stream at a time and each stream maps to one WebSocket. Sending DTMF from the server to Twilio is not supported. Stream stop on a bidirectional stream: the call ends or the server closes the connection.
- What the Pipecat runner expects at `/ws` (`run.py`, `utils.py`, `twilio.py` at `v1.14.0`): `/ws` (and `/ws/{token}`) applies the same token and Origin checks as `/ws-client` (close code 4003), accepts the socket and hands it to the bot without parsing; the bot calls `parse_telephony_websocket`, which reads up to two text messages (`iter_text`): the first is required (empty stream raises `ValueError`; invalid JSON is treated as `{}`), the second is optional. A message is Twilio's when `event == "start"` and `start` holds `streamSid` and `callSid`; it extracts `stream_id` from `streamSid`, `call_id` from `callSid` and `body` from `start.customParameters` (the keys `from_number` and `to_number` there are promoted to `from` and `to`). Tracer therefore sends `connected` first and `start` second, as text messages. Providers detected by that function are Twilio, Telnyx, Plivo and Exotel (Telnyx needs a top-level `stream_id` and `start.call_control_id`; Plivo needs `start.streamId` and `start.callId`; Exotel needs `event == "start"` and `start.stream_sid`, `call_sid`, `account_sid`); an `eval-connect` first message is routed to the evals transport. A first or second message that matches none gives the type `unknown` and the bot fails with an unsupported-provider error.
- What `TwilioFrameSerializer` does with the stream: inbound it handles only `media` (reads `media.payload`, base64-decodes, converts mu-law at `twilio_sample_rate`, default 8,000, to PCM at the pipeline rate; an empty payload returns nothing) and `dtmf` (`dtmf.digit`); `start` and `stop` and every other event return nothing and are ignored (so `stop` does not end the call at the serializer; the end of the WebSocket does). Outbound it writes `{"event":"media","streamSid":<constructor stream_sid>,"media":{"payload":<base64 mu-law 8,000 Hz>}}` and, for an interruption, `{"event":"clear","streamSid":<constructor stream_sid>}`; it never writes `mark`. Inbound `streamSid` values are never compared with the constructor's. The SID values are not validated for shape or prefix. With `auto_hang_up` on (the default) the serializer requires `call_sid`, `account_sid` and a credential at construction and, on the first end or cancel frame, sends a POST to `https://api.twilio.com/2010-04-01/Accounts/{account_sid}/Calls/{call_sid}.json` with form `Status=completed` (a 404 with error code 20404 is logged at debug level; other failures are logged, not raised).
- Audio: G.711 mu-law, 8,000 Hz, mono, base64 in the JSON `payload`; decoded by the pure ITU G.711 table of the recorder (ADR 0027). The size of a Twilio `media` payload is not stated on the two Twilio pages (the page says only that outbound audio can be of any size), so "20 ms (160 bytes) per `media` message" is not verified from a source; it is Tracer's own chosen sending chunk (rule 6), and the 160-byte value is what 20 ms of 8,000 Hz one-byte samples makes.

### `smallwebrtc/1`
- Sources: Pipecat documentation, small-webrtc page, retrieved 2026-10-27 by the staff-reviewer (SCOPE F9): it names `SmallWebRTCTransport` and `SmallWebRTCConnection` but no signalling route or body. The route and bodies are now read in the source at tag `v1.14.0`, retrieved 2026-10-27 (BL-291): `https://raw.githubusercontent.com/pipecat-ai/pipecat/v1.14.0/src/pipecat/runner/run.py`, `https://raw.githubusercontent.com/pipecat-ai/pipecat/v1.14.0/src/pipecat/transports/smallwebrtc/request_handler.py`, `https://raw.githubusercontent.com/pipecat-ai/pipecat/v1.14.0/src/pipecat/transports/smallwebrtc/connection.py` (directory listing `https://github.com/pipecat-ai/pipecat/tree/v1.14.0/src/pipecat/transports/smallwebrtc`: `connection.py`, `request_handler.py`, `transport.py`). These were read through the fetch tool's summarising model; the dataclass tables below are from its summary of the code.
- Offer and answer: `POST /api/offer` (the runner mounts it when the WebRTC routes are enabled), JSON body `SmallWebRTCRequest`: `sdp` (string, required), `type` (string, required, "offer"), `pc_id` (string or null, default null; identifies an existing peer connection), `restart_pc` (boolean or null, default null), `request_data` (any, optional; `requestData` is accepted as an alias); an optional `session_id` query parameter. The reply is the dict from `SmallWebRTCConnection.get_answer()`: `{"sdp": <answer SDP>, "type": <answer type>, "pc_id": <connection id>}`. With no `pc_id`, or an unknown one, the handler creates a new connection and starts the bot; with a known `pc_id` it renegotiates, and `restart_pc: true` closes the old peer connection and initialises a new one first (the field is read only on the renegotiation path). In single-connection mode a wrong or missing `pc_id` is HTTP 400. Under the Pipecat-Cloud-style proxy the same bodies go to `/sessions/{session_id}/api/offer`.
- ICE: the answer is created without candidates ("this answer does not contain the ice candidates, which will be gathered later"), and remote candidates arrive through `PATCH /api/offer` with `SmallWebRTCPatchRequest`: `pc_id` (string) and `candidates` (list of `IceCandidate`: `candidate` (string), `sdp_mid` (string), `sdp_mline_index` (integer)); an empty `candidate` string is the end-of-candidates marker; an unknown `pc_id` is HTTP 404 ("Peer connection not found"); success is `{"status": "success"}`. So the trickle PATCH route is present at the tag. Whether a client whose offer already holds all its candidates (as aiortc produces after gathering) needs the PATCH is not verified.
- Session: `POST /start` with `transport: webrtc` returns `sessionId`, an optional `fileUploadUrl` and `iceConfig` (only when the runner has ICE servers or `enableDefaultIceServers` is true); the bot starts when the offer arrives. `GET /client/` is the prebuilt web UI mount, not a WebRTC signalling route (the ADR Context line that calls `/client` "WebRTC" means the UI).
- Data channel: the server does not create a data channel; it handles the one the remote peer creates, queues up to 50 messages for up to 10 seconds until it opens, and asks the client to renegotiate with a `renegotiate` signalling message over that channel. Whether a call needs the client's data channel to carry audio is not verified.
- Media: the codec, the sample rate and the RTP payload type are not stated in the files read (not verified). The recorder takes the decoded PCM at the rate aiortc delivers, which the sim profile must state and the TTS must be asked for (no resampling).

For the lead (SCOPE D1 auto-approval covers the Q items; these are readings the SCOPE leaves open).
- **Ambiguity 1. Where the minimum interval lives.** Q18 and O4 name a minimum interval but the CLI of P4-23 has no option for it. **Recommendation:** `limits.min_call_interval_ms` in `tracer.sim_profile/1`, required, no default (rule 18). Rejected: a new CLI option (the P4-23 option list is pinned by its tests); the allowlist file (it lists targets, not policy).
- **Ambiguity 2. Who speaks first.** The SCOPE does not say. **Recommendation:** `turn_taking.caller_speaks_first`, a required boolean of the sim profile (rule 10). Rejected: always waiting for an agent greeting (an agent that waits for the caller would end every call on `max_silence`).
- **Ambiguity 3. What `--authorisation-reference` stores.** P4-21 step 3 and P4-23 name the option, not its record. **Recommendation:** the SHA-256 in `tracer.sim_outcome/1`, never the text (rule 21). Rejected: the text in `Run.metadata` (free text in a record that holds machine keys only, ADR 0027).
- **Ambiguity 4. Exit precedence.** The SCOPE adds exit 5 without an order. **Recommendation:** 1, 5, 3, 2, 0 (rule 19): an unexpected failure first, then the absence of a call, then a missing transcript, then an unscored result.
- **Ambiguity 5. URL queries in targets.** `AgentTarget` endpoints may hold a query (ADR 0012). **Recommendation:** refused for simulated calls in Phase 4 (rule 16; BL-294).

## Consequences
- Tracer owns its wire code. Every Pipecat release that the project pins needs the dialect specifications re-verified and the loopback interop tests re-run (BL-282).
- A real simulated call needs: an allowlist entry, an authorisation reference, four caps for real engines, an owner-valued sim profile (silence values, minimum interval) and, for Sarvam TTS or LLM, the owner's O1 answer. The dry run shows the plan first.
- BL-291 is partially closed (2026-10-27): the message sets of `pipecat-protobuf/1`, `twilio-media-stream/1` and the `smallwebrtc/1` signalling are recorded above from the cited sources; the items still marked "not verified" there (the proto audio sample format, the Twilio payload frame size, the WebRTC codec and data-channel need, the serializer a deployed agent uses) are checked at P4-16 to P4-18. The four contradictions the fetch found were decided by the lead on 2026-10-27 (BL-298 to BL-301): the protobuf dialect is kept and hand-written from the public proto (the Q5 fallback only if P4-16 cannot verify the message set line by line), the Twilio-compatible call ends by closing the socket, a runner token travels only as a bearer header from a named variable, and the Context facts are corrected.
- A Twilio-compatible target whose bot holds real telephony credentials is refused in Phase 4 (rule 6); the sample bot runs without them.
- Timing values are labelled per dialect and never compared across dialects.
