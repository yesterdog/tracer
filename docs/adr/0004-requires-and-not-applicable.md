## Context
Core rule: consume telemetry if present, never break if absent. Agents expose different capability tiers (T0 black-box, T1 telemetry, T2 observer). The same evaluator must produce the same schema at every tier. A metric whose inputs are missing must say so explicitly. Reporting it as 0, false or failed would make a missing tool-call span indistinguishable from a wrong tool call, and the verdict would lie.

## Decision
1. **`MetricDefinition.requires: list[InputKind]`** declares every input the metric needs (closed `InputKind`, ADR 0003). **Shape (P-07):** non-empty and without duplicates.
2. **`Run.available_inputs: list[InputKind]`** records what this run actually has. It is derived from evidence (artifacts, transcripts, spans, channel maps), not from the declared tier. `observed_tier` is a summary for display only; no logic reads it.
   - **What `usage` means (revision 29, T-A1).** The input kind `usage` means usage of the agent under test (`UsageRecord` with `domain=agent_under_test`, ADR 0014): the run lists it only when such usage was reported or observed. Our own evaluation usage (the judge's, our STT's), which a bundle normally also holds, is never an input of an agent metric and never makes `usage` available. A metric that requires `usage` and needs a particular unit (for example input tokens) reads the units it finds; when the run lists `usage` but no record of the agent under test has that unit, the inputs existed and the metric could not be computed, so the result is `error` with a structured error, never a score, 0 or `not_applicable`.
   - **Limitation (revision 29, T-A2): no input kind for interruptions.** No `InputKind` separates frame-accurate turn boundaries and interruptions (an observer, T2) from audio-aligned or telemetry timing, so applicability cannot tell T2 from T1, and a metric that read `Turn.interrupted` would be scored on turns where it is `None`. No Phase 1 metric reads `Turn.interrupted`. When a Phase 3 metric needs it, an `interruptions` input kind is added to the closed set (an additive closed-set change, ADR 0003, with its own decision) before that metric is defined.
2a. **`Run.observed_tier` (revision 12, O3 decided by the owner, option A).** A closed set `T0 | T1 | T2` (ADR 0003 Decision 1), required, with no default. It means **the highest tier whose evidence the run holds**: `T2` if the run holds observer evidence, else `T1` if it holds telemetry evidence, else `T0`. It is a display and filter summary only. No metric, verdict, cost or privacy logic reads it: applicability uses `available_inputs` (Decisions 2 and 3), and `detected_capabilities` stays a separate record (ADR 0009 Decision 5, P-23). The owner also decided that **a check rejects values that contradict the recorded capabilities**. Which contradictions can be detected:
   - **What the capability fields can say.** `available_inputs` and `detected_capabilities` are `InputKind` lists (ADR 0003 Decision 1), and an input kind does not record its producer. A transcript, turn timing and tool calls can each come from an agent export (T0), from telemetry (T1) or from an observer (T2); `ToolCallEvent.source` includes `agent_export` for that reason (O2). So no rule over these fields can detect a T1/T2 confusion, and no rule over them can detect an over-claim (a stored T1 or T2 without such evidence). There is therefore no single rule that covers the whole meaning. The architect proposed two rules (O3a), and **the owner accepted both in revision 13 (option A)**:
   - **R1, on the Run record (P1-12).** `spans` in `available_inputs` together with `observed_tier=T0` is rejected, with the error located at `observed_tier`. Reason: the `spans` input is StageSpan records, each with a required trace or span `ExternalRef` (ADR 0012 Decisions 2 and 6), which exist only where the agent emits telemetry or an observer records it; a black-box (T0) run cannot hold them. Premise, accepted by the owner with R1: no T0 source (for example an agent export file) can supply `spans`. If a real-sample mapping (P1-28 to P1-36) finds a T0 source that does supply spans, the mapping records it as a gap (ADR 0018) and R1 goes back to the owner; it is never relaxed silently. Nothing else is checked on the record. `detected_capabilities` is not read by R1, because the ADRs do not say whether a detected capability means that this run holds the evidence (P-23 records detections without that statement).
   - **R2, over a RunBundle (P1-14).** `check_observed_tier(run, records)` computes the evidence tier from the closed provenance fields of the bundle's records, and the stored `observed_tier` must equal it (both an under-claim and an over-claim are rejected; the message names the stored and the computed tier and the ID of one evidence record, never a value). Observer evidence: `Transcript.source=observer`, `Turn.timing_source=observer`, `Exchange.source=observer`, `TimelineOrigin.kind=observer` (on a Transcript or a ToolCallEvent), `ToolCallEvent.source=observer`. Telemetry evidence: `Transcript.source=agent_telemetry`, `Turn.timing_source=telemetry`, `Exchange.source=telemetry`, `TimelineOrigin.kind=telemetry`, `ToolCallEvent.source=agent_telemetry`, any `StageSpan`, any `UsageRecord` with `domain=agent_under_test` and `source=telemetry` (P1-23). Limit, accepted by the owner with R2: a `StageSpan` has no producer field, so a run whose only observer evidence is spans computes T1 and cannot store T2 (an additive producer field on StageSpan would lift this).
   - **Deliberately withheld records (revision 13, added by the owner with O3a).** R2 needs the whole run, so a legitimate partial export would fail it. P1-14 must define how a bundle declares records that were deliberately withheld, and R2 then reads that declaration. The P1-14 shape must meet these constraints (api-surface 22.12 item D3):
     - the declaration is explicit, per run, and names record kinds and IDs, never values;
     - without a declaration R2 is strict;
     - an under-claim (stored tier below the tier computed from the records present) is always rejected, because withholding cannot remove evidence that is present;
     - an over-claim is accepted only when the declaration covers a record kind that can carry the missing evidence (Transcript, Turn, Exchange, ToolCallEvent, StageSpan, UsageRecord); a declared Artifact alone does not excuse it;
     - a declaration never raises the computed tier;
     - P1-14 also states how a sealed record (`SealedPayload`) and a redacted record count, and whether a RunBundle, the unit of a run (N22), may declare withheld records or only an ExportBundle may.
   - **The declaration (revision 22, P1-14, B4 and B3; api-surface 25.6).** `RunBundle.withheld: list[WithheldRecord]`, where `WithheldRecord{kind, record_id}` is a value object (ADR 0001 Decision 8): `kind` is one of `artifact, transcript, turn, exchange, tool_call, span, result, usage_record, cost_record` (`bundle.WITHHOLDABLE_KINDS`) and `record_id` a typed ID of exactly that kind. It lives on the RunBundle, the unit of a run, so a RunBundle may declare and an ExportBundle declares through the run bundles it embeds (there is no export-level declaration); a declaration never covers another run. Rules: a declared record must not be in the bundle and is declared once (`[withheld]`); a reference by ID to a declared record (an evidence reference, a turn's transcript, an artifact's `turn_ref`, a channel map's artifact, a result's declared-language transcripts, a cost record's usage records, a verdict check's result) is not `[unresolved]`; an over-claim is excused when at least one declared record has a kind in `bundle.PROVENANCE_KINDS` = `transcript, turn, exchange, tool_call, span, usage_record` (an artifact, a result or a cost record alone does not excuse it); an under-claim is never excused; the computed tier reads only the records present. A declaration excuses nothing else (an unprotected payload, a marker, any other rule). Counting: a redacted record keeps its provenance fields readable and counts as present; the metadata record of a sealed artifact, transcript or tool call stays in the export and counts; only the turns that a sealed `transcript_text` replaced are gone and count through a declaration. Not pinned (B4): whether a declared `span` or `usage_record`, which cannot carry observer evidence, should excuse a T2 over-claim; the implementation follows the owner's D3 text (any of the six kinds); restricting T2 to `transcript, turn, exchange, tool_call` is a possible later tightening. Functions: `bundle.evidence_tier(records)` and `bundle.check_observed_tier(run, records, *, withheld=())`.
3. **`missing_inputs(definition, run) = requires - available_inputs`** is a pure helper. If the result is non-empty, the metric's result is `not_applicable` with `na_reason=missing_input` and `missing_kinds` equal to that set, except in the single case of Decision 5 (revision 11, N23), which reports `agent_channel_unknown` instead.
4. **`MetricResult.status ∈ {scored, not_applicable, error}`**:
   - `not_applicable`: `value=None`, `passed=None`, and `na_reason` is required: `missing_input` (with kinds), `agent_channel_unknown`, `language_not_observed` (revision 9, P-59), `unsupported_language`, or `unsupported_script`. **Precedence (P-10, amended by P-59 in revision 9):** when several apply, the first of `missing_input`, `agent_channel_unknown`, `language_not_observed`, `unsupported_language`, `unsupported_script` is reported.
   - **Language provenance (revision 10, N14).** Every result also carries `language_source: observed|declared|None` and `declared_language_transcript_ids: list[TranscriptId]`, with the rules of Decision 6g. They say whether the language that the language steps used came from a producer's tag or from a user's declaration.
   - `error`: `value=None`, `passed=None`, and `error{code, message}` is required. The inputs existed, but scoring failed. **An undetermined overall judge outcome (P-09)** is `error` with `error.code=judge_undetermined`; it is never recorded as pass, fail or not_applicable.
   - `scored`: `value` is present and matches the definition's `value_type` (ADR 0010). **Without a pass rule (P-08)** `passed=None` (informational metrics such as talk ratio). **Exception for `per_turn_share` (user decision P-58, revision 7):** `value` is forbidden (`None`), `per_turn` (with a share consistent with its counts) is required, and `passed` is the definition's range pass rule applied to the share (ADR 0010 Decision 3a). For not_applicable and error results of such definitions `value` stays `None`, and `per_turn` is present (without a share) only for the P-56 no-counted-turn outcomes.
5. **The agent channel.** If no ChannelMap identifies exactly one agent channel, `agent_audio` is not in `available_inputs`. Metrics that need it are `not_applicable` with `agent_channel_unknown` under the following exact rule (revision 11: N23 decided by the owner, option A). Before revision 11, Decision 3 made the same situation `missing_input`, which comes first in the precedence, so `agent_channel_unknown` could never have been reported.
   - The reason is `agent_channel_unknown` iff all three hold: `agent_audio` is the only missing kind (`missing_inputs(definition, run) == ["agent_audio"]`), `audio` is in `run.available_inputs`, and no ChannelMap of the run identifies exactly one agent channel (`agent_audio_available(run.channel_maps)` is false). Then `missing_kinds` is empty.
   - In every other case with missing kinds, the reason is `missing_input` and `missing_kinds` lists all of them, `agent_audio` included.
   - Reason: `agent_channel_unknown` says "the recording exists, but nobody established which channel is the agent". That is true only when a recording is available and nothing else is missing. Without a recording there is no channel to identify, and when other inputs are missing too, the run would stay not applicable even if the channel were identified, so the actionable statement is the full list of missing kinds.
   - In both cases the language steps do not run, so `language_source` is `None` and `declared_language_transcript_ids` is empty (Decision 6g).
5a. **Worked examples for the agent channel (revision 11, N23).** A metric that requires `agent_audio`, unless stated otherwise:
   - `audio` available, no channel map (or only `unknown` or `mixed` channels): `agent_channel_unknown`, no kinds. This is the case T-DEG checks (`test_deg_agent_audio_na_when_channel_unknown`).
   - no recording at all (`audio` and `agent_audio` both absent from `available_inputs`), `requires=[agent_audio]`: `missing_input` with `[agent_audio]`. There is no channel to identify.
   - `requires=[audio, agent_audio]`, no recording: `missing_input` with `[audio, agent_audio]`.
   - `requires=[agent_audio, reference_text]`, `audio` available, no channel identifies the agent, no reference text: `missing_input` with `[agent_audio, reference_text]`. The channel question is listed, not hidden, and the missing reference is not hidden behind it.
   - `audio` available and a channel map identifies exactly one agent channel, but `agent_audio` is not in `available_inputs` (the converse of the Run rule is not required, `docs/phase1/api-surface.md` section 22.1): `missing_input` with `[agent_audio]`. The channel is known, so `agent_channel_unknown` would be false; the producer did not list the input.
6. **Language applicability.** A metric whose `languages[]` does not cover the primary language of the observed input is `not_applicable` with `unsupported_language` (for example WER on an observed `bn-IN` turn). Revision 9 (P-59, decided by the owner) makes this exact as follows.
   - **6a. Two forms of `MetricDefinition.languages`.** The field is required, has no default, and is exactly one of:
     - the string `"language_independent"`, emitted in JSON Schema as `{"type": "string", "enum": ["language_independent"]}` (never `const`, ADR 0003 Decision 6);
     - a non-empty list of `SupportedLanguage` tags with distinct primary languages (ADR 0005 Decision 6).
     No other string is accepted (`"all"`, `""`, `"language-independent"`), and the string inside a list (`["language_independent"]`) is rejected.
   - **6b. A language-independent metric has no language step.** It is never `language_not_observed`, `unsupported_language` or `unsupported_script`. Examples: response latency, interruption counts, talk ratio, turn counts. It must have `script_sensitive=false`, and `script_sensitive=true` with `"language_independent"` is rejected when the definition is validated. Reason: Decision 7 judges a script against the allowed scripts of the observed language, so a metric that depends on the script depends on the language. Such a metric must list its languages. (Detail fixed while applying P-59, for owner confirmation.)
   - **6c. The observed language of a turn.** It is `Turn.language` when present. Otherwise it is the `detected_language` of the turn's Transcript. Otherwise the turn has no observed language. Two more cases also count as "no observed language":
     - the tag `und` (the producer stated that it did not determine the language);
     - a raw label that did not normalize to a tag (`Turn.language_raw` or `Transcript.detected_language_raw` present with the normalized field `None`, ADR 0005 Decision 3).
     Configured languages are never used as an observation: `Evaluator.language`, `Persona.language`, `ScriptedTurn.language`, `DatasetItem.language` and `AgentTarget.languages` describe intent, not what was heard. A user-declared language (Decision 6g, revision 10) is not an observation either. It is a separate input with its own source, `declared`, and it is used only where 6g allows. A tag counts only when the producer of the turn or transcript recorded it (an STT provider, an agent export, or our runner for turns it generated from a script). The turn-before-transcript order and the `und` rule are details fixed while applying P-59, for owner confirmation. The tags `mul` and `zxx` are observations: their primary language is never in a metric's list, so they give `unsupported_language`.
   - **6d. Which turns a metric reads.** These are the turns of the transcripts that supply its transcript-type inputs, limited to the role the input kind names (for example only agent turns for `agent_transcript`). A language-dependent metric that reads no turn (audio-only inputs) takes the observed language from the `detected_language` of a Transcript of the same artifact. With no such tag the input has no observed language.
   - **6e. Order of the language steps for a language-dependent metric.** These steps run after `missing_input` and `agent_channel_unknown`:
     1. any read turn without an effective language: `language_not_observed`. A turn's effective language is its observed language (6c), or else, only where Decision 6g allows it, the declared language of its transcript (revision 10);
     2. otherwise, any read turn whose effective primary language is not covered by `languages[]` (compared by `primary_language()`): `unsupported_language`;
     3. otherwise, the script rule of Decision 7: `unsupported_script`. It reads observed tags only, and a script-sensitive metric never uses a declared language (6g), so a declaration can neither cause nor hide `unsupported_script`;
     4. otherwise the metric is scored.
     The five reasons and their precedence (Decision 4) are unchanged by revision 10.
     A `per_conversation` metric applies the steps to the set of turns it reads, so one untagged turn makes the whole result `language_not_observed`. Scoring the tagged turns alone would score a different input than the definition names. A `per_turn_share` metric applies the steps to each turn on its own. A turn that is not applicable for a language reason is excluded from the denominator (P-26). When no turn is counted, the result's reason follows ADR 0010 Decision 3, using the precedence of Decision 4.
   - **6f. Worked example: an untagged VoicEra transcript (F8; structure only, no real text).** Import of an F8 file gives `Transcript.source=agent_export`. `detected_language` and `detected_language_raw` are absent. Every `Turn.language` and `Turn.language_raw` is absent, `timing_source=none`, and there is no audio artifact. The evaluator's configured language is a Marathi tag. Four definitions are applied, and for each one the transcript inputs that the F8 mapping makes available are assumed present:
     - p95 response latency: `languages="language_independent"`, `requires` includes `turn_timing`. Result: `missing_input` (no turn timing). It has no language step at all.
     - agent turn count: deterministic, `"language_independent"`, `script_sensitive=false`, requires a transcript input. Result: scored.
     - goal completion: `llm_judge`, `languages` lists Marathi, Hindi and English tags, `script_sensitive=false`. Result: `language_not_observed`. The configured Marathi tag does not change this (6c).
     - WER: `languages` lists the same tags, `script_sensitive=true`, and `requires` includes `agent_audio` and `reference_text`. Result: `missing_input`, which precedes the language steps.
     The F8 turns may mix scripts. This produces no `unsupported_script`, because without a tag no script is observed (P-11), and the language step stops at `language_not_observed` first. Suppose a later STT pass over a recording of the same call writes an `our_stt` transcript whose turns carry `mr-IN`. On that transcript the goal-completion judge is scored. A turn tagged `mr-Latn` would make a script-sensitive metric `unsupported_script`. The imported `agent_export` transcript stays untagged: a tag observed on one transcript is never copied to another.
   - **6g. A user-declared language for an untagged import (N14, decided by the owner in revision 10).** An importer may take a language that the user declares for an import that carries no language label. The declaration is recorded, it is never an observation, and the result records when it was used.
     - **Where it is recorded.** `Transcript.declared_language: LanguageDeclaration?` (ADR 0011). The value object (ADR 0001 Decision 8) is `LanguageDeclaration{language, source, declared_by, declared_at}`:
       - `language: SupportedLanguage`, without a script subtag (`mr-IN` and `mr` are valid, `mr-Deva-IN` is rejected). A declaration states the language of the call, not the script of each turn, and imports such as F8 mix scripts. A language outside the nine cannot be declared; such input stays `language_not_observed`.
       - `source`: a closed set with exactly one member, `user_declared` (emitted as `enum`, ADR 0003 Decision 6). It is closed so that any later kind of declaration needs its own decision.
       - `declared_by: MachineKey?`: the actor that recorded the declaration, for example `cli` or, from Phase 2, an account key. It is never a person's name or e-mail address, and a value containing `@` is rejected. **Revision 32 (N19, gate finding M5):** optional, default `None` (absent and `null` are the same); a present value is validated as before; `language`, `source` and `declared_at` stay required. It names an actor, so a shared or benchmark `ExportBundle` holds none (`[declared_by]`, ADR 0016 Decision 6a); an internal export, a `RunBundle` and a `Transcript` may keep it. An absent `declared_by` changes nothing in the language steps: the declaration is used exactly as before, and the results still record `language_source=declared` with the declared transcript IDs.
       - `declared_at: UtcDatetime`: when the declaration was made. It is required, because a declaration without a time cannot be audited.
     - **When it is allowed.** Only on a transcript that is an import and carries no transcript-level label: `Transcript.source` is `agent_export`, `agent_telemetry`, `observer` or `human_reference`, and `detected_language` and `detected_language_raw` are both absent. Otherwise the Transcript is rejected, with a message that names the rule. Reasons: for `our_stt` and `script` transcripts our own producer records the tag. When a producer recorded any transcript-level label (a tag, `und`, or a raw label that did not parse), the producer has spoken, and a declaration must not overrule it.
     - **When it is supplied.** In 0.0.1 the declaration is supplied with the import that writes the transcript. Adding or changing a declaration on a stored transcript is not defined in 0.0.1, because a result that cites the declaration must keep its meaning. How that interacts with idempotent re-import (P-02) is a Phase 2 question (`docs/phase1/api-surface.md` section 21.5).
     - **It is never an observation.** No observed field is filled from it: `Turn.language`, `Turn.language_raw`, `Transcript.detected_language` and `detected_language_raw` stay as imported. It is never copied to another transcript, including a later `our_stt` transcript of the same call. A configured language (6c) never becomes a declaration. In particular `DatasetItem.language` is not copied into `declared_language` (P1-13). A declaration is an explicit act of a user at import.
     - **Which turns it covers.** It is used for a read turn only when the turn has no label of its own: `Turn.language` and `Turn.language_raw` are both absent. A turn tagged `und`, or with a raw label that did not parse, keeps "no observed language" (6c), and the declaration does not cover it. A turn with its own tag uses that tag (source `observed`). For a language-dependent metric that reads no turn (6d), the declaration of a Transcript of the same artifact may supply the language in the same way.
     - **Script-sensitive metrics.** A metric with `script_sensitive=true` never uses a declared language. A turn whose language would come only from a declaration has no effective language for such a metric, which gives `language_not_observed`, the same result as without the declaration. Reason: Decision 7 judges the script of the text, and in 0.0.1 the script is known only from the script subtag of an observed tag (P-11). A declaration has no script subtag, so using it would score WER or CER on text whose script nobody stated. This rule is revisited when the text's script becomes known by other means (the Phase 3 script detection recorded as evidence, P-11). Changing it is a schema change.
     - **Effect on the precedence of P-59.** For a metric that is not script-sensitive, a turn covered by a declaration has an effective language, so `language_not_observed` no longer applies to it. `unsupported_language` still applies when the declared language is not covered by `languages[]`. `unsupported_script` still applies to observed turns of a script-sensitive metric (step 3). `missing_input` and `agent_channel_unknown` still come first. In `per_turn_share`, a covered turn is judged like a tagged turn, and an uncovered untagged turn is a not_applicable turn (I25).
     - **What each MetricResult records.**
       - `language_source: observed|declared|None` (closed set, ADR 0003). It is `declared` iff the effective language of at least one read turn came from a declaration, and `observed` iff every read turn that has an effective language has an observed one.
       - It is required iff the definition is language-dependent (the list form), the language steps ran, and at least one read turn has an effective language. That covers status `scored` and `error`, `not_applicable` with `unsupported_language` or `unsupported_script`, and `language_not_observed` or a `per_turn_share` result in which some other read turn had an effective language.
       - It is `None` for a language-independent definition, and whenever the language steps did not run (`missing_input`, `agent_channel_unknown`). It is also `None` for `language_not_observed` when no read turn has an effective language (the F8 case of 6f).
       - `declared_language_transcript_ids: list[TranscriptId]`: the transcripts whose declaration was used, unique and sorted by their string form. It is non-empty iff `language_source` is `declared`, and empty otherwise (default `[]`).
       - Checks: the result alone checks the presence rules that need only its own fields. Where the result meets its definition (P1-11), `language_source` on a language-independent definition is rejected, and so is `declared` on a script-sensitive definition. The bundle check (P1-14) verifies that each listed transcript exists in the bundle and has `declared_language`.
       - Reports (Phase 3 and later) show "language declared by user" next to every result with `language_source=declared`, so a declared language is never presented as an observed one.
     - **Not affected.** `Run.available_inputs` and `missing_inputs()`: a declaration is not an input kind. WER and every other script-sensitive metric, as stated above. Language-independent metrics, which have no language step.
   - **6h. Worked example: the F8 transcript of 6f with a declared language (N14; structure only, no real text).** The user imports the same untagged F8 file and declares Marathi. The transcript then has `source=agent_export`, `detected_language` and `detected_language_raw` absent, and `declared_language{language: mr-IN, source: user_declared, declared_by: cli, declared_at: <time of import>}`. Every turn still has `language` and `language_raw` absent. Results:
     - p95 response latency: `missing_input`, as in 6f. `language_source` is `None`, because the metric is language-independent.
     - agent turn count: scored, as in 6f. `language_source` is `None` (language-independent).
     - goal completion (`llm_judge`, `languages` lists Marathi, Hindi and English tags, `script_sensitive=false`): scored, with `language_source=declared` and `declared_language_transcript_ids` holding this transcript's ID. It carries `JudgeInfo` and no `scorer` (ADR 0010 Decision 5a).
     - the same judge in a version whose `languages` lists only Hindi and English: `unsupported_language`, with `language_source=declared`.
     - WER: `missing_input`, as in 6f, because that comes before the language steps. If audio and a reference existed, WER would still be `language_not_observed`, because it is script-sensitive and never uses a declaration.
     - a script-sensitive metric that reads only agent turns (for example a native-script check): `language_not_observed`, as without the declaration. The F8 turns may mix scripts, and the declaration says nothing about script.
     - A later `our_stt` transcript of the same call whose turns carry `mr-IN` gives results with `language_source=observed` on that transcript. The declaration stays on the `agent_export` transcript only.
7. **Script applicability (accepted in revision 3).** `MetricDefinition.script_sensitive: bool` is required and has no default. If `script_sensitive=true` and the observed input's script is not one of the allowed native scripts of its language in `languages.json` (for example observed `hi-Latn`), the result is `not_applicable` with `na_reason=unsupported_script`. Hindi is supported; romanized Hindi is not, and the reason says exactly that. A metric with `script_sensitive=false` (for example a judge-based goal-completion check) is scored on the same text. **How the observed script is determined (P-11):** in 0.0.1 only from the script subtag of the observed language tag (`Turn.language` or `Transcript.detected_language`); text without a tag, or a tag without a script subtag, is not treated as romanized. Text-based script detection is a Phase 3 scorer step owned by indic-linguistics that records its finding as evidence. **Revision 9 (P-59):** the script rule runs only for a language-dependent metric, and only after the language steps of Decision 6e found every read turn tagged and covered. A language-independent metric is never script-sensitive (Decision 6b).
8. **The verdict.** `not_applicable` and `error` never count as passed or failed. They make a required check `inconclusive` (ADR 0013).
9. **The bundle re-runs applicability (revision 29, batch 23; B15, T-DEG decision D1, with T-A3 and T-A4).** A stored result is never taken on trust: `check_run_bundle` (P1-14) ends with the rule `[applicability]`, the last of its rules (after R2), which re-runs `applicability` (Decisions 3 to 6g) for every result of the bundle and rejects any difference. Contract: `docs/phase1/api-surface-applicability.md`; summary in `docs/phase1/api-surface.md` 25.4.1 step 9.
   - **What is re-run.** For each result: the definition `(id, version)` the bundle's snapshot embeds; the run; the transcripts the result read; their turns, limited by role (Decision 6d: the agent turns for `agent_transcript`, all turns for `transcript`, none for a metric with no transcript input). A run-level answer (`missing_input`, `agent_channel_unknown`) stands whatever else holds. A `per_conversation` metric is re-run over its read turns together; a `per_turn_share` metric once per read turn, aggregated as ADR 0010 Decision 3 does (scored if any turn applies, else the strongest reason by Decision 4; `declared` if any turn used a declaration, else `observed` if any turn had an effective language, also one that was then not applicable; the declared transcripts are the union). Nothing else is read: not the tier, not a configured language.
   - **What is compared**, the first difference reported: the status class (`not_applicable` or not), `na_reason`, `missing_kinds` (in the order of `requires`), `language_source`, `declared_language_transcript_ids`. An `error` result is exempt from the status class, except that a run-level answer rejects it (I3: an error is for a metric whose inputs existed); its language provenance is compared. The value and the judge and scorer records are not compared; the per-turn counts are judged by T-B16 below (revision 32).
   - **Which transcripts a result read: `MetricResult.transcript_ids` (T-A3).** An optional `list[TranscriptId]`, default `None` (absent and `null` are the same); when present it has at least one element, no element twice, and keeps the producer's order. Each element resolves inside the same run bundle or through a withheld declaration (`[unresolved]`). Without it, a bundle with one transcript reads that one and a bundle with none reads none. With several held transcripts it is **required** on every result of a metric whose `requires` has `transcript` or `agent_transcript` or whose `languages` is a list; this is decided on the definition, not on the stored outcome (a rule that read the outcome it checks would be circular). A named transcript that is declared withheld is not held and is not read. The field is part of the result's content (digest domain); it is additive within the unreleased 0.0.1 (ADR 0008).
   - **`agent_transcript` implies an agent turn (T-A4).** When `available_inputs` lists `agent_transcript`, the bundle holds at least one turn and declares no turn withheld, at least one turn has `role=agent`. A bundle with no turn (an empty call, the text left out) is not judged by this rule.
   - **A scored result read a turn (revision 32, T-B13, gate finding M4; contract `docs/phase1/api-surface-gate-fixes.md` P-C1, P-C2, P-C5).** A stored `scored` result of a metric whose `requires` names `transcript` or `agent_transcript` has read at least one turn (an agent turn for `agent_transcript`): the turns of the transcripts it read, limited by role as above. Otherwise it was scored over nothing and is rejected at the field `status`. The cases: an empty call; a transcript with no turn; an `agent_transcript` metric whose `transcript_ids` name only a transcript without an agent turn while another transcript has them (T-A4, which is global, holds). `not_applicable` and `error` results claim nothing and are not judged by it (A-C2). It runs after the run-level answer: a result whose run-level answer differs is reported by that comparison first. The message does not name the input kind.
   - **The per-turn counts (revision 32, T-B16, gate finding M4; P-C3 to P-C6).** For a `per_turn_share` result that carries a `per_turn` summary, whatever its status (`scored`, every turn `not_applicable`, or the `error`/`judge_undetermined` outcome), the bundle recomputes from the turns the result read: `per_turn.total_turns` is their number, and `per_turn.counts.not_applicable` is the number of them for which `applicability` over that turn alone is not applicable (the same per-turn answers that give the language outcome). `passed`, `failed` and `undetermined` are what the scorer or the judge answered and are not compared (A-C4; their sum is fixed by the two compared counts, since the model makes the four add up to `total_turns`). The count fields are reported after the five compared fields, `total_turns` before `not_applicable`; a scored per-turn result over no turn is reported at `status` (T-B13, A-C5).
   - **Withheld records (B22: skip only what cannot be re-run).** When a `transcript` or `turn` is declared withheld the language steps cannot be re-run for the bundle: only the run-level answer is judged (stored exactly; any other answer must not carry a run-level reason) and the language outcome is accepted as stored; T-B13 and T-B16 are off for every result of that bundle (A-C3: a withheld ID does not say which transcript it belonged to). For a `per_turn_share` metric that reads no turn (T-B4) the language outcome is likewise accepted as stored and the run-level reasons are compared; since revision 32 a stored `per_turn` summary on such a result is rejected at `per_turn.total_turns` (a summary counts at least one turn; P-C6), and a scored one is T-B13. Withheld artifacts, exchanges, tool calls, spans, usage and cost records and results take nothing away (the turn rule and the counts still run); a withheld result is not there to check. A `SealedPayload` of `transcript_text` in an export replaces the transcript's turns, so the embedded run bundle declares those turns withheld; without the declaration its scored transcript results read no turn and are rejected (A-C1).
   - **The error** is a `ValueError` tagged `[applicability]` that names the result's ID, its position `results[<index>]` and the one field that differs (one of the five, or since revision 32 `per_turn.total_turns` or `per_turn.counts.not_applicable`) (or, for the missing ids, the words `transcript_ids required when the bundle holds several transcripts`; for T-A4 the run ID and `agent_transcript`). It never quotes a text, a tag or a reason value.
   - **Reason.** Without the rule a bundle could carry a result that its own run contradicts (a score for an input the run lacks, `not_applicable` for an input it has, an observed language where none was observed), and the T-DEG guarantee "the same evaluator gives the same outcome at every tier" would hold only for the evaluator, not for what a bundle says. The rule is a pure function of the bundle, so a rescoring (a new bundle, B5) is judged exactly like the first one.
   - **Not covered (later rules, each a tightening):** "`transcript` in `available_inputs` implies a turn" as a rule on the run (T-B13 judges only the results that claim a score); the tally of `JudgeInfo.per_turn` verdicts against `passed`, `failed` and `undetermined` (A-C4, once the judge record format is frozen). T-B13 and T-B16, listed here in revision 29, are rules since revision 32.
10. **Our own STT transcript of a recording (revision 40, 2026-10-25, Phase 3 task P3-00d; `docs/phase3/SCOPE.md` Q14 and Q16, auto-approved under the owner's rule, decision log "PHASE 3 SCOPE DELIVERED").** Phase 3 transcribes a recording in chunks through a provider (ADR 0024). Two rules make what the run then holds an exact statement of what happened; neither changes a model or a rule of 0.0.1.
   - **10a. STT failure is all or nothing.** When any chunk of the recording fails after its bounded attempts, no `our_stt` Transcript is written, and no Turn or Segment is built from the chunks that succeeded. `transcript` is therefore not in `Run.available_inputs` (Decision 2: availability is derived from the records), and every metric that requires it is `not_applicable` with `na_reason=missing_input` and `transcript` in `missing_kinds` (Decision 3), never `error` (the input never existed, Decision 4) and never a score over a partial text (its missing chunks would read as deletions). The Run records an `IngestWarning` that names the failed chunk by index and the error class, never a response body, a transcript text or a key, and the command exits non-zero. The usage records of the chunks that succeeded are kept: that usage happened (ADR 0014 Decision 8, `source=measured`). Rejected: a partial transcript; `error` (Q14). Tests: `test_stt_failure_is_missing_input_with_warning_and_nonzero_exit`, `test_sarvam_partial_chunk_failure_yields_no_transcript` (Phase 3, P3-20 and P3-07).
   - **10b. An empty chunk makes no Turn.** A chunk whose STT transcript is empty or white space only yields no Turn; the Transcript's metadata counts such chunks and lists their indices. The language tag a provider returns with an empty transcript is not an observation (Decision 6c): it is never written to a Turn, and it does not count towards `Transcript.detected_language`. A recording where every chunk is empty still yields its Transcript, with no Turn, so `transcript` is available; a metric that then reads no token is `error` with its own code (ADR 0023 rule 15), and T-B13 (Decision 9) keeps any scored result honest. Rejected: a Turn with empty text (it would state that a turn existed in an observed language); dropping the chunk silently (the plan would not account for every sample). Tests: `test_empty_chunk_makes_no_turn_and_is_counted`, `test_detected_language_set_only_when_all_chunks_agree` (Phase 3, P3-09).

## Rejected alternatives
- **Score missing inputs as 0 / false / fail.** This misrepresents capability as quality: a T0 run would "fail" tool-call correctness for not having telemetry. It is fabrication of a value.
- **Drop the metric from results when inputs are missing.** The result set would then differ by tier, which breaks "same schema at every tier" (T-DEG). The reader also could not tell "not run" from "not configured".
- **Infer availability from `declared_tier` / `observed_tier`.** Tiers are coarse. A T1 agent may emit spans but no tool calls. Availability per input kind is exact.
- **One generic `skipped` status.** It merges "could not run because inputs are absent" with "ran and crashed". Those have different fixes and different verdict meanings.
- **Free-text NA reasons only.** Free text cannot be aggregated (for example "share of not_applicable by reason per tier").
- **`unsupported_language` for romanized text.** It states something false (the language is supported) and hides how much NA comes from script rather than language, which is what an Indic-first report must show.
- **Hard-coding WER/CER as script-sensitive in scorer code.** The decision would be invisible in the snapshot, so a reproduced run could behave differently. A required field in the versioned definition is reproducible and testable from data.
- **`script_sensitive` with a default of false.** Forgetting the flag would silently score WER on romanized text against native references.
- **(Revision 9, P-59) `unsupported_language` for input without a tag.** The language may well be supported. The reason would be false, and a report could not separate "we do not cover this language" from "nobody told us the language".
- **(P-59) Filling a missing tag from the configured language (Evaluator, DatasetItem, Persona).** That assumes what the agent or caller actually spoke, which the core rule forbids. It would also hide whether the agent answered in the language it was configured for.
- **(P-59) An empty `languages[]` or a list of all nine languages for a language-independent metric.** Empty is rejected (ADR 0005 Decision 6). A list of all nine would still give `unsupported_language` for an observed language outside the nine and `language_not_observed` for untagged input, which is false for latency. An explicit value states the intent and is checked.
- **(P-59) Scoring a `per_conversation` metric on its tagged turns only.** The result would describe a subset of the conversation while claiming the whole.
- **(Revision 10, N14) Recording a declaration as an observation** (filling `detected_language`, or a new `Transcript.source` value). Downstream logic and reports could no longer tell what a producer heard from what a user asserted, and the rule that configured or declared languages are never observations would be broken in the data itself.
- **(N14) The declaration on Run.** A run may hold several transcripts, some tagged (an `our_stt` pass) and some not, so a run-level value would claim a language for transcripts that the user did not declare. The transcript is the unit that lacks the tag.
- **(N14) A declaration that overrides `und`, an unparseable label or a provider tag.** It would overrule a statement that the producer made. A declaration fills only absence.
- **(N14) Using a declaration for script-sensitive metrics.** It would score WER and CER on text whose script nobody stated, which P-11 forbids.
- **(N14) A new reason `script_not_observed` for script-sensitive metrics on declared input.** It would be more specific than `language_not_observed`, but it adds an `na_reason` and changes the precedence the owner accepted. It is noted as finding N17 in `docs/phase1/api-surface.md` section 21.5 and not adopted.

## Consequences
- Every scorer (Phase 3) must declare `requires` and `script_sensitive` truthfully. qa enforces this per scorer.
- T-DEG bundles at T0/T1/T2 have the same metric keys. Only status, value and reasons differ.
- A run with all required checks `not_applicable` is `inconclusive`, never `pass`.
- (Revision 9, P-59) Every metric author states whether a metric depends on language, and a scorer must declare it truthfully, like `requires`. An import that carries no language tag (F8) makes every language-dependent metric `language_not_observed` until a producer records a tag, for example our own STT pass. Reports can count this reason separately from `unsupported_language`. (Revision 10, N14) A user may declare the language of such an import (Decision 6g). Metrics that are not script-sensitive are then judged in the declared language, and each such result says so (`language_source=declared`).

## Decided items (formerly [Proposed]; all decided by the user in revision 5)
- **P-07. `requires[]` shape. Decided by the user (revision 5): accepted as recommended.** Decision: non-empty and without duplicates. Reason: an empty list would make a metric look applicable to every run including ones with no inputs at all, and duplicates make `missing_kinds` ambiguous. Had it been decided otherwise: an empty `requires` means "always applicable", and `test_requires_nonempty_unique` is dropped.
- **P-08. `passed` without a pass rule. Decided by the user (revision 5): accepted as recommended.** Decision: a scored result whose definition has no pass rule has `passed=None`.
