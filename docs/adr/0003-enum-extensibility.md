## Context
Many fields take a value from a set: roles, transcript sources, input kinds, cost basis, units, statuses. Some sets have meanings that drive invariants and metrics, and an unknown value there would be silently misread. Others name things in the outside world (providers, models, codecs, tool names) that we neither control nor should couple to. Real sources also produce values we have never seen. The core rule says ingestion must never break because of them, and the no-fabrication rule says we must never pretend we understood them.

## Decision
1. **Closed enums** are used where a value's meaning is used by schema invariants, the verdict, the cost model, privacy or NA logic. Unknown values are rejected by pydantic and JSON Schema (`enum`). The closed sets in 0.0.1 (revision 3 additions in bold; revision 5 changes marked "rev 5"):

   - `ChannelRole` (`ChannelMap.channels[].role`): caller, agent, unknown, mixed (rev 5, P-31; `mixed` = a mono channel carrying both speakers)
   - `Transcript.source` (the producer): our_stt, agent_export, agent_telemetry, observer, script, human_reference (rev 5, P-27)
   - `Turn.source`: our_stt, agent_stt, agent_llm_output, agent_tts_input, agent_context, **agent_log**, script, human_reference

2. **Open values** are used where the value names an external thing: `provider`, `model`, tool `name`, `AudioFormat.container`/`codec`, `KeyRef.provider_hint`, IngestWarning `code` (so the importer's warning codes, among them `currency_contract_conflict` of revision 16, are not a closed set), `PriceProvenance.kind` (revision 16, N50 remainder: the kind of source document a price comes from). These are typed `MachineKey` strings (ADR 0017). No provider list is hard-coded in the schema. **Revision 31 (Phase 1 gate finding m2, decided by the lead): `ExternalRef.system` is `VerbatimText`, not `MachineKey`,** as in `tracer_evalschema/ids.py`, together with `ExternalRef.kind` and `ExternalRef.value`. It is also an open value, but it names another system in that system's own spelling, and ADR 0001 Decision 7 stores all three parts of an `ExternalRef` exactly as given: they form the Phase 2 re-import key `(entity kind, system, kind, value)` (P-02), so a `MachineKey` (`^[A-Za-z0-9][A-Za-z0-9._:/@+-]{0,255}$`) would reject or force a rewrite of names other systems use (spaces, non-ASCII letters, a leading punctuation mark, more than 256 characters), and a rewritten name would no longer match the source on re-import. The code and the tests were already free text; this sentence corrects the ADR, which listed `ExternalRef.system` among the `MachineKey` fields. `StageSpan.stage` and `Exchange.source` are closed (Decision 1; P-05, P-06).
3. **Unknown at ingestion.** When an adapter meets a source value it cannot map to a closed enum, it uses that enum's explicit catch-all if one exists (`unknown`, `other`) and records the raw value in an IngestWarning. If no catch-all exists, it leaves the optional field `None` with a warning. It never picks the nearest-looking member.
4. **Evolution.** Adding a member to a closed enum is an additive (minor) schema change, unless the ADR defining the set states that the addition also requires a reshape elsewhere (`SupportedCurrency`, ADR 0014 Decision 5). Readers on older versions already reject the newer file through `SchemaVersionTooNew` (ADR 0008). Removing or renaming a member is breaking (major) and needs a migration. During 0.0.x every change requires an exact version match anyway.
5. Enum values are lowercase snake_case ASCII, except external standard spellings (`A256GCM`, `A256KW`, ISO 4217 codes, digest scheme names, `tracer.sealed.v1`).
6. **JSON Schema form of closed sets (revision 7).** Every closed value set in Decision 1, including single-member sets (`SupportedCurrency` in 0.0.1, `SealedPayload.format`, `alg`, `dek_wrap.alg`, `CostRounding.mode`) and the tag of each discriminated-union variant, is emitted as `{"type": "string", "enum": [...]}`, never as `const`. Pydantic (verified on 2.14.1) emits `const` for a one-member `Literal`, so closed sets are declared through one shared helper: `Annotated[str, <membership validator>, WithJsonSchema({"type": "string", "enum": [...]})]`, where the validator and the `enum` are built from the same tuple, giving identical validation-mode and serialization-mode schemas. Data-driven sets (`SupportedCurrency`) pass the tuple read from their data file. Whether pydantic's discriminator mapping stays correct with such tags is verified at P1-08. Test: `test_no_const_in_generated_schemas` (C).

## Rejected alternatives
- **Open strings everywhere.** Invariants such as "not_applicable implies value None" or "basis is reported|computed only" could not be enforced. A typo (`not_aplicable`) would pass validation and count as a different state.
- **Closed enums for providers and models.** This couples the schema to a vendor list, needs a schema release for every new model, and breaks the agent-agnostic principle. Provider specifics belong in adapters and the pricing catalog.
- **Lenient enums (unknown values coerced to a default member).** Silent coercion is fabrication: an unknown transcript source read as `our_stt` would let a noisy agent transcript be treated as our measurement.
- **Integer-coded enums.** Unreadable in exports and logs, and fragile under reordering.

## Consequences
- Some real values will arrive that the schema cannot express precisely. They become ingest warnings, and if they matter to a metric, the verdict or cost, they are blocking gaps (ADR 0018) that need a schema change. That is deliberate: gaps stay visible.
- `agent_log` is not a catch-all. It means "reported by the agent's own export, pipeline stage not stated". A value whose producer is also unknown is a gap, not `agent_log`.

## Decided items (formerly [Proposed]; all decided by the user in revision 5)
- **P-05. `StageSpan.stage` value set. Decided by the user (revision 5): accepted as recommended.** Decision: reuse the closed `UsageRecord.stage` set (stt, llm, tts, judge, sim_caller_llm, sim_caller_tts, realtime, other), plus `stage_raw: MachineKey?` holding the source label whenever `other` is used. Reason: per-stage latency and per-stage cost must join on the same key; an open string would let `stt` and `STT` and `speech_to_text` diverge. Had it been decided otherwise (open `MachineKey`): latency/cost joins need a mapping table, and `test_all_closed_enums_exact` drops the entry.
- **P-06. `Exchange.source` value set. Decided by the user (revision 5): accepted as recommended.** Decision: `audio_alignment | telemetry | observer | inferred_from_turns`. Reason: an exchange is either reported by a source with its own timing or reconstructed by us from turns; the reconstruction must be distinguishable. Had it been decided otherwise: the set the user chooses replaces this one in Decision 1 and in `test_all_closed_enums_exact`.
