# P2-24 security audit of the storage layer (`packages/evaldb`)

- Date: 2026-10-24
- Repository HEAD audited: b50c3cc (origin/main, batch E). Gate items: `docs/phase2/SCOPE.md` section 4 items 12 (security) and 17 (private fixtures, no key value in tree, history or CI config). Format and base findings: `docs/security/P1-21-audit.md`.
- Method: read-only. No key value, no `.env.local` content, no keys file and no private call were read. All probes used synthetic values built from parts at run time. Postgres probes ran in throwaway containers (15.19 and 18.6, the two digest-pinned images of `.github/workflows/ci.yml`) bound to loopback on a random port, with a password generated per run, held only in a process environment variable (never written to a file or log). Both containers were removed at the end of the run; no other container was touched.

## Verdict for the security-licensing gate item: PASS WITH CONDITIONS

No blocker. Every public write, delete and read path of the repository returns errors whose visible text holds no document text, parameter value, row detail, URL, host or password, on SQLite, Postgres 15 and Postgres 18. No SQL is built from a value. The deletion audit holds no content. `expected_purpose` is required at both export entry points. The conditions are: the Postgres error scrub is defeated by exception chaining on the untranslated path (E5, E6); the at-rest statement is not yet in a shipped document (E16); the three P2-24 test names are not yet in the tree (E23); and the hosted CI run for b50c3cc must finish green (E22). Owner decisions are listed at the end.

## Findings

Severity: blocker, high, medium, low, info. Status: closed, open, owner decision.

| id | severity | status | evidence |
|---|---|---|---|
| E1 SQL is built only from bound parameters | info | closed | `ruff --select S --ignore-noqa` over `packages/evaldb/src` reports exactly 3 S608 sites (`migrate.py` `_lost_tables`, `migrations/helpers.py` `_plan` and `rewrite_documents`); with the repository `noqa` comments the check is clean. An AST scan of `text()`, `exec_driver_sql()` and `execute()` finds 7 calls whose first argument is an f-string: `engine.py` `PRAGMA busy_timeout=` (the value is checked `type(...) is int and >= 0` first), the 3 S608 sites (table and column names come from `tables.ENTITY_TABLES` or from `DOWNGRADE_DROPS` constants of a revision; values are bound), and the downgrade of 0001/0002 (names from constant tuples). Every other statement uses the SQLAlchemy expression language (`sa.select/insert/delete` with `.where()` on bound columns) or a fixed literal (`versioning.py`, `engine.py` PRAGMA/SET/SHOW, `0001` `INSERT ... :evaldb_version` via `bindparams`). `triggers.py` DDL is f-strings over the 37 metadata table names and constants and holds no `%` (so the `DDL()` `%` substitution is not in play). No `.like/.ilike/.contains/literal_column` in `repository.py`, `deletion.py`, `verify.py`. The frozen DDL of `0001` is a literal dict; `0002` is a literal tuple of 25 index names, tables and columns. |
| E2 Trusted-code boundary of migrations | low | open (document) | `migrate.alembic_config(version_locations=...)` makes Alembic import and run Python from caller-chosen directories; `DOWNGRADE_DROPS` entries and `new_version` (`helpers.py`, `schema_version = '<new_version>'`) are interpolated into SQL; `BEGIN_OPTION` (`engine.py`) executes the execution-option string as SQL. None is reachable from stored data or user input of the repository API (the only writer of `BEGIN_OPTION` is `deletion.py`, value `BEGIN IMMEDIATE`); it is a trust boundary around whoever holds the Engine or writes a revision. Fix: one sentence in STORAGE_POLICY. |
| E3 No secret columns | info | closed | Walk of `tracer_evaldb.metadata`: 37 tables, 301 columns; names matching `credential/secret/key/token/passw/auth/bearer/private` are exactly two: `metric_definition.key` (a metric identifier, `KeyCol`) and `external_ref_index.key_sha256` (a SHA-256 of a reference, `Sha256Col`). `KeyCol` is also the default type of every projected text column (33 distinct column names, all closed sets, labels or references). No column holds key material or a key reference. |
| E4 Phase 1 credential rules do not reach free-text labels | low | owner decision | Probed by substituting a synthetic AWS-shaped value (built from parts) into every golden document field that is projected into a `KeyCol`. Refused: all closed-set fields, `metadata` values (`ValidationError`, value not echoed), `deletion_audit.actor` (`ValueError`, only the rule name). Accepted and stored in `doc` and in the plain column: `Project.name` (`project.name`), `policy_ref` of Artifact, DatasetItem, Transcript, Run (`*_policy_ref` columns), `ToolCallEvent.name`, `ExportBundle.name` and `RunBundle.name`. This is the Phase 1 design (ADR 0007 Decision 5a covers metadata, URLs, `config_ref`, `KeyRef`); evaldb stores what the models accept. Options: extend `credential_reason` to these labels (a schema change under ADR 0008) or leave and document. |
| E5 Postgres error scrub is defeated by exception chaining | medium | open (condition) | `engine._translate_integrity` returns an `IntegrityError` holding only the fields `S V C M s t c d n`. SQLAlchemy raises it `from` the original driver error, so the original (with field `D`, "Failing row contains (...)") stays as `__cause__`. Verified on 15.19 and 18.6: a raw check violation and a raw not-null violation (value = synthetic marker incl. Devanagari) show the marker in `traceback.format_exception` of the untranslated error; scrubbed args have keys `C M S V n s t`, the cause has `C D F L M R S V n s t`. Not affected: every repository and deletion path, because `translate_integrity_error` raises `StoreConstraintViolation ... from None` (visible text: `the database refused a write: check constraint violated (table 'project') (constraint 'schema_version_pinned')`, marker absent). Exposed: any `IntegrityError` that escapes untranslated (a caller's own statements on the Engine, a migration step). SQLite messages carry no value (`CHECK constraint failed: <name>`, `UNIQUE constraint failed: <table>.<col>`), so SQLite is not affected. Fix: in the hook, also overwrite `original.args` with the scrubbed fields so the chained cause is scrubbed too; add a test that formats the full chain. |
| E6 Values stay reachable through the exception objects | low | open | After `raise StoreConstraintViolation from None`, `__context__` still holds the SQLAlchemy error; its `.params` attribute holds the bound values on both backends (`hide_parameters=True` hides them in `str()` only), and on Postgres its `__cause__` holds field `D`. Visible traceback and `logging.exception` are clean (`__suppress_context__`); a handler that walks `__context__` ignoring the flag would see values. Fix: after translating, set `error.__context__ = None` (or scrub `.params`). |
| E7 Hook covers SQLSTATE class 23 only | low | open | `_translate_integrity` returns `None` for other classes. A raw `CAST(<text> AS bigint)` on Postgres gives a `ProgrammingError` whose `str()` and `args` contain the value (message field `M` of class 22 errors quotes it). No probe reached this through the repository (typed columns validate first: `StoreValueOutOfRange` names table and column only). Fix: widen the scrub to all server errors (keep `M` only for class 23). |
| E8 Opt-in logging can expose content and the host | low | open (document) | The package has no `logging` or `print` call. With `sqlalchemy.engine` at INFO, statements are logged with "parameters hidden"; at DEBUG, result rows are logged: a stored project name (marker) appeared in 2 `Row (...)` lines on a load/verify. With `sqlalchemy.pool` DEBUG and a bad host, the log shows the host name (not the user or password). `repr(engine)` shows user and host and masks the password. Fix: README/STORAGE_POLICY: never enable DEBUG on `sqlalchemy.engine` where rows are personal data. |
| E9 Engine URL is never echoed | info | closed | Bad host, wrong password, nonexistent SQLite directory, unsupported scheme (`mysql://`), unparseable string, and a URL with a duplicate `password` query: each raises `StoreConnectionError("could not connect to the database")` or `StoreConfigurationError` with a fixed message, `from None`. Neither the password nor the user nor the host nor the path appears in the formatted traceback; the password appears in no log record at any level incl. pool and pg8000 DEBUG (host appears in the pool DEBUG line and in `__context__`, E6/E8). SQL_ASCII database: `UnsupportedServerEncoding` names the encoding only. |
| E10 Any `Engine` is accepted | low | open | `repository._engine`, `deletion`, `migrate`, `versioning.open_store` check `isinstance(engine, Engine)` only, although the message says "the Engine of create_store_engine". An Engine built elsewhere lacks `hide_parameters=True`, the Postgres hook, `PRAGMA foreign_keys=ON` (SQLite) and the UTF8 check. Fix: refuse an engine with `hide_parameters` false and mark engines from `create_store_engine` (for example in `engine.info`). |
| E11 No TLS option for remote Postgres | medium | owner decision | `create_store_engine(url, *, busy_timeout_ms)` has no `connect_args`; the pg8000 dialect takes an `ssl_context` only through `connect_args` (SQLAlchemy docs lines in `dialects/postgresql/pg8000.py`). The URL accepted by tracer therefore cannot request TLS, and an Engine built elsewhere is refused only by the weak check of E10 (accepted). Not exploitable on loopback (CI and local use). Decide before Phase 5 (remote staging): add a `ssl_context` parameter, or document a TLS proxy. |
| E12 Deletion audit rows are content-free | info | closed | After `delete_project` of a project named with the marker: `deletion_audit` columns are `audit_uuid, deleted_at, actor, reason, root_kind, counts`; the row text holds neither the project ID nor the name nor the marker; `counts` is a JSON object of the 17 fixed kind names to integers. Same on SQLite, Postgres 15.19 and 18.6. `reason` is a closed set (`operator_request`, `retention_policy`, `data_subject_request`); `actor` is refused when control, separator or invisible characters are present (not echoed) or when `credential_reason` flags it (only the rule name in the message; two credential-shaped values built from parts refused). Append-only trigger: `UPDATE deletion_audit` and `DELETE FROM deletion_audit` are refused on all three databases (SQLite `RAISE(ABORT)`, Postgres SQLSTATE 23001); every other table refuses `UPDATE`. By the docstring of `triggers.py` `TRUNCATE` is not intercepted and a table owner can drop the trigger (not probed). |
| E13 Immutability refusal has a misleading kind | info | open | Postgres 23001 maps to kind `foreign_key`; SQLite trigger refusals map to `other`. Cosmetic: no value is echoed. Fix: a dedicated kind. |
| E14 `deletion_audit.actor` is free text, unbounded, kept forever | low | owner decision | `delete_project(..., actor=)` accepted a person's e-mail address shape, a personal name and a 200000-character actor and stored all three in the append-only table (`SELECT` returned lengths 19, 8 and 200000). An erasure request (`data_subject_request`) therefore cannot remove the operator's own personal data, and the length is not capped. Options: cap the length (for example 256), document that actor should be a role or pseudonym, or hash it. |
| E15 `expected_purpose` is required | info | closed | `store_export` and `load_export` take it keyword-only: omitted and `None` both raise `TypeError`; a non-member raises `ValueError` listing the closed set (code `_purpose`). Probed on SQLite and both Postgres versions. |
| E16 At-rest statement missing from shipped documents | medium | open (condition) | No file under `packages/evaldb`, ADRs 0019-0022 or SCOPE states that the database is not encrypted by tracer (grep for "encrypt" finds only the P2-24 task row). Verified facts to put in STORAGE_POLICY (P2-25): (a) tracer does not encrypt the database or the file; a SQLite file created with the default umask is mode 0644 (observed; the directory was 0700) and tracer does not change it; (b) the stored data is personal data (ADR 0006 Decision 6, ADR 0020 intro): a stored `TestProfile` row held its name, date of birth and account number as readable strings in the raw database file; (c) the `human_subject`, `*_reason`, `retain_until`, `delete_on_expiry` columns exist and are indexed but nothing enforces retention (README line 70, ADR 0020 Decision 8); (d) the test profile is stored in clear in internal exports (`SealedPayload` is for explicit portable exports, ADR 0006 Decision 7); (e) known limitation: an internal snapshot records the plain digest of its profile (`InternalSnapshotRefused` requires it), which can be brute-forced offline for a low-entropy profile (ADR 0006 Decision 6); shared exports never carry it. Also consider creating a new SQLite file with mode 0600. |

## Owner decisions open

1. Credential rule for labels (E4): extend `credential_reason` to `Project.name`, `policy_ref`, `ToolCallEvent.name` and the bundle names (a schema change), or leave and document.
2. Audit actor (E14): cap the length, require a role or pseudonym, or hash it; and whether an erasure request may leave the operator's name in the append-only audit.
3. TLS for a remote Postgres (E11): add an `ssl_context` parameter before Phase 5 or document a TLS proxy.
4. SQLite file mode (E16): create new database files with mode 0600, or leave to the deployment.
5. Error scrub (E5, E6, E7): fix before the Phase 2 gate (recommended; the repository paths are already clean) or accept and record as a documented limit of the raw Engine.
6. Engine provenance (E10): refuse Engines not made by `create_store_engine`, or accept any Engine and document it.
7. Phase 5 concurrency (E20): typed busy error and retry policy for A15 and A16; read-side size bound for exports.
8. Retention enforcement stays a later phase (ADR 0020 Decision 8); the at-rest statement of E16 is to be carried into STORAGE_POLICY (P2-25).
9. Carried unchanged from `docs/security/P1-21-audit.md`: the Sarvam audio clips in public history, the local user name in older revisions, the SIX ISO 4217 terms, the real-file F8 run, GitHub settings (Dependabot security updates, branch protection), Sarvam ToS 10.5(a) and the Langfuse terms, the optional N1 and N6 wording.
