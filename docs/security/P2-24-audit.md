# P2-24 security audit of the storage layer (`packages/evaldb`)

- Date: 2026-10-24
- Repository HEAD audited: b50c3cc (origin/main, batch E). Gate items: `docs/phase2/SCOPE.md` section 4 items 12 (security) and 17 (private fixtures, no key value in tree, history or CI config). Format and base findings: `docs/security/P1-21-audit.md`.
- Method: read-only. No key value, no `.env.local` content, no keys file and no private call were read. All probes used synthetic values built from parts at run time. Postgres probes ran in throwaway containers (15.19 and 18.6, the two digest-pinned images of `.github/workflows/ci.yml`) bound to loopback on a random port, with a password generated per run, held only in a process environment variable (never written to a file or log). Both containers were removed at the end of the run; no other container was touched.

## Verdict for the security-licensing gate item: PASS WITH CONDITIONS

No blocker. Every public write, delete and read path of the repository returns errors whose visible text holds no document text, parameter value, row detail, URL, host or password, on SQLite, Postgres 15 and Postgres 18. No SQL is built from a value. The deletion audit holds no content. `expected_purpose` is required at both export entry points. The conditions are: the Postgres error scrub is defeated by exception chaining on the untranslated path (E5, E6); the at-rest statement is not yet in a shipped document (E16); the three P2-24 test names are not yet in the tree (E23); and the hosted CI run for b50c3cc must finish green (E22). Owner decisions are listed at the end.

## Batch F note A3: the SQL-text rule (E1)

SCOPE's absolute rule "no `text()` takes an f-string" was replaced by a reviewed table of 18 non-literal SQL sites: `REVIEWED` in `packages/evaldb/tests/test_evaldb_guards.py:88`. `test_no_string_built_sql` pins it exactly in both directions: a new site that is not a plain literal fails ("nothing new"), a listed site that no longer exists or that changes what it interpolates fails ("nothing stale"). The same test requires `ruff --select S608` to be clean with exactly 3 `noqa: S608` comments (`migrate.py` 1, `migrations/helpers.py` 2), no such call at all in the Core-only modules (repository, codecs, deletion, verify, versioning, columns, tables), and every piece interpolated in a revision file to be drawn from a literal of that file or a constant of `triggers.py`. 10 sites are built from identifiers only (checked by the reader as `DYNAMIC` with named pieces); 8 are not traceable by the reader (`OPAQUE`: the statement comes from a function result, a loop variable or an option). I read each of the 8 in the source and traced what can reach it.
