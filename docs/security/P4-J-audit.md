## Judge verification list (no finding)

- **Judge allowlist:** https only (http only for a literal loopback address), no user information, query or fragment, an exact entry match, no-follow open with an inode check, one name, mode 0600, a 64 KiB cap, and key names bound to one host. The entry match and the DNS check come before the key read (order in the run: allowlist check, authorisation reference, caps, output probe, key binding); the real-run check precedes DNS. A DNS answer that is private, loopback or link-local, or a DNS failure, is refused for a public entry. Tests: `test_judge_refusals_before_any_key_read_or_connect`, `test_judge_caps_required_for_real_engine_no_defaults`.
- **HTTP clients:** no redirects (a 3xx is `unexpected_status`), no proxy or certificate environment, TLS verified; the bearer header goes only to the one configured URL; extra headers are limited to a fixed set and the profile's own list; the judge response cap is 64 KiB; an identity encoding is requested and decoding errors are handled; a retry delay above 30 s is refused. The judge client cannot send the OpenRouter key to another host: it uses the bound endpoint URL and nothing else. Tests: `test_judge_client_never_follows_redirects_or_reads_proxy_env`, `test_openai_compat_response_parse_rejects_wrong_shape_and_oversize`, `test_openai_compat_retry_taxonomy_matches_adr0024`.
- **Exchange files:** `item-<id>-<attempt>.json` written 0600 with `O_EXCL` and no-follow in a 0700 directory and fsynced; the name function blocks path escape; replay and fake engines send nothing; `<out>/judge/<run>` stays unreadable to others even when `<out>` is 0755; the ignore rules and the guard cover the exchange files and both allowlist files. Test: `test_judge_exchange_files_private_no_follow_and_guarded`.
- **Injection:** see J-F5 for the controls; the caller brain is covered by `test_caller_injection_suite.py` (validator, sentinel and cap paths), which is outside this document's table.
- **Key path:** see the key-path trace of `docs/security/P4-32-audit.md`; no exception out of the environment-file read carries a key or a path. Canary test: `test_judge_key_canaries_never_in_any_output_channel`.
- **Claim words:** the judge output code, the report headline "Uncalibrated judge signal", counts with denominators and "outcome not evaluated" were read. Tests: `test_judge_report_never_claims_accuracy_or_quality`, `test_judge_lines_labelled_uncalibrated_everywhere`.
- **Standing rules:** only the AI agent is evaluated; judge cost is `not_available` and the provider cost field is read nowhere; a `cannot_tell` verdict is an error `judge_undetermined`; the judge refuses the LLM caller and real-caller data structurally (the judge command needs judge definitions in the snapshot and the window reads only the agent turns of the Sarvam transcript).
