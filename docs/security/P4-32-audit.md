## Key-path trace (BL-351)

Question: can an exception out of the environment-file read carry a key value or a path? Result: no. The decision log entry "SECURITY AUDIT P4-32 + P4-J26 DELIVERED" records this trace as clean.

1. The file reader (`secrets.py`): `os.open`, `fstat`, `fdopen` and `read` errors are caught and become the reason `env_file_unreadable`; a non-regular file becomes `env_file_not_regular`; a file over 64 KiB becomes `env_file_too_large`. A NUL byte in a path raises a `ValueError` whose text holds no path (an argv value cannot carry NUL). A readable mode emits `EnvFileModeWarning` whose text is the mode only.
2. Decoding catches `UnicodeDecodeError` and returns `key_invalid`; the lookups only run regular expressions and return `ambiguous`, `missing` or `found`.
3. `ApiKey.__init__` raises `SttKeyMissingError(reason=...)`; `FactError` validates `reason` against a short lowercase pattern and refuses anything else, so arbitrary text cannot enter the message.
4. `load_named_key` stores the reason inside the handler and raises `JudgeKeyMissingError(reason=reason)` outside it, so there is no `__cause__` and no `__context__`; `load_role_key` does the same.
5. Consumers: the judge key binding catches `ValueError` and raises a `Refusal` `from None`; the simulate command catches `(ValueError, SttError)` and raises a `Refusal` `from None`; the top-level `run()` prints only `type(error).__name__` for unexpected failures. With `-W error`, `EnvFileModeWarning` surfaces as `unexpected failure (EnvFileModeWarning)`, exit 3, with no key and no path.
6. Residual: `raise ... from None` keeps `__context__` (reason strings only); frames hold locals such as the text read, but no code formats locals and the default exception hook does not print them.
7. The Sarvam keys are read and validated at step 6 and then read again by the Sarvam factories: an unprotected double read of the same file (TOCTOU only, P3, tracked with BL-367).
8. Tests: `test_env_file_errors_quote_no_line_and_no_path`, `test_judge_key_canaries_never_in_any_output_channel`, `test_three_provider_roles_one_key_and_a_bearer_token_never_leave_through_any_channel`, `test_judge_key_env_name_pattern_and_never_value_in_config`.
9. Can any path send the OpenRouter key to another host? The judge client cannot: it uses the bound endpoint URL and nothing else, follows no redirect (a 3xx is `unexpected_status`), ignores proxy variables, and restricts extra headers to a fixed set. The only route was an owner allowlist that names the key's variable for another host, which A-F5 closed in code. `test_judge_client_never_follows_redirects_or_reads_proxy_env`.

## Other areas verified (no finding)

- **Judge allowlist:** https only (http only for a literal loopback address), no user information, query or fragment, an exact entry match, no-follow open, one name, mode 0600, a 64 KiB cap, key names bound to one host; the entry match and the DNS check come before the key read. Tests: `test_judge_refusals_before_any_key_read_or_connect`, `test_judge_dns_answer_private_refused_for_public_entry`, `test_judge_https_only_except_loopback_literal`.
- **HTTP clients:** no redirects, no proxy or certificate environment, TLS verified, the bearer header sent only to the one configured URL, an identity encoding requested, a bounded retry delay (a delay above 30 s is refused), response caps.
- **Exchange files and guard:** written 0600 with `O_EXCL` and no-follow, in a 0700 directory, fsynced; the name function blocks path escape; the ignore rules and the guard have name and content rules for outputs; the store is created 0600; the TTS cache directory is 0700 and entries 0600 no-follow; the call log is 0600 no-follow and holds integers and closed codes only. Test: `test_judge_exchange_files_private_no_follow_and_guarded`.
- **Recovery file:** writes only the class name of the error, usage, cost and catalog records; mode 0600, `O_EXCL`; usage is handed out before the next request.
- **WebSocket client:** message size 65,536, no compression, no proxy, redirects raise, `wss` uses the default context; inbound rate cap of 1,000 messages per second. Tests: `test_a_flood_of_frames_ends_the_call_at_the_rate_cap`, `test_inbound_reader_rate_cap_is_a_sliding_one_second_window`.
- **Target allowlist and call length:** the allowlist is required before any socket or key for a non-fake agent; the 180 s call bound is the owner's pre-registered value (the code accepts a larger value; there is no hard-coded 180 s).
- **Not runnable today:** `smallwebrtc/1` is refused by the command, so the aiortc and av surface is library and test only (an SDP answer with arbitrary ICE candidates would make aiortc send STUN to arbitrary addresses: P3, for later).
- **Licences and headers:** `scripts/check_licenses.py` 73 ok, 0 failed; every tracked Python file has the SPDX Apache-2.0 header; root and package LICENSE and NOTICE are present. A-F14 is the one licence record gap.
- **Other:** no `subprocess`, `eval`, `exec`, `pickle` or `yaml.load` in the checked trees (only a guarded import of aiortc); no logging beyond a silenced `websockets` logger; no key pattern in tracked non-test files by a regular-expression scan. No source of Dograh or VoicEra is in the tree to compare; the protobuf wire reader is hand-written from the public wire description (BL-298), and the VoicEra importer reads an export data format; no verbatim similarity was found, but this was not a diff against their code.
- **Standing rules:** only the AI agent is evaluated; missing becomes `not_applicable` or `not_available`; no breach was found apart from A-F2 ("never assume").
