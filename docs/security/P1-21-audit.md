Scope note A1 (info, new): the gate wording "no plain digest in shared exports" is enforced for the test-profile digest (the item ADR 0006 Decision 6 names: a low-entropy personal profile). Other content digests in a shared export stay plain by design: `Artifact.sha256` (integrity checksum of the file bytes), the digests of versioned references (evaluators, metric definitions, pricing catalog) and `ConfigSnapshot` digests. They cover public or non-personal documents or whole recordings, not low-entropy personal fields. I found no sentence in the ADR that says this for `Artifact.sha256`; if a recording could be guessed from a catalogue, a plain file checksum would confirm the guess. Recommendation: add one sentence to ADR 0006 Decision 6 stating the scope, or record that `Artifact.sha256` of human-subject audio is exempt by design.

Residual R1 (info): a sealed payload's confidentiality rests on the key manager and on the Phase 2 sealing implementation; this package checks structure only and cannot detect a nonce reused with the same data key (fresh data key per payload is a documented rule and is tested only in the test-support reference implementation).
