## Verified by reading (no finding)

- Key handling: the `ApiKey` redacting wrapper, one `reveal()` at the request header, errors that carry codes only, the project reference `env:SARVAM_API_KEY` (a name, never a value).
- Transport: no redirects followed, the https endpoint pinned, TLS verification on by default (before batch G; `trust_env` was F3).
- Data flow: what leaves the machine is the chunk WAV with a clean 44-byte header plus the three fixed form fields; the call log holds counts, ids and timings only.
- The dry run sends nothing.
- Hostile Sarvam bodies are bounded and refused by type.
- The report's XSS surface: a strict CSP, per-piece escaping, the audio `src` pattern, the report file created with `O_EXCL` and mode 0600.
- Parsers of untrusted input: the WAV reader and the VoicEra export reader.
- History scans: no key hit; credential-shaped test ids only in Phase 1 pytest logs.
- Licences: `scripts/check_licenses.py` 62 ok; certifi (MPL-2.0) is an unmodified dependency and acceptable.
- Lead action during the audit: the private fixtures directory set to mode 0700 (was 0755).

## Run book preconditions (conditions of the verdict)

Recorded in ADR 0024, section "Run book for a real send (P3-30)", which also says what batch G now enforces in code. In short: the dry run first with exactly the arguments of the real send; `--out` outside the repository, pre-created with mode 0700, no `?`; the proxy and CA variables unset (ignored by the adapter since batch G, kept as practice for other tools); the key from `SARVAM_API_KEY` or a 0600 `--env-file`; each export well under 10,000 tokens; the clip with the fewest chunks first, alone; the consent source recorded in the decision log before the send; afterwards counts only and a reconciliation of the call log with the Sarvam dashboard.

## Not verified by this audit (BL-236)

Stated plainly, so that nobody reads the verdict as covering them:

- pip-audit results: not run by the audit; read the hosted CI run.
- gitleaks: not run locally.
- Real Sarvam behaviour: acceptance of 24 kHz audio, the billing of retries and failed attempts, response compression in practice. Only a real send shows them (P3-30).
- The report's CSP and `'self'` under `file://` in real browsers (also BL-224).
- Windows (modes, `O_NOFOLLOW`, FIFOs are POSIX only).
- The owner's proxy and CA environment.
- Whether any committed string equals the owner's real key: the audit did not search for the key value; the owner can run `git log -S` with the key locally, and the lead key-scans the tree before every commit.
- The batch G fixes themselves were written after the audit and were not re-audited; their evidence is the batch G tests named above and the qa mutants (`docs/phase3/evidence/red/batch-g/`).
