## 2. F2: `langfuse_otlp.map_f2(document, *, run_id, created_at, privacy, cost_contract=LANGFUSE_COST_CONTRACT) -> MappingResult`

`document` is an OTLP/JSON trace document (`resourceSpans[].scopeSpans[].spans[]`, attributes as typed values, as in F1). `cost_contract` is a `common.Citation` (default: the module's `LANGFUSE_COST_CONTRACT`, url on `langfuse.com`, a `YYYY-MM-DD` retrieval date, a statement that says USD). `None`, or a citation without a URL or without a retrieval date, means there is no contract. Source pointers are RFC 6901 pointers into the document; one that continues inside a JSON text is chained with `#` (batch 6 section 1.2, `%23` and `%25` escapes). The converter never raises on content (wrong shapes, wrong value types, lone surrogates).

### 2.1 Observation kinds (P, F2-M2)

Per span, in this order: (1) `langfuse.observation.type` with a recognized value (`span generation event embedding agent tool chain retriever guardrail evaluator`) is the type and is read as decision input; (2) an unrecognized explicit value gives an `unknown_enum_value` warning (raw = the value) and the span falls through; (3) a model attribute (below) present makes the type `generation` (documented fallback; the trace names `observation_type_inferred_from_model` with the citation of "Ingestion transformations"); (4) otherwise `span`. The documented middle step ("other mapped conventions, for example `gen_ai.operation.name`") is not applied: no page says which operation maps to which type.

A **model call** is an observation of type `generation` or `embedding` (Langfuse captures usage and cost on both). It yields a StageSpan, a UsageRecord when it states usage, a CostRecord when it states cost, and (generation only) a Turn. A **tool** observation yields a ToolCallEvent. Every other observation yields nothing but its gap rows.

### 2.2 StageSpan (P, F2-M3, F2-M8)

`stage` is `llm` iff `gen_ai.operation.name` is `chat`, `text_completion` or `generate_content` (derivation `chat_operation_to_llm_stage`, cited to the OpenTelemetry registry); otherwise `other` with `stage_raw` the Langfuse type (`generation`, `embedding`; for an inferred type the derivation `observation_type_inferred_from_model`). `provider` = `gen_ai.provider.name` (nothing else is read; `gen_ai.system` is not). `model` = the first non-empty text among `langfuse.observation.model.name`, `gen_ai.request.model`, `gen_ai.response.model`, `llm.model_name`, `model` (the order of the documentation's table; all present ones are read as decision input). `start`, `duration_ms`, `span_ref = ExternalRef(otel, span_id, spanId)` and the E3 rule are exactly F1's (microsecond truncation, floored ms, `time_precision_reduced` quoting the source instant; digits lost from the interval warn at `endTimeUnixNano`). `ttfb_ms`, `exchange_index` are absent.

### 2.3 UsageRecord (P, F2-M4, F2-M6)

Domain `agent_under_test`, source `telemetry`, `occurred_at` = start, `stage` as the StageSpan's, `provider` required (a model call that states usage and names none: no record, one `malformed_entry` warning on the span, one blocking gap row per usage attribute present, F1 decision 5), `model` as above, `raw` = the usage attributes read, as sent.

- If `langfuse.observation.usage_details` is present it is the source (the `langfuse.*` attributes take precedence, documented) and the `gen_ai.usage.*` attributes of the span are read as decision input and not copied. It is a JSON text of an object. Documented keys: `input` -> `input_tokens`, `output` -> `output_tokens`, `cache_read_input_tokens` and `input_cached_tokens` -> `cache_read_input_tokens`; `total` is the sum of the buckets, not a bucket, and is not stored. The buckets are exclusive (documented), as the usage units are. A count must be a non-negative integer lexeme. Anything else refuses the call (no UsageRecord at all, ADR 0018 Decision 3a / N76): an unknown key (`usage_key_unmapped`, path = the key inside the text, raw = its count), a bad count (`usage_inconsistent`), two keys for one unit (`usage_quantities_not_merged`, no raw), a text that is not an object (`observation_json_unparseable`), each with one blocking gap row `F2:<span name>.langfuse.observation.usage_details`.
- Otherwise `gen_ai.usage.{input_tokens,output_tokens,cache_read.input_tokens,cache_creation.input_tokens}`: Langfuse documents that for these attributes "cache reads and writes are subtracted from input", and the OpenTelemetry registry says the input count SHOULD include the cached tokens. So `input_tokens = gross - cache read - cache creation` for every provider (derivation `input_tokens_gross_minus_cache`, citation on the entry and the row), `cache_read_input_tokens`, `cache_write_input_tokens` and `output_tokens` as reported. A count that is not a non-negative integer, a repeated attribute, or cache counts above the input: `usage_inconsistent`, no record, blocking gap row.

### 2.4 CostRecord (P, F2-M1, F2-M5, F2-M6, F2-M7)

Source: `langfuse.observation.cost_details` (a JSON text of an object; the `total` key) or, when that attribute is absent, `gen_ai.usage.cost` (documented as the `total` key). With both, the first wins and the second is read as decision input. The amount is passed to `cost.import_reported_cost(domain="agent_under_test", reported_by="telemetry_platform", currency_raw=None, contract=<the cited USD contract or None>, amount_source_path=<the amount>, currency_source_path=<the cost attribute>)`; `usage_record_ids` = the UsageRecord of the same observation (empty if none was built). Every warning of the importer is forwarded unchanged (`currency_not_reported`, `amount_unparseable`, `decimal_normalized`, ...), so each carries a path.

- Amount text: a number inside the JSON text is read as its **lexeme** (`0.000097`, `9.7e-05`), never through a float. A `gen_ai.usage.cost` double has no lexeme: its shortest decimal text is the amount (derivation `float_amount_canonical`; 3.1e-05 -> `0.000031`, the way F1 reads audio seconds); an integer is its digits; a text is its text.
- The importer decides everything else (N59): `0.0000970` is imported as `0.000097` with `decimal_normalized`; `9.7e-05`, a sign or a non-number is `amount_unparseable` (status `not_available`, `reported_raw` keeps the lexeme, `currency_source` `api_contract`, `currency_raw` `USD`).
- No `total` (key absent, `null`, empty object): no CostRecord, `cost_total_absent` (path = the attribute, raw = its text), one blocking gap row `F2:<span name>.langfuse.observation.cost_details`. Langfuse derives a missing total from the parts, but that is a sum of floats the source does not state (F2-M5). A text that is not a JSON object: `observation_json_unparseable`, no record, blocking gap row.
- The per-usage-type costs (`input`, `output`, ...) have no target: registered non-blocking `F2:*.langfuse.observation.cost_details.@components` (the total, which the cost model needs, is kept).

Trace entries of a CostRecord (all of them): `/domain` constant, `/status` constant, `/amount/amount` derivation `amount_lexeme_canonical` (or `float_amount_canonical`), `/amount/currency` and `/reported_raw/currency_raw` derivation `contract_currency_usd` with the citation (entry and row), `/basis`, `/reported_by`, `/na_reason`, `/reported_raw/reported_by`, `/reported_raw/currency_source` constants, `/reported_raw/amount_raw` verbatim (the lexeme) or `float_amount_canonical`. `/usage_record_ids` is a framework link, checked by `test_no_fabricated_values_f2` (each id names a UsageRecord of the result, at most one).

### 2.5 ToolCallEvent (P, F2-M10)

One per `tool` observation, in order of span start (a tie keeps document order), `seq` from 0 over the events built. `name` = the observation name (must be a machine key, else `malformed_entry` on the span and no event; never rewritten). Arguments: `langfuse.observation.input` (a JSON text), or, when absent and none of `gen_ai.prompt`, `input.value`, `mlflow.spanInputs` is present (they outrank it, documented), `gen_ai.tool.call.arguments`; stored raw, parsed with `arguments_complete` true only for one whole JSON object (else false, no parsed arguments, `tool_arguments_incomplete` quoting the text); no input attribute: `arguments_complete` false (constant) and no warning. Result: `langfuse.observation.output`, else `gen_ai.tool.call.result` under the same shadowing rule, stored raw; status `completed` iff an output is stated, else `unknown`. `result_complete`, `result_error`, `external_call_id` are absent. Source `agent_telemetry`.

### 2.6 Transcript and Turns (P, F2-M11)

The output of a `generation` (`langfuse.observation.output`, a JSON text) is one agent Turn (`agent_llm_output`, `timing_source` none, no language, no `wall_time`) when it is a JSON string or an object with `role` `assistant` and a string `content` (source pointer `ptr#` or `ptr#/content`). Any other JSON is not an agent line (no Turn, no warning); text that is not JSON warns `observation_json_unparseable` (the mapping does not decide that raw text is a reply). Turns are ordered by span start (ties: document order), `seq` from 0; they share one Transcript of source `agent_telemetry`, created only when a Turn exists. No Exchange exists (Langfuse has no turns).

### 2.7 External references (P, F2-M9)

`otel/trace_id` once per distinct `traceId` (first appearance) and `langfuse/session_id` once per distinct value, in order of first appearance. The session value of a span is `langfuse.session.id`, else `session.id` (the first wins when both are present; both are read as decision input). `langfuse.user.id` and `user.id` identify the end user and are never copied (gap rows, owner security-licensing).

### 2.8 Warning codes (closed; `_support_b11.WARNING_CODES_F2`)

`unknown_enum_value usage_quantities_not_merged usage_inconsistent usage_key_unmapped cost_total_absent observation_json_unparseable tool_arguments_incomplete malformed_entry text_not_valid_unicode time_precision_reduced` and the importer's `currency_not_reported amount_unparseable decimal_normalized currency_label_normalized unsupported_currency currency_contract_conflict`. A warning's `raw` is the source value as sent (a number inside a JSON text: its lexeme).

## 3. F5: `pipecat_evals.map_f5(document, *, declarations, created_at) -> MappingResult`

`document` is the top-level mapping of a scenario file as Pipecat reads it (YAML, `!include` already spliced, integers decimal-only: `_support_b11.load_scenario_yaml`). `declarations` is `pipecat_evals.F5Declarations`, a frozen dataclass:

| Field | Meaning |
|---|---|
| `language: str` | the `SupportedLanguage` of every Evaluator and ScriptedTurn built |
| `persona: Mapping` | `{"id": PersonaId, "version": int}`: the persona every Evaluator references |
| `metric_languages: str \| Sequence[str]` | `MetricDefinition.languages` of every definition built (`"language_independent"` or tags) |
| `script_sensitive: bool` | `MetricDefinition.script_sensitive` of every definition built |
| `instructions: str \| None = None` | the Evaluator `instructions` of a scripted scenario (the file has none) |
| `expected_outcome: str \| None = None` | the Evaluator `expected_outcome` of a scripted scenario |
| `max_duration_ms: int \| None = None` | the Evaluator cap of a scripted scenario |

No `privacy` argument (none of these records carries a marker); no run id; `created_at` is the creation time of every record. Source pointers address `{"document": <the file>, "declared": <declared_root>}` (`/document/scenarios/0/goal`, `/declared/language`; `declared` keys are `language`, `persona` (`id` as text, `version`), `metric_languages`, `script_sensitive`, `instructions`, `expected_outcome`, `max_duration_ms`, as built by `_support_b11.declared_root`). A value filled from a declaration has derivation `user_declared` and table kind `user_declared` (F5-M1); no other row may be `user_declared` (`test_f5_provenance_table_is_well_formed_...` lists the allowed targets).

Records built (all are versioned entities, `version` 1, `content_digest` computed; `/version`, `/content_digest`, `/evaluator_id`, `/metric_bindings`, `/metric`, `/items/*/binding` are framework links and are not traced; their consistency is asserted by `test_f5_validates`): `MetricDefinition`, `MetricBinding`, `Evaluator`, `Rubric`, per scenario, all or nothing (a scenario that cannot be built gives no record at all, not an Evaluator without its checks).

### 3.1 File and scenario shape (P)

`name` (file) and `scenarios[].name` give the scenario name `<file>/<scenario>` (derivation `scenario_qualified_name`; Pipecat's own name). A key at the top of the file is the default of every scenario; a scenario that sets the key replaces the whole value, nothing merges (documented; `test_f5_a_scenario_value_replaces_the_file_default_without_merging`). A file without `scenarios` is the deprecated shape: one scenario named by the file, warning `deprecated_scenario_shape` (path `/document`). A scenario with `persona` is simulated, one with `turns` is scripted; both or neither, a scenario without a name, a file without a name, a non-mapping: `malformed_entry` at the entry and nothing built for it. Keys the format does not document: `unknown_key` at the key. `/document/scenarios` and every `.../expect/N/event` are read as decision input (`consumed`).

### 3.2 Evaluator of a simulated scenario (P, F5-M3, F5-M4)

`name` as above; `language`, `persona` ref: declared; `instructions` = `persona.strip() + "\n\n" + goal.strip()` (derivation `join_persona_and_goal`; Pipecat puts both word for word into the caller's instructions, and `Persona` has no description field, N11); `expected_outcome` = `success` verbatim (edges kept); `max_duration_ms` = `max_duration_s` in whole ms (derivation `seconds_to_ms_floor`, `time_precision_reduced` when digits are lost), or, when the scenario names none, **300 000 by Pipecat's documented default** (`DEFAULT_MAX_DURATION_S = 300.0`; derivation `documented_default_max_duration` with a citation; warning `max_duration_default_applied` at the scenario). A cap outside 1 ms to 4 h: `max_duration_out_of_range` at the value, `evaluator_not_built` at the scenario, blocking gap `F5:max_duration_s`. The declarations `instructions`, `expected_outcome` and `max_duration_ms` are ignored for a simulated scenario (the file wins). `scripted_turns` empty; `expected_tool_calls` and `expected_tool_calls_exhaustive` from a `function_calls` metric (3.3, 3.4).

### 3.3 Metrics and the expected-outcome check (P, F5-M5, F5-M8, F5-M11)

**Judge model.** `judge.eval.service` and `judge.eval.model` verbatim become `judge_model_ref` of every `llm_judge` definition. A scenario with no `judge`, or a `judge` without a truthy `eval`, uses Pipecat's documented default (`ollama`, `gemma4:12b`; derivation `documented_default_judge`, citation on the entry and the row, warning `judge_default_applied` at the scenario). A written `eval` that lacks a text `service` or `model` (a `factory`, one of the two, wrong types) has no model reference we can state: `judge_model_unknown` at the block, `evaluator_not_built`, blocking gap `F5:judge.eval`, nothing built.

**Expected-outcome check** (every Evaluator): definition key `expected_outcome`, `llm_judge`, `boolean`, `per_conversation`, `pass_rule` `equals_true`, `prompt_template` `{{expected_outcome}}`, `prompt_variables` `["expected_outcome"]`, `requires` `["transcript", "tool_calls"]`; an enabled binding; a required rubric item. It is Pipecat's `success` (judged over the whole conversation).

**Judged metric** (`criterion`): key = `name` (must be a `MetricKey`); `llm_judge`, `boolean`, aggregation `per_turn_share{turn_rule: equals_true}` (Pipecat: yes or no for every bot turn, the score is the share of yes), `prompt_template` = `criterion` verbatim (no `{{` allowed: a template with braces is refused), `pass_rule` `range{min: min_score, inclusive: true}` iff `min_score` (a number in 0..1, kept as written, type included), none otherwise; `requires` `["transcript", "tool_calls"]` (derivation `documented_judge_inputs`, cited: the judge reads the conversation and the bot's tool calls by name and arguments, not their results). Required rubric item iff `min_score` is present (Pipecat: a metric with `min_score` fails the run; one without is reported and never fails anything).

**Measured metric** (`measure`): `MEASURE_TABLE` in `_support_b11` is the pin: `turns` (deterministic, numeric, `count`, requires `transcript`), `duration` (deterministic, numeric, `ms`, `turn_timing`), `words` (deterministic, numeric, `count`, `agent_transcript`), `latency` (kind `latency`, numeric, `ms`, `turn_timing`), `function_calls` (deterministic, boolean, no unit, `tool_calls` and `expected_tool_calls`); `implementation_ref` `pipecat_evals:<measure>` (Pipecat's own computation; its `latency` differs from ours by modality); `requires` carry derivation `documented_measure_table` with a citation; aggregation `per_conversation`; the key is `name`, default the measure. `pass_rule` for the four numeric ones: `range{min?: min_value, max?: max_value, inclusive: true}` (Pipecat: both bounds inclusive); a bound in seconds (`duration`, `latency`) is converted to ms as a float (derivation `seconds_to_ms_float`: `0.5` -> `500.0`), a count bound is kept as written. `function_calls`: `equals_true`. Always a required rubric item (a measure outside its range fails the run).

**Exhaustive calls** (batch 17, finding F5-2 resolved; owner decision: `Evaluator.expected_tool_calls_exhaustive: bool | None = None`, where `None` is not stated, `True` is "a call other than the expected ones is a failure" and, with an empty list, "must call nothing"). Pipecat 1.13.0 `evals/simulation.py`, the module documentation of the metrics: "`function_calls` takes a `calls:` list instead of a range: the calls the bot should make ... in any order. Every listed call must have happened and any call not listed fails it, so `calls: []` says the bot must call nothing, the check for a caller who should be turned down." The driver says the same (`simulation_driver._calls_outcome`: the metric passes only when no listed call is missing and no made call is unlisted). So the extras rule does not depend on the list: **every `function_calls` metric, with an empty or a listed `calls`, gives `expected_tool_calls_exhaustive = True`** on the scenario's Evaluator. `calls: []` is no longer refused: the metric becomes a definition, an enabled binding and a required rubric item like any `function_calls` metric, the Evaluator has `expected_tool_calls == []` (no call is made up) and the flag `True`, there is no `empty_call_list` warning and no gap row. A scenario without a `function_calls` metric, and every scripted scenario, leave the flag `None` (never `False`: the file does not say that extra calls are allowed; and Pipecat's scripted `function_call` expectations only require the listed calls, they do not fail on others, so no exhaustiveness is stated for them). Trace entry for the flag: field `/expected_tool_calls_exhaustive` of the Evaluator, source pointer the `calls` key of the metric (`/document/scenarios/<s>/metrics/<m>/calls`), derivation `documented_measure_table` (the measure table is where this statement about `function_calls` is documented), and a complete `Citation` of that text (url `https://github.com/pipecat-ai/pipecat/blob/v1.13.0/src/pipecat/evals/simulation.py`, retrieval date 2026-10-23, a statement that quotes "every listed call must have happened and any call not listed fails it" and "`calls: []` says the bot must call nothing"). The provenance table gets the row `Evaluator.expected_tool_calls_exhaustive` (kind `derivation`, source `metrics.calls`, derivation `documented_measure_table`, the same citation). Open point F5-M12 (section 8): two `function_calls` metrics in one scenario.

**Refusals** (F5-M2): a metric that cannot be a definition (not a mapping; neither or both of `criterion` and `measure`; judged without a text `name`; a name that is not a `MetricKey`, or a duplicate of an earlier one in the evaluator; an empty or braced criterion; a `min_score` outside 0..1 or not a number (`bool` included); an unknown `measure` (`unknown_enum_value`); a measure with no bound, a non-number bound, or bounds the unit's domain or the band refuses; `function_calls` without a usable `calls` list: absent or not a list; an empty list is usable since batch 17, see Exhaustive calls above) gives no definition, binding or rubric item, one warning (`malformed_entry` or `unknown_enum_value`) whose path locates the offending value, and one blocking dynamic gap row `F5:metrics.<name|criterion|min_score|measure|min_value|max_value|calls>` (owner a project role). The evaluator and its other checks are still built.

### 3.4 Scripted scenarios and expected tool calls (P, F5-M6, F5-M7)

A scripted scenario has no `instructions`, `expected_outcome` or cap, so the declarations must supply all three; with any missing the scenario gives nothing, one `evaluator_not_built` warning per scenario whose message names the missing declaration(s) by field name. Scripted turns: for each turn with a `user`, index from 0 over the lines that have text; text = the string verbatim, or, for a list, its text items trimmed and joined by one space (derivation `join_user_text_parts`; Pipecat: `user` then holds the text alone; `pause_ms` items are not text); language = the declaration. A turn with only `dtmf`, `audio` or `image` is not a line. The expected-outcome check is built from the **declared** expected outcome (anchor `/declared/expected_outcome`).

Expected tool calls (scripted: `function_call` expectations; simulated: the `calls` of a `function_calls` metric): each expectation (or metric) is one **rank**, in file order over the turns, the calls of one expectation share it (Pipecat matches them in any order; equal ranks are any order, ADR 0010); ranks run 0..R without gaps (an expectation that yields no call takes none). A call is a name, or a mapping with `name` and `args`, or the `name`/`args` shorthand of the expectation. `name_only` without `args` (an empty `args` is a subset every call satisfies: `name_only`); `arguments_subset` with non-empty `args` (verbatim, Pipecat: every listed key must be present, extras ignored); derivation `args_to_match_mode`. `function_call_stopped` expectations and `absent: true` ones are not expected calls. A call without a usable name (a bare expectation asserts that some call happened; a name that is not a machine key) is skipped with `expectation_not_representable`; arguments that are not one I-JSON object (a YAML date, `.nan`) are skipped with `non_json_value` at the value (no raw). `calls: []` yields no call and takes no rank; its meaning is carried by `expected_tool_calls_exhaustive` (3.3).

### 3.5 Warning codes (closed; `_support_b11.WARNING_CODES_F5`)

`deprecated_scenario_shape evaluator_not_built judge_default_applied max_duration_default_applied expectation_not_representable judge_model_unknown unknown_key unknown_enum_value max_duration_out_of_range non_json_value malformed_entry time_precision_reduced text_not_valid_unicode`. (Batch 17: `empty_call_list` leaves the vocabulary, `calls: []` is no longer a warning case.) A lone surrogate in a copied text becomes U+FFFD with `text_not_valid_unicode` (derivation `lone_surrogate_replaced` on `expected_outcome` and `prompt_template`); the persona, goal and user texts get the same replacement before they are joined (the trace of a joined text is not pinned for that case).

## 7. Findings (facts about the sources, for the owner and staff-reviewer)

- **F2-1 (cost).** Python's `json.dumps` writes 9.7e-05 for floats below 1e-4, and real Langfuse costs per call are that small, so a producer that serializes `cost_details` with `json.dumps` sends exponent forms. N59 (decided) treats an exponent amount as `amount_unparseable`, so those costs are `not_available` with the lexeme kept. Pinned as decided (`test_f2_cost_amount_forms_follow_the_import_rules`). Recommendation: keep N59 for 0.0.1; ask the owner whether the importer may read a JSON-number exponent form (an exact, lossless decimal, not an extrapolation) as a later, additive change.
- **F2-2 (carriers).** Langfuse also reads input and output from `gen_ai.prompt`, `gen_ai.completion`, `input.value`, `output.value`, `mlflow.spanInputs`, `mlflow.spanOutputs` (and `llm.token_count.*` for usage). This mapping reads `langfuse.observation.*` and the `gen_ai.usage.*` / `gen_ai.tool.call.*` names only; the others are non-blocking gap rows (owner dev). A producer that sets only `gen_ai.completion` yields no Turn. Phase 5 adapters re-verify against a real instance.
- **F2-3 (TTFB).** `langfuse.observation.completion_start_time` is "when the model began generating"; no page defines time to first token as that minus the start (the public API has a `timeToFirstToken` filter column, undefined on the fetched pages). No `ttfb_ms` is derived. If an MVP-1 latency metric needs a T1 stage TTFB this becomes **blocking** and needs a schema field (a first-output instant on `StageSpan`). Registered `lossy`, non-blocking, owner staff-reviewer.
- **F2-4 (reasoning tokens).** Langfuse's `output` bucket excludes `output_reasoning_tokens` ("`output` excludes any `output_*` values"), and no usage unit holds reasoning tokens. A call that reports them through `usage_details` is refused whole (no UsageRecord, blocking dynamic gap), because dropping them would price the call as a partial available cost. The documentation (exclusive buckets, each token in exactly one key) arguably states that the reasoning tokens are billed output, so a cited merge into `output_tokens` would be defensible; that is a decision for the owner (F2-M4), not a guess. Real reasoning-model traffic through `usage_details` will hit this.
- **F2-5 (units).** `input_cached_tokens` is documented only as the exclusive form of OpenAI's `cached_tokens` ("cache hits"); it maps to `cache_read_input_tokens`. A Langfuse key for cache writes is not documented, so any other key is refused.
- **F5-1 (declarations).** An Evaluator needs a language, a persona reference, `instructions`, an `expected_outcome` and a cap that a scenario file cannot always supply. ADR 0018 Decision 2 allows exactly one value from outside the source (`Transcript.declared_language`). F5 needs the same exception for six fields (the table rows of kind `user_declared`, F5-M1). Without it no scripted scenario can become an Evaluator.
- **F5-2 (`calls: []`).** Pipecat's `function_calls` with `calls: []` means "the bot must call nothing" (documented as the check for a caller who should be turned down). `Evaluator.expected_tool_calls == []` means "no expectation". **Resolved in batch 17** (owner decision): `Evaluator.expected_tool_calls_exhaustive`; `calls: []` maps to an empty list with the flag `True` (3.3). Before: the statement could not be represented, so the metric was refused with a blocking dynamic gap row `F5:metrics.calls` and a warning `empty_call_list`. It does not occur in the fixtures; it is a documented use of the format.
- **F5-3 (event assertions).** A scripted scenario's pass criteria are event assertions (`response` with `eval` or `text_contains`, `within_ms` budgets, `absent`, `llm_marker` checks, `user_transcription` text). The Evaluator holds a script, expected tool calls, an expected outcome and metric bindings, not per-turn event expectations. They are registered non-blocking gaps (no MVP-1 metric imports Pipecat's event assertions): an imported scripted evaluator runs the script and the declared expected outcome, not Pipecat's assertions. staff-reviewer confirms at the gate (F5-M9); if interop with Pipecat scripted scenarios is an MVP-1 requirement these are blocking and need a schema field.
- **F5-4 (exclusivity).** A `function_calls` metric fails on any call not listed; the evaluator's expected calls cannot say so. **Resolved in batch 17** with F5-2: the rule is carried by `expected_tool_calls_exhaustive = True` as well as by the scorer name `pipecat_evals:function_calls` (the non-blocking row `F5:metrics.calls.@exclusive` leaves the register). Before: carried only by the scorer name.
- **F5-5 (scorers).** `pipecat_evals:*` scorers do not exist in Phase 1. By P-61 a run stops before it starts if the registry cannot find the scorer, so an imported evaluator with a measured metric does not run until an adapter provides it. That is the honest outcome; naming a Tracer scorer instead would claim an equivalence nobody checked.
- **F5-6 (YAML `!include`).** Pipecat's loader resolves `!include` paths anywhere the process can read ("only on trusted documents"). The test helper confines them to the fixture directory; an importer that reads user files must do the same or document the trust.

## 10. Validation and its limits

Throwaway oracle converters (scratchpad, outside the repository) make all 364 tests pass on Python 3.11 to 3.14 (`oracle-green-*` logs). Single-change mutants of the oracle (58 for F2, 79 for F5) were run against `test_mapping_f2.py` and `test_mapping_f5.py`; the first run left nine survivors: one equivalent (below), four mutants that changed nothing (rewritten; two of the rewritten ones then still survived because no test pinned the behavior), and four that exposed missing tests; six tests were added (E3 duration floored, tool order by start, text edges kept, pause-text trimming, no merging of a replaced block, the TTS language is not the evaluator language); the final run (`mutants-f2.txt`, `mutants-f5.txt`) kills every mutant except one equivalent (the oracle's gap-free rank renumbering is redundant because ranks are only taken by expectations that yield a call) and one skipped as equivalent (an incomplete citation is treated as no contract by `import_reported_cost` itself). ruff, ruff format, `mypy --strict`, `check_headers`, `guard_private_fixtures` and `check_licenses` pass.

Not verifiable: the oracle and the tests share one author, so a misreading of a source would sit in both; the Langfuse pages are the cloud documentation as served on the retrieval date (no version) and may change; no Langfuse instance was run, so real exporters' attribute shapes (for example whether `gen_ai.usage.cost` is a double, a string or absent) are unverified; Pipecat's 1.13.0 parser was run only on the three fixtures; the measure table's `requires` and units are qa's reading; the Hindi text is `needs_native_review`; JSON-Schema validity of the built definitions and evaluators is not asserted here (the P1-16 harness); `PyYAML` has no CPython 3.15 wheel, so the F5 tests that load YAML would fail on the non-blocking 3.15 leg (the F5 fixtures-free tests would still run).
