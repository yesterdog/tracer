## Decisions (final)
- Distribution `tracer-evalschema`, import `tracer_evalschema`. JSON Schema `$id` = `urn:tracer:evalschema:0.0.1:<entity>`. Schema files ship inside the wheel. PyPI availability of the name is unverified.
- IDs: UUIDv7 stored natively (`uuid.UUID`); wire form `<prefix>_<uuid>` (lowercase, hyphenated, version nibble 7, variant 10xx); per-type JSON Schema `pattern`; wrong-kind IDs rejected. Bare/v4 UUIDs never become our IDs: `from_external()` mints a v7 ID and records an `ExternalRef`. Registry (frozen at the gate; 26 entities): prj agt per tpf evl met mbd rub snap run art tsc turn exc tcl spn res vrd dts dti pcat use cst csum rbnd exp (revision 15: `pce` withdrawn, `PriceEntry` is a value object, N47); new prefixes must be >= 2 edits from every prefix and not an anagram (P-03). Value objects have no ID. Phase 2 deduplicates re-imports by a unique index on the external reference (P-02).
- Verdict: headline "x/y required checks passed", y = all required checks including not_applicable. Counts: required_total, passed, failed, not_applicable, errored. Status: pass (x==y), fail (any failed), inconclusive (none failed, some did not run). Weights live in the rubric; the separate `weighted_score = Σ(w·passed)/Σ(w)` over scored weighted checks is always stored and shown with its `weight_coverage` (scored weight / total weight), and is absent when nothing was scored. A metric without a pass rule cannot carry a weight (P-55).
- Versioning: same id + integer version, `(id, version)` immutable. Versioned: Persona, TestProfile, Evaluator, MetricDefinition, MetricBinding, Rubric, PricingCatalog, AgentTarget, Dataset. Files from a newer schema version raise `SchemaVersionTooNew`; while 0.0.x, require exact version match; frozen fixtures per version, older ones raise `SchemaVersionMismatch` until an `upgrade()` step exists. First release 0.0.1.
- PII and digests: ConfigSnapshot stores `TestProfileRef{id, version, content_digest?}` only, never PII. Internal digests are PLAIN SHA-256 over JCS (RFC 8785) canonical JSON, `ContentDigest{scheme: "sha256-jcs/v1", value}`. Registry: `sha256-jcs/v1` (`key_ref` absent) and `hmac-sha256-jcs/v1` (`key_ref` = KeyRef, key never in an export); unknown scheme rejected with a typed error; verification behind one function. Shared/benchmark exports and sealed profiles never carry a plain profile digest: drop it or key it. SCHEMA_POLICY.md documents that a plain internal digest of a low-entropy profile can be brute-forced. The ConfigSnapshot digest excludes `TestProfileRef.content_digest`, which is recorded separately. Profile values in evaluator instructions and scripted turns are `{{profile.<field>}}` placeholders filled at run time, with a lint for literal profile values. Optional `SealedPayload` for explicit portable exports only; its `plaintext_digest` is dropped or keyed for every payload type.
- Python: develop on 3.13; floor 3.11; CI required 3.11-3.14; 3.15 non-blocking. uv workspace + GitHub Actions.
- Languages (configured): English, Hindi, Marathi, Telugu, Tamil, Kannada, Malayalam, Punjabi (Gurmukhi), Gujarati. No Bengali, Urdu, Shahmukhi, Odia, Assamese. No Hinglish/code-mix (no CodeMix type, no `hi-en` alias; reject with a message that code-mix is unsupported). Native script only for configured languages: romanized/transliterated tags such as `hi-Latn` are rejected in Persona/ScriptedTurn/Evaluator/DatasetItem. Configured regions are exactly IN, US and GB (vendored; others rejected with a clear message; adding one is a data change). Provider-observed tags are validated by syntax only (primary subtag 2-3 letters, grandfathered tags rejected), never against a registry, never rejected for being unknown (including romanized tags and languages like `bn-IN`); the raw provider label is kept verbatim in `detected_language_raw` (and per turn in `Turn.language_raw`); importers turn `_` into `-` with a warning, and a label that is not a tag (`hindi`) is kept raw with the normalized field empty, never rejected. Script-sensitive metrics are not_applicable (`unsupported_script`) on observed romanized text. Data files verified against raw sources; native names `needs_native_review`.
- Roles: caller, agent, unknown (revision 5). Only the AI agent is evaluated; the caller is a human or a simulator (`Run.caller_origin`, simulated|human, required, no default); `unknown` is speech whose speaker is not identified. Agent channel map (declared|inferred, method; channel roles caller, agent, unknown, mixed). PrivacyMarker on every payload entity; `human_subject` derived from origin and roles (`unknown` role or no role evidence -> true); a stored marker may be stricter than the derivation with a reason, never looser. Human-subject data cannot enter a shared or benchmark export unless sealed or redacted, and cannot enter a benchmark at all unless consent is `obtained`. Both export rules use the export-time value `export_human_subject()`: a precautionary marker (`marked_before_role_evidence`) is re-derived from the role evidence in the exported bundle, the stored record is never edited, human-caller recordings stay human-subject, and consent is not applicable to a payload that evaluates as non-human (P-57).
- Cost: Money = decimal string + currency, never float; the only supported currency in 0.0.1 is USD (data-driven `SupportedCurrency` set), configured and user-supplied prices must be USD, there is no FX, and `CostSummary` has one USD total. A provider/telemetry-reported cost in another currency is `not_available` (`unsupported_currency`) with the reported amount and currency kept verbatim in `reported_raw`, never converted and never rejected. `basis` is ONLY `reported` or `computed` (no `estimated`) and is present only when the cost is available. If neither applies the cost is `not_available` (never 0), excluded from totals, totals state what they exclude. `computed` requires (1) known usage of the actual billable event, either provider/telemetry-reported or directly observed by us in a call WE made, and (2) a known price including billing rules; billing rules are explicit (`increment` and `minimum` each a value or `"none"`) or `"unknown"`, and `"unknown"` gives not_available (`billing_rules_missing`). Evaluation-domain costs can be computed or reported. Agent-under-test costs are computed only from telemetry-reported usage; a recording's duration is NOT accepted as the agent's STT usage; LLM tokens for a black-box agent are not_available. User-supplied prices yield `computed` with a separate `price_source` (catalog|user_supplied) as provenance. Reported currency labels differing from `USD` only by case or whitespace are normalized by the importer with a warning (raw kept; `$`/`US$` never mapped); a reported cost without a currency is `not_available` (`currency_not_reported`) unless a cited API contract states the currency. Each usage counts in at most one included cost record; when the provider's own report is in another currency, the computed USD record is included and the excluded reported record names it (P-54). The supported-currency list is the `currencies` key of `supported_currencies.json`. Revision 15 (owner, N43 to N60): a usage record may carry `occurred_at`, which selects the price date before `Run.started_at`, never "now"; price entries are value objects of their catalog version with a stable entry identifier; ranges are half-open; condition facts are passed by the caller; a reported USD amount that is not a valid decimal or is negative is `not_available` (`amount_unparseable`) with the raw text kept; the reason precedence is no usage, `no_price_for_model`, `billing_rules_missing`, `unit_unpriced`, `ambiguous_price`; a computed record that partly overlaps reported usage is excluded whole and the summary is partial. Revision 16 (owner, the revision 15 owner items): price entries are named by a catalog-scoped `entry_key` (`pricing_snapshot.entry_keys`); the pricing models hide their input; usage quantities are non-empty, one per unit and never negative, and a zero quantity costs 0 with no minimum; `pricing.check_catalog_succession` checks P-24; `applies_when` is non-empty, has distinct kinds and is all-must-hold; `provenance.url` is an absolute `http`/`https` URL and a user-supplied price needs `provenance.note`; a USD payload label against a cited non-USD contract is `not_available` (`currency_conflict`) with a `currency_contract_conflict` warning.
- Text and bidi: store text byte-for-byte; `contains_bidi_controls` computed and verified; `display_safe()` isolates untrusted text (FSI...PDI) AND renders U+202A-U+202E and U+2066-U+2069 as visible markers; LRM/RLM/ALM unchanged in free text; identifier-like fields (names, keys, IDs, labels) reject U+202A-U+202E, U+2066-U+2069, LRM, RLM, ALM, ZWSP, U+2060, BOM and C0/C1 controls; ZWJ/ZWNJ preserved everywhere. UBA reference for tests: the in-repo clean-room UAX #9 implementation (python-bidi failed conformance and was removed 2026-10-22).
- Metrics: pass rules `range{min?,max?,inclusive}`, `equals_true`, `one_of`, each stating its direction (no rule without a direction); `script_sensitive` required; `requires[]` non-empty and unique; `languages` is `"language_independent"` (then `script_sensitive=false`) or a non-empty list with distinct primary languages (P-59, revision 9); `na_reason` missing_input|agent_channel_unknown|language_not_observed|unsupported_language|unsupported_script with that fixed precedence (P-10 as amended by P-59); configured languages are never used as observed ones; a user may declare the language of an untagged import (`Transcript.declared_language`), which is never an observation, is never used by script-sensitive metrics, and is recorded on each result as `language_source=declared` (N14, revision 10); each non-judge result that ran records `scorer: ScorerInfo{implementation_ref, version}` (P-61, revision 10); `per_turn_share` excludes not_applicable and undetermined turns from its denominator and is always shown with its turn coverage (counted/total turns) (P-26, P-56); the share is stored in `MetricResult.per_turn`, never in `value`, is checked against the counts, and `passed` is the range pass rule applied to it (P-58, revision 7).
- Core rule: consume telemetry if present, never break if absent. Missing inputs give `not_applicable` (value None, passed None), never 0 or false.

### Format of F8 (structure only; do not quote real text anywhere committable)
Plain text: line 1 `call_id=<uuid>`; line 2 `---`; then lines `[ISO-8601 UTC timestamp with milliseconds and +00:00] assistant|user: text`. One timestamp per line (meaning ambiguous: start, end or log time) -> `Turn.wall_time{at, meaning: unknown}`, `timing_source=none`. No audio, confidence, language tag, tool calls, end-of-call reason. Roles assistant/user map to agent/caller; both lines have `Turn.source=agent_log`. `call_id` is a bare UUID kept as an `ExternalRef`. One logged assistant line may concatenate several utterances (repeated prompts plus a closing message); it stays one Turn. Turns may mix scripts. The file name carries local time (IST) while content is UTC; the file name is never used for timing. User states this is VoicEra's standard export (not verified in VoicEra docs). The importer itself is Phase 6; Phase 1 proves expressibility.
