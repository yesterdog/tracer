# Batch 4 (usage, pricing, cost) mutants (qa, 2026-10-23)

Throwaway oracle `oracle12` outside the repository: a correct implementation of api-surface section 23 (modules usage, pricing, cost) on top of the batch 1 to 3 oracle. One change per mutant (a few use two or three coordinated edits). Each mutant is run with `pytest -x -q` over the eight new test files (test_usage, test_pricing, test_cost, test_cost_summary, test_cost_compute, test_cost_import, test_cost_contract, test_batch4_entities; 206 tests) on Python 3.13. CAUGHT = at least one test failed (the first failing test is listed); SURVIVED = all passed.

Final run: 228 mutants, 223 caught, 5 survived, 0 other (patch not applied or broken). The first pass (210 mutants) found 11 survivors; six were closed by strengthening the tests (P37 order of applies_when, C72 distinct entry IDs, S09 covered_by names only records sharing usage, K10 duplicate_of_reported needs a reported cover, I23 amount_raw kept untrimmed when no currency is sent; C56 was a patch that did not apply and was fixed) and 18 mutants on closed-set and ID typing (E01 to E18) were added.

## Survivors

- S08 | partial overlap with reported allowed | SURVIVED |  -- not pinned: a computed record that shares only part of its usage with reported records. ADR 0014 Decision 16a does not say what happens; the oracle raises a ValueError (api-surface 23.3 N53). Owner decision needed before a test can pin it.
- S12 | no-usage record counted covered | SURVIVED |  -- equivalent: an excluded record with no usage has no covering record either way, so covered_by is empty with or without the vacuous-subset guard.
- K09 | check: duplicate_of_reported accepted for reported | SURVIVED |  -- redundant, not a gap: the same summary (a reported record excluded as duplicate_of_reported) is rejected by the next check, which requires every covering record to be a reported one; the mutant only changes which message is raised first.
- K16 | check_pricing_snapshot: scheme skipped | SURVIVED |  -- equivalent: only two digest schemes are registered and a plain digest never has a key_ref while a keyed one always has, so a scheme difference always shows as a key_ref difference.
- I04 | normalize uses unicode strip | SURVIVED |  -- not pinned: Unicode white space (for example U+00A0) around a currency label. ADR 0014 Decision 12a says only "surrounding whitespace"; the tests pin ASCII white space (api-surface 23.3 N59).
