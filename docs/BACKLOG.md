## How to triage

Priorities:
- **P0**: blocks a phase gate, or affects the correctness or security of stored data.
- **P1**: medium security or quality issue in our own code.
- **P2**: meaningful improvement.
- **P3**: low, informational, cosmetic or theoretical.

Status values:
- **open**: nothing done yet.
- **in-progress**: work exists in the tree (committed or not); the cell names where.
- **closed**: fixed and verified. Closing a row requires the commit id and the test name(s) that
  prove it, written into the status cell (for example `closed: abc1234, test_x`).
- **wontfix (reason)**: accepted on purpose; the reason and who accepted it are in the cell.
- **held-off (owner, date)**: deliberately postponed by an owner decision; reopen only on a new
  owner decision.
- **verify: ...**: not sure whether still open; the cell says what to check. Resolve to one of the
  four values above.

Rules:
1. IDs are stable. Never renumber or reuse an ID; add new rows at the end of the right table with
   the next free number of that table's block (blocks: 001-029 Phase 1 schema, 030-069 Phase 2
   storage, 070-099 security and licensing, 100-119 CI and tooling, 120-129 documentation,
   130-139 owner decisions, 140-199 Phase 3+ risks; a full block continues at 200 and up).
2. A row is closed only with a commit id and a test name (or, for a document-only fix, the commit
   id and the file and section). Log the closure in the decision log as well.
3. Re-check a row's source before acting on it; sources can be superseded.
4. Owner guidance (decision log 2026-10-25, "OWNER GUIDANCE"): fix where possible, but P0 work
   comes first; do not spend gate time on P3 rows.
5. After editing this file, run the Phase 1 document tests (T-DRIFT and the drift tests), because
   they scan every text file under `docs/`.
